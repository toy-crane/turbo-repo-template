# AI 채팅 스크롤 명세

## 목표

긴 대화와 스트리밍 답변에서도 사용자가 읽던 위치를 잃지 않게 한다. 새 질문을 보내면 질문이 화면 위쪽에서 시작하고 AI 답변은 그 아래로 자란다. 사용자가 최신 답변을 보고 있을 때만 스트리밍을 따라가며, 이전 메시지를 읽기 시작하면 자동 이동을 멈춘다.

이 명세는 [최소 채팅 화면 명세](../ai-chat/spec.md)의 메시지 표시, 입력과 전송, 화면 수명과 서버 연결을 유지한다. 기존 명세에서 제외했던 긴 대화용 가상 목록, 읽기 위치 보존과 최신 메시지 이동 버튼만 이번 범위에서 추가한다.

## 확정한 범위

### 메시지 목록

- 메시지 목록은 `KeyboardAwareLegendList`가 소유한다. 이 컴포넌트가 `LegendList` 가상 목록과 `KeyboardChatScrollView`의 키보드 동작을 연결한다.
- 메시지는 사용자 메시지와 AI 답변을 시간 순서대로 표시한다. 목록을 뒤집지 않는다.
- 메시지의 안정적인 `id`를 목록 항목의 키로 사용한다.
- 대화는 메시지 수와 관계없이 첫 메시지를 화면 위쪽에 배치한다. 대화가 화면보다 짧아도 메시지를 입력창 위로 내리지 않는다.
- 채팅 화면은 빈 대화로 시작하고 이전 대화를 복원하지 않으므로 처음부터 목록 끝으로 이동하지 않는다.
- 메시지 높이가 달라져도 사용자가 읽는 위치를 지키되, 새 데이터가 추가됐다는 이유만으로 위치를 바꾸지 않는다. 크기 변화에 대한 위치 보정만 사용한다.
- 기존 사용자 메시지와 AI 답변의 배치, 일반 텍스트 렌더링과 선택 가능한 본문은 유지한다.

### 새 질문 전송

- 질문을 보내면 입력창을 비우고 키보드를 닫는다.
- 첫 질문은 목록 자체의 위쪽 여백 24px로 배치하고 `anchoredEndSpace`로 답변 뒤의 빈 영역에서도 스크롤 드래그가 시작되게 한다.
- 두 번째 질문부터 방금 보낸 질문을 화면 위쪽 24px 위치에 고정하고, AI 답변과 그 뒤의 빈 영역이 남은 공간에서 이어지게 한다.
- 위쪽 배치는 방금 보낸 사용자 메시지만 기준으로 삼는다. AI 답변이 시작되거나 커질 때 기준을 바꾸지 않는다.
- 질문이 화면보다 길면 질문의 시작을 화면 위쪽에 맞춘다. 질문 전체와 AI 답변을 한 화면에 동시에 보이게 하려고 축소하거나 겹치지 않는다.
- 새 질문을 보내면 사용자가 이전 메시지를 읽고 있었더라도 최신 답변 자동 추적을 다시 켠다.

### 스트리밍 자동 추적

- 자동 추적은 사용자가 최신 메시지를 따라가겠다는 상태다. 단순히 목록 끝이 한 프레임 보이는지만으로 상태를 정하지 않는다.
- 자동 추적이 켜진 동안 AI 답변이 스트리밍으로 커지면 최신 메시지를 계속 보여 준다. 잦은 스트리밍 갱신은 스크롤 애니메이션을 반복하지 않는다.
- 사용자가 직접 위로 스크롤해 이전 메시지를 읽기 시작하면 자동 추적을 끄고 현재 위치를 유지한다.
- 콘텐츠 경계 밖의 음수 스크롤 위치는 이전 메시지를 읽으려는 이동으로 보지 않는다.
- 키보드 애니메이션, 입력창 높이 변화, 메시지 크기 변화와 자동 스크롤 자체는 사용자의 중단 의도로 보지 않는다.
- 사용자가 직접 목록 끝까지 내려오거나 최신 메시지 이동 버튼을 누르면 자동 추적을 다시 켠다.
- 키보드가 열릴 때는 사용자가 목록 끝에 있을 때만 최신 메시지 영역을 키보드와 함께 올린다. 이전 메시지를 읽는 중이면 키보드 때문에 읽던 위치를 바꾸지 않는다.

### 최신 메시지 이동 버튼

- 최신 메시지가 보이지 않을 때 입력창 위 가로 중앙에 원형 아래쪽 화살표 버튼을 표시한다.
- 버튼의 보이는 표시는 아래쪽 화살표 하나만 사용한다. 접근성 이름은 `최신 메시지로 이동`이다.
- 버튼을 누르면 최신 메시지로 애니메이션해 이동하고 자동 추적을 다시 켠다.
- 최신 메시지가 보이면 버튼을 숨긴다.
- 버튼은 입력창, 전송 버튼과 메시지 본문을 가리지 않고 글자 크기 확대와 Safe Area에서도 누를 수 있어야 한다.

### 여러 줄 입력창과 키보드

- 기존 `KeyboardStickyView`, 여러 줄 입력창과 전송 버튼을 유지한다.
- 입력창 높이가 바뀌면 메시지 목록이 쓸 수 있는 아래쪽 공간도 같은 변화량으로 조정한다.
- 입력창 높이는 키보드 인셋과 같은 흐름에서 한 번만 반영한다. 별도의 고정 하단 여백을 더해 공간을 중복으로 만들지 않는다.
- iOS에서는 키보드를 아래로 밀어 닫는 상호작용을 유지한다. Android에서도 목록을 끌어 키보드를 닫을 수 있다.
- 질문 전송 뒤에는 키보드를 닫아 새 질문과 AI 답변을 읽을 공간을 확보한다. 사용자가 입력창을 다시 누르면 키보드를 연다.

## 선택한 구성

- `@legendapp/list`의 `KeyboardAwareLegendList`를 사용한다.
- 공식 키보드 채팅 입력창 인셋 연결을 사용해 입력창 높이를 목록에 전달한다.
- 모든 질문은 목록의 위쪽 여백과 `anchoredEndSpace`의 `anchorOffset: 24`를 함께 사용한다. 첫 질문의 자연스러운 시작 위치는 목록 여백이 만들고, `anchoredEndSpace`는 답변 뒤의 빈 영역을 목록 공간으로 만든다. 별도의 `blankSpace` 계산을 중복해서 두지 않는다.
- iOS에서는 React Native의 content inset hit-test 문제를 우회해 `anchoredEndSpace`로 만든 빈 영역에서도 스크롤을 시작할 수 있게 한다.
- 키보드가 목록을 올리는 조건은 `keyboardLiftBehavior="whenAtEnd"`다.
- 최신 메시지 이동은 키보드가 적용된 목록의 실제 스크롤 영역을 대상으로 한다.
- 목록의 스크롤 컴포넌트와 메시지 렌더러는 다시 렌더링해도 같은 참조를 유지한다.
- 읽는 위치 보정은 메시지 크기 변화에만 적용하고 데이터 추가에 대한 보정은 끈다.

## 제외할 범위

- 뒤집은 목록
- 짧은 대화를 화면 아래쪽에 배치하는 `alignItemsAtEnd`
- 화면 진입 시 목록 끝으로 이동하는 `initialScrollAtEnd`
- 목록 항목 재활용
- 새 데이터 추가에 대한 `maintainVisibleContentPosition`
- 별도로 계산한 `blankSpace`
- 사용자가 읽던 위치를 무시하는 무조건적인 `scrollToEnd()`
- 전송 뒤 키보드 유지
- 메시지 복사, 편집 후 다시 보내기, 다시 생성, 생성 중지와 다시 시도
- Markdown, 파일, 출처, 도구와 멀티모달 입력
- 대화 저장, 지난 대화 조회와 이전 메시지 추가 불러오기
- 서버 경로, 인증, 모델 라우팅과 스트리밍 프로토콜 변경

## 완료 조건

### 공통 동작

1. 짧은 대화와 긴 대화 모두 첫 메시지는 화면 위쪽에서 시작하고, 긴 대화는 화면에 보이는 항목만 렌더링한다.
2. 첫 질문은 목록 위쪽 24px에서 시작하고 답변 뒤의 빈 영역에서도 스크롤 드래그가 반응한다. 두 번째 질문부터 화면 위쪽 24px 위치에 고정하고 AI 답변은 그 아래로 자란다.
3. 질문을 보내면 키보드가 닫히고 자동 추적이 켜진다.
4. 최신 메시지를 보고 있으면 스트리밍 답변을 계속 따라가며 불필요한 반복 애니메이션이 생기지 않는다.
5. 사용자가 위로 스크롤하면 스트리밍 중에도 현재 읽는 위치를 유지한다.
6. 자동 추적이 꺼지면 입력창 위 가로 중앙에 아래쪽 화살표 버튼이 나타난다. 버튼을 누르거나 사용자가 직접 끝까지 내려오면 최신 메시지로 이동하고 자동 추적을 다시 켠다.
7. 여러 줄 입력창이 최소 높이에서 최대 높이까지 커지고 줄어도 최신 메시지, 스크롤 표시와 입력창 사이에 빈 공간이나 겹침이 생기지 않는다.
8. 기존 입력, 전송, 일반 텍스트 메시지 표시, 오류 안내와 접근성 동작이 유지된다.

### iOS와 Android 확인

- 키보드 열기와 닫기
- 목록을 끌어 키보드 닫기
- 짧은 대화와 화면 여러 배 길이의 긴 대화
- 짧은 질문, 여러 줄 질문과 화면보다 긴 질문의 위쪽 배치
- 짧은 답변과 화면 여러 배 길이의 스트리밍 답변
- 스트리밍 자동 추적, 사용자 스크롤에 따른 중단과 끝 도달 및 아래쪽 화살표 버튼에 따른 재개
- 입력창이 여러 줄로 커지고 다시 한 줄로 줄어드는 동안의 목록 위치
- 글자 크기를 확대한 상태에서 메시지, 아래쪽 화살표 버튼, 입력창과 전송 버튼의 접근성

자동 테스트는 자동 추적 상태 전환, 버튼 표시와 동작, 전송 뒤 키보드 닫기 요청, 안정적인 메시지 키와 기존 입력·전송 회귀를 확인한다. 키보드 애니메이션, 실제 스크롤 위치, 가상 목록 렌더링과 플랫폼별 상호작용은 iOS 및 Android Development Build에서 확인한다.

## 가정

- 아래쪽 화살표 버튼은 기존 아이콘과 색상 시맨틱을 사용한다. 최종 크기와 간격은 실제 기기에서 입력창을 가리지 않는 범위로 정한다.
- 자동 추적을 끄는 사용자 스크롤의 거리 기준과 목록 끝으로 판단할 여유 값은 실제 기기에서 흔들리지 않는 가장 작은 값으로 정한다.
- 이번 대화는 화면이 살아 있는 동안만 유지되므로 화면을 처음 열 때 복원할 읽기 위치는 없다.

## 남은 위험

- `KeyboardAwareLegendList`에서 여러 줄 질문을 보낸 직후 입력창 높이와 위쪽 배치 계산 시점이 겹치면 iOS에서 질문 위치가 조금 어긋날 수 있다. 이 조합은 라이브러리의 열린 문제이므로 여러 줄 질문을 실제 기기에서 반복 확인한다.
- 동적 높이 메시지의 측정이 끝나기 전에 최신 메시지로 이동하면 첫 위치가 보정될 수 있다. 질문 전송, 첫 AI 메시지 추가와 스트리밍 시작이 연속으로 일어나는 경우를 따로 확인한다.
- 가상 목록은 긴 대화의 렌더링 양을 줄이지만 매우 긴 단일 텍스트 메시지의 렌더링 비용까지 줄이지는 않는다.
- 아래쪽 화살표 버튼이 나타나고 사라지는 경계가 너무 좁으면 스트리밍 중 깜빡일 수 있다. 사용자 스크롤과 콘텐츠 성장에 따른 상태를 분리해 검증한다.
