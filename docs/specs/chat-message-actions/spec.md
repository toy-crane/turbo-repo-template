# 채팅 메시지 동작 명세

## 목표

대화를 하다가 답변을 가져가고, 마음에 들지 않는 답변을 다시 받고, 보낸 메시지를 수정해 다시 묻고, 받는 중인 답변을 멈추고, 실패한 요청을 다시 보낼 수 있게 한다. 다섯 동작과 그 동작을 붙일 표면을 이번 범위에 둔다.

이 명세는 [최소 채팅 화면 명세](../ai-chat/spec.md)가 제거했던 항목 가운데 다섯 개를 되살린다. 그 명세의 제거할 범위에 있던 "메시지 복사, 편집 후 다시 보내기와 다시 생성"과 "생성 중지, 다시 시도 버튼과 편집 상태"는 이 명세가 대체한다. 그 명세의 완료 조건 가운데 "메시지 작업 UI가 화면과 접근성 트리에 남아 있지 않다"는 항목은 더 이상 적용하지 않는다. 나머지 범위와 [AI 채팅 스크롤 명세](../ai-chat-scrolling/spec.md)는 그대로 유지한다.

확정한 화면은 [프로토타입](prototype.html)에 있다. 더미 데이터로 만든 검토용 사본이며 구현 코드가 아니다.

## 확정한 범위

### 동작을 붙이는 표면

- AI 답변은 답변 아래 아이콘 줄로 동작을 보여 준다. 완료된 모든 답변에 붙인다.
- 사용자 메시지는 길게 눌러 여는 메뉴로 동작을 보여 준다. 모든 메시지에 붙인다.
- 메뉴는 길게 누를 때만 연다. 메시지를 한 번 누르는 것은 아무 일도 하지 않는다.
- AI 답변 본문은 지금처럼 선택할 수 있게 둔다. 답변에는 앱 메뉴를 붙이지 않으므로 텍스트 선택과 시스템 편집 메뉴가 길게 누르기를 그대로 쓴다.
- 사용자 메시지 본문은 선택을 끈다. 길게 누르기는 메시지 메뉴가 가져간다.
- 답변을 기다리거나 받는 동안에는 그 답변에 아이콘 줄을 붙이지 않고 메시지 메뉴도 열지 않는다.
- 아이콘 줄과 메뉴는 기존 스크롤 위치 유지, 자동 추적과 키보드 동작을 바꾸지 않는다.

### 메시지 본문과 터치 영역

- 사용자 메시지와 AI 답변은 같은 본문 역할을 쓴다. 지금 사용자 메시지에만 크기 지정이 없어 React Native 기본값 14px이 적용되고 있으므로, 답변과 같은 16px과 행간 24px로 맞춘다.
- 아이콘 줄의 버튼은 보이는 크기를 32px로 두고, 서로 붙여 아이콘의 중심 간 거리를 32px로 만든다. 널리 쓰는 채팅 앱이 자리 잡은 밀도이며, 사람이 한 덩어리로 읽는다.
- 좌우로는 32px가 그대로 누르는 범위다. 44px를 채우려고 옆으로 넓히지 않는다. 두 버튼의 넓힌 영역이 겹쳐 어느 쪽이 눌렸는지 흐려지고, 그만큼 아이콘을 떼어 놓아야 해서 한 덩어리로 보이지 않는다.
- 위아래로는 `hitSlop`으로 6px씩 넓힌다. 그 방향에는 touch를 가져갈 이웃이 없다.

### 답변 복사

- 아이콘 줄의 복사는 그 답변의 본문 전체를 클립보드에 넣는다.
- 복사한 뒤 별도 알림을 띄우지 않는다.

### 답변 다시 받기

- 아이콘 줄의 다시 받기는 그 답변과 그 뒤의 모든 메시지를 버리고 답변을 다시 만든다.
- 확인을 받지 않는다. 대화 중간에서 눌러도 바로 버린다.

### 메시지 수정

- 메뉴의 수정은 그 메시지의 원문을 입력창에 넣고 입력창을 수정 상태로 바꾼다.
- 수정 상태에서는 입력창 위에 사라질 범위를 알리는 한 줄과 그만두기를 둔다.
- 목록에서는 그 메시지와 그 뒤의 메시지를 흐리게 보여 준다.
- 수정 상태에서 보내면 그 메시지와 그 뒤의 모든 메시지를 버리고 수정한 메시지로 다시 묻는다.
- 그만두면 대화를 그대로 두고 수정 상태만 끝낸다.
- 수정을 시작할 때 쓰던 초안은 보관했다가 그만두면 되돌린다.
- 한 번에 한 메시지만 수정한다.

### 메시지 복사

- 메뉴의 복사는 그 메시지의 본문 전체를 클립보드에 넣는다.
- 메시지 본문의 선택을 끄므로 메시지를 가져가는 길은 이 항목과 수정으로 들어간 입력창뿐이다. 두 길을 모두 남긴다.

### 최신 메시지 이동 버튼

- iOS 26 이상에서는 `expo-glass-effect`의 `GlassView`로 표시한다. 표준 네이티브 셸로 표현할 수 없는 중요한 플로팅 컨트롤에만 커스텀 Glass를 허용한다는 렌더러 경계의 예외를 따른다.
- 그 밖의 iOS 버전과 Android에서는 지금과 같은 `surface` 배경의 원을 그대로 둔다. 테두리나 그림자를 더하지 않는다.
- Android에서 Liquid Glass를 흉내 내지 않는다.
- 크기, 자리, 접근성 이름 `최신 메시지로 이동`과 눌렀을 때의 동작은 바뀌지 않는다.

### 답변을 기다리는 동안

- 메시지를 보낸 뒤 첫 글자가 오기 전까지 답변이 올 자리에 `답변을 쓰고 있어요.`를 보여 준다.
- 이 문구는 움직임으로 진행 중임을 함께 알린다.
- 첫 글자가 오면 문구를 지우고 같은 자리에서 본문이 이어진다.
- 글자가 흐르는 동안에는 별도 표시를 두지 않는다. 흐르는 글자 자체가 표시다.
- 시스템의 동작 줄이기 설정을 켠 기기에서는 움직임 없이 문구만 보여 준다.

### 답변 그만 받기

- 답변을 기다리거나 받는 동안 전송 버튼 자리는 중지 버튼으로 바뀐다.
- 중지하면 그때까지 받은 답변을 대화에 그대로 남긴다.
- 중지한 뒤에는 새 메시지를 보내거나 그 답변을 다시 받을 수 있다.
- 중지한 답변은 받은 데까지 그대로 두고 중지했다는 별도 표시를 붙이지 않는다. 완료된 답변과 같은 모양으로 보인다.

### 실패 뒤 다시 시도

- 요청이 실패하면 기존 오류 문구 옆에 다시 시도 버튼을 둔다.
- 실패한 메시지는 목록에 그대로 남긴다. 사용자가 메시지를 다시 입력하지 않는다.
- 다시 시도는 답변 다시 받기와 같은 동작이다.

### 화면 문구와 접근성 이름

| 이름 | 화면에 보이나 | 자리 |
| --- | --- | --- |
| `복사` | 보인다 | 메시지 메뉴 항목 |
| `수정` | 보인다 | 메시지 메뉴 항목 |
| `다시 시도하기` | 보인다 | 오류 문구 옆 버튼 |
| `답변을 쓰고 있어요.` | 보인다 | 첫 글자가 오기 전 답변 자리 |
| `답변 복사` | 아니다 | AI 답변 아래 아이콘 줄 |
| `답변 다시 받기` | 아니다 | AI 답변 아래 아이콘 줄 |
| `수정 그만두기` | 아니다 | 수정 상태의 그만두기 버튼 |
| `답변 그만 받기` | 아니다 | 답변을 받는 동안의 전송 버튼 자리 |

- 수정 상태 안내 문구는 `수정하면 여기서부터 대화를 다시 시작해요.`다.
- 기존 오류 문구 `답변을 받지 못했어요.`는 그대로 둔다.
- 새 이름은 `chat-labels.ts`와 저장소 README의 접근성 이름 표에 함께 넣는다.

## 선택한 구성

- 메시지 메뉴는 `heroui-native`의 `Menu`를 `presentation="popover"`로 사용한다. 이 컴포넌트가 길게 누르기 대상, 위치 계산, 화면 경계 회피, 바깥을 눌러 닫기를 소유한다.
- 메뉴를 위해 `@expo/ui`의 `Host`를 만들지 않고 새 네이티브 의존성도 넣지 않는다. 일반 제품 콘텐츠는 React Native UI와 HeroUI Native가 소유한다는 렌더러 경계를 따른다.
- 되돌리기는 `useChat`의 `regenerate`를 사용한다. 답변 다시 받기와 다시 시도는 대상 답변을 기준으로 부르고, 메시지 수정은 `setMessages`로 그 메시지 앞까지 자른 뒤 수정한 글을 보낸다.
- 중지는 `useChat`의 `stop`을 사용한다. 서버는 이미 요청 신호로 모델 호출을 함께 멈춘다.
- 수정 상태는 입력창이 소유한다. 목록 항목 안에 입력칸을 넣지 않는다. 키보드 회피, 입력창 높이 조절, 공백과 중복 전송 막기를 그대로 재사용한다.
- 아이콘은 프로젝트 `Icon`의 이름 표에 더한다. 기능 코드는 `lucide-react-native`를 직접 부르지 않는다.
- 클립보드는 `expo-clipboard`를 더해서 사용한다. React Native 코어에는 클립보드 API가 없다.
- Liquid Glass는 `expo-glass-effect`를 더해서 사용한다. `isLiquidGlassAvailable()`로 갈라 쓰고, 지원하지 않는 곳에서는 이 컴포넌트가 평범한 `View`로 떨어져 기존 style을 그대로 그린다.
- 기다리는 동안의 표시는 문구 하나로 한다. 진행 표시만 있고 무슨 일인지 말해 주지 않는 도형은 쓰지 않는다.
- 문구의 움직임은 밝은 띠가 글자 위를 왼쪽에서 오른쪽으로 지나가는 형태다. `@react-native-masked-view/masked-view`와 `expo-linear-gradient`를 더해서 만든다. 글자는 일반 `Text`로 남으므로 시스템 글자 크기 확대를 그대로 따른다.
- SVG로 글자를 그려 그라디언트를 채우는 방법은 쓰지 않는다. 패키지는 늘지 않지만 그 줄만 시스템 글자 크기 확대를 따르지 못한다.

## 제외할 범위

- 되돌린 대화를 갈래로 남기는 버전 이동
- 되돌리기 확인 대화상자
- AI 답변 수정
- 복사 성공 알림과 토스트
- 답변 평가
- 부분 선택을 메뉴에서 시작하는 텍스트 선택 항목
- 길게 누르기를 알려 주는 안내 표시
- 여러 메시지를 한 번에 고르는 선택 모드
- Markdown, 코드 블록과 코드 복사
- 첨부, 모델 고르기, 지난 대화 저장과 조회
- 서버 경로, 인증, 모델 라우팅과 스트리밍 프로토콜 변경

## 완료 조건

### 공통 동작

1. 완료된 모든 AI 답변 아래에 복사와 다시 받기가 보이고, 기다리거나 받는 중인 답변에는 보이지 않는다.
2. 답변 복사를 누르면 그 답변의 본문 전체가 클립보드에 들어간다.
3. 답변 다시 받기를 누르면 그 답변과 뒤의 메시지가 사라지고 새 답변이 그 자리에서 이어진다. 대화 중간에서도 같다.
4. 메시지를 길게 누르면 메뉴가 열리고, 한 번 누르면 아무 일도 일어나지 않는다.
5. 메뉴의 복사를 누르면 그 메시지의 본문 전체가 클립보드에 들어간다.
6. 메뉴의 수정을 누르면 원문이 입력창에 들어가고, 사라질 범위가 흐리게 보이며, 안내 한 줄과 그만두기가 나타난다.
7. 수정 상태에서 보내면 그 메시지부터 다시 시작하고, 그만두면 대화와 원래 초안이 그대로 돌아온다.
8. 메시지를 보내면 첫 글자가 오기 전까지 답변 자리에 `답변을 쓰고 있어요.`가 보이고, 첫 글자가 오면 사라진다.
9. 답변을 기다리거나 받는 동안 전송 버튼 자리가 중지로 바뀌고, 누르면 받던 답변이 그 자리에 남은 채 멈춘다.
10. 요청이 실패하면 오류 문구 옆 다시 시도로 같은 메시지를 다시 보낼 수 있고, 메시지를 다시 입력하지 않는다.
11. AI 답변 본문은 길게 눌러 부분 선택할 수 있고, 메시지 본문은 대신 메뉴가 열린다.
12. 사용자 메시지와 AI 답변의 글자 크기가 같고, 아이콘 줄의 두 아이콘이 한 덩어리로 보이며 각각 따로 눌린다.
13. 기존 스크롤 위치 유지, 스트리밍 자동 추적, 최신 메시지 이동, 키보드 회피와 전송 동작이 그대로 유지된다.

### iOS와 Android 확인

- 메시지 길게 누르기, 메뉴 열기와 바깥을 눌러 닫기
- iOS 26에서 최신 메시지 이동 버튼의 Liquid Glass 표시, 그 아래 버전과 Android에서의 fallback
- 대화 중간과 마지막에서 답변 다시 받기
- 수정 상태 진입, 보내기, 그만두기와 초안 되돌리기
- 메시지를 보낸 직후부터 첫 글자가 올 때까지의 표시
- 동작 줄이기 설정을 켠 상태에서 기다리는 동안의 표시
- 답변을 받는 도중 중지와 중지 뒤 이어가기
- 요청 실패 뒤 다시 시도
- 키보드가 열린 상태에서 메뉴와 수정 상태
- 긴 답변과 화면보다 긴 메시지에서 아이콘 줄과 메뉴의 위치
- 글자 크기를 확대한 상태에서 아이콘 줄, 메뉴 항목과 수정 상태의 접근성

자동 테스트는 아이콘 줄 표시 조건, 복사 호출, 되돌리기가 자르는 범위, 수정 상태 전환과 초안 되돌리기, 중지와 다시 시도 호출을 확인한다. 길게 누르기 제스처, 메뉴 표시, 실제 클립보드와 플랫폼별 상호작용은 iOS 및 Android Development Build에서 확인한다.

## 가정

- 실패한 요청의 메시지는 목록에 남긴다.
- 아이콘 줄과 메뉴의 크기, 간격과 색상은 기존 시맨틱 토큰을 따르고, 최종 값은 실제 기기에서 본문과 입력창을 가리지 않는 범위로 정한다.
- 흐리게 보여 주는 정도는 사라질 범위를 알아볼 수 있으면서 본문을 읽을 수 있는 값으로 정한다.

## 남은 위험

- `heroui-native`의 `Menu`는 이 저장소에서 아직 번들해 본 적이 없다. `@gorhom/bottom-sheet`와 `expo-blur`가 optional peer로 빠져 있고 라이브러리가 `src/optional/` 심으로 이를 다루지만, `presentation="popover"`가 Metro에서 문제없이 묶이는지는 첫 Development Build에서 확인한다. 막히면 필요한 패키지를 더한다.
- 오버레이의 흐림 효과는 `expo-blur`가 없어 빠진다. 불투명 오버레이로 충분한지 실제 기기에서 확인한다.
- iOS 26에서 `selectable`이 하이라이트와 선택 핸들 없이 복사 메뉴만 띄운다는 React Native의 열린 이슈가 있다([facebook/react-native#55187](https://github.com/facebook/react-native/issues/55187)). 0.81.5에서 보고됐고 고쳐졌다는 표시가 없다. 이 명세가 유지하는 AI 답변의 부분 선택이 iOS에서 실제로 되는지 확인한다. 되지 않으면 답변을 가져가는 길은 아이콘 줄의 복사뿐이다.
- Expo 문서가 `@react-native-masked-view/masked-view`의 Android 지원을 실험 단계이며 플랫폼 사이 동작이 다를 수 있다고 밝힌다. Android에서 띠가 기대대로 지나가는지 첫 Development Build에서 확인한다. 어긋나면 Android만 `reanimated`로 글자 밝기를 반복하는 형태로 내린다.
- 오류 문구는 `danger` 색을 본문 크기로 쓴다. 시맨틱은 맞지만 그 값이 화면 배경과 맞지 않아 대비가 라이트 3.25, 다크 4.41로 본문 기준 4.5에 못 미친다. `danger`의 값은 이 프로젝트가 정한 적이 없고 heroui-native 기본값을 그대로 쓰고 있으며, 색상 시맨틱 결정도 상태 색상의 실제 값을 확정하지 않는다고 밝혀 두었다. 라이트를 `oklch(0.565 0.2 25)`, 다크를 `oklch(0.6 0.18 25)` 정도로 옮기면 넘긴다. 토큰 값은 `danger`를 쓰는 모든 자리에 걸리므로 이 명세가 아니라 색상 시맨틱 결정에서 정한다.
- `stop()`이 받다 만 답변을 대화에 남기는지는 공식 문서가 밝히지 않는다. 남긴다고 보고 만들되 기기에서 확인한다.
- 메시지를 길게 눌러야 메뉴가 열린다는 것을 알려 주는 표시가 없다. 널리 쓰이는 방식이지만 찾지 못하는 사용자가 있을 수 있다.
- 최신 메시지 이동 버튼의 fallback은 배경과의 대비가 라이트 1.10, 다크 1.13이라 원의 윤곽이 보이지 않는다. 버튼이 메시지 위에 떠 있을 때 글자를 가리는데 경계가 없어 글자가 잘린 것처럼 보인다. 앱이 iOS 최소 버전을 따로 지정하지 않으므로 iOS 26 미만과 Android 전체가 여기 해당한다. 지금 화면 상태를 그대로 두기로 한 결정에 따르는 결과다.
- `GlassView`가 지원하지 않는 플랫폼에서 기존 `style`을 그대로 그리는지는 문서가 "reverts to a standard View component"라고만 밝힌다. 첫 Development Build에서 Android와 iOS 26 미만을 확인한다.
- 대화 중간에서 다시 받기를 잘못 누르면 뒤의 대화가 확인 없이 사라진다. 대화를 저장하지 않으므로 되살릴 방법이 없다. 확인을 두지 않기로 한 결정에 따르는 결과다.
