# 채팅 메시지 동작 명세

## 목표

대화를 하다가 답변을 가져가고, 마음에 들지 않는 답변을 다시 받고, 질문을 고쳐 다시 묻고, 받는 중인 답변을 멈추고, 실패한 요청을 다시 보낼 수 있게 한다. 다섯 동작과 그 동작을 붙일 표면을 이번 범위에 둔다.

이 명세는 [최소 채팅 화면 명세](../ai-chat/spec.md)가 제거했던 항목 가운데 다섯 개를 되살린다. 그 명세의 제거할 범위에 있던 "메시지 복사, 편집 후 다시 보내기와 다시 생성"과 "생성 중지, 다시 시도 버튼과 편집 상태"는 이 명세가 대체한다. 그 명세의 완료 조건 가운데 "메시지 작업 UI가 화면과 접근성 트리에 남아 있지 않다"는 항목은 더 이상 적용하지 않는다. 나머지 범위와 [AI 채팅 스크롤 명세](../ai-chat-scrolling/spec.md)는 그대로 유지한다.

## 확정한 범위

### 동작을 붙이는 표면

- AI 답변은 답변 아래 아이콘 줄로 동작을 보여 준다. 완료된 모든 답변에 붙인다.
- 사용자 질문은 길게 눌러 여는 메뉴로 동작을 보여 준다. 모든 질문에 붙인다.
- 메뉴는 길게 누를 때만 연다. 질문을 한 번 누르는 것은 아무 일도 하지 않는다.
- AI 답변 본문은 지금처럼 선택할 수 있게 둔다. 사용자 질문 본문은 선택을 끄고 길게 누르기를 메뉴에 넘긴다.
- 답변을 기다리거나 받는 동안에는 그 답변에 아이콘 줄을 붙이지 않고 질문 메뉴도 열지 않는다.
- 아이콘 줄과 메뉴는 기존 스크롤 위치 유지, 자동 추적과 키보드 동작을 바꾸지 않는다.

### 답변 복사

- 아이콘 줄의 복사는 그 답변의 본문 전체를 클립보드에 넣는다.
- 복사한 뒤 별도 알림을 띄우지 않는다.

### 답변 다시 받기

- 아이콘 줄의 다시 받기는 그 답변과 그 뒤의 모든 메시지를 버리고 답변을 다시 만든다.
- 확인을 받지 않는다. 대화 중간에서 눌러도 바로 버린다.

### 질문 고치기

- 메뉴의 고치기는 그 질문의 원문을 입력창에 넣고 입력창을 편집 상태로 바꾼다.
- 편집 상태에서는 입력창 위에 사라질 범위를 알리는 한 줄과 그만두기를 둔다.
- 목록에서는 그 질문과 그 뒤의 메시지를 흐리게 보여 준다.
- 편집 상태에서 보내면 그 질문과 그 뒤의 모든 메시지를 버리고 고친 질문으로 다시 묻는다.
- 그만두면 대화를 그대로 두고 편집 상태만 끝낸다.
- 편집을 시작할 때 쓰던 초안은 보관했다가 그만두면 되돌린다.
- 한 번에 한 질문만 고친다.

### 질문 복사

- 메뉴의 복사는 그 질문의 본문 전체를 클립보드에 넣는다.

### 답변 그만 받기

- 답변을 기다리거나 받는 동안 전송 버튼 자리는 중지 버튼으로 바뀐다.
- 중지하면 그때까지 받은 답변을 대화에 그대로 남긴다.
- 중지한 뒤에는 새 질문을 보내거나 그 답변을 다시 받을 수 있다.

### 실패 뒤 다시 시도

- 요청이 실패하면 기존 오류 문구 옆에 다시 시도 버튼을 둔다.
- 실패한 질문은 목록에 그대로 남긴다. 사용자가 질문을 다시 입력하지 않는다.
- 다시 시도는 답변 다시 받기와 같은 동작이다.

### 화면 문구와 접근성 이름

| 이름 | 자리 |
| --- | --- |
| `답변 복사` | AI 답변 아래 아이콘 줄 |
| `답변 다시 받기` | AI 답변 아래 아이콘 줄 |
| `질문 복사` | 질문 메뉴 항목 |
| `질문 고치기` | 질문 메뉴 항목 |
| `고치기 그만두기` | 편집 상태의 그만두기 버튼 |
| `답변 그만 받기` | 답변을 받는 동안의 전송 버튼 자리 |
| `다시 시도하기` | 오류 문구 옆 버튼 |

- 편집 상태 안내 문구는 `이 질문을 고치면 아래 대화를 다시 시작해요.`다.
- 기존 오류 문구 `답변을 받지 못했어요.`는 그대로 둔다.
- 새 이름은 `chat-labels.ts`와 저장소 README의 접근성 이름 표에 함께 넣는다.

## 선택한 구성

- 질문 메뉴는 `heroui-native`의 `Menu`를 `presentation="popover"`로 사용한다. 이 컴포넌트가 길게 누르기 대상, 위치 계산, 화면 경계 회피, 바깥을 눌러 닫기를 소유한다.
- 메뉴를 위해 `@expo/ui`의 `Host`를 만들지 않고 새 네이티브 의존성도 넣지 않는다. 일반 제품 콘텐츠는 React Native UI와 HeroUI Native가 소유한다는 렌더러 경계를 따른다.
- 되돌리기는 `useChat`의 `regenerate`를 사용한다. 답변 다시 받기와 다시 시도는 대상 답변을 기준으로 부르고, 질문 고치기는 `setMessages`로 그 질문 앞까지 자른 뒤 고친 글을 보낸다.
- 중지는 `useChat`의 `stop`을 사용한다. 서버는 이미 요청 신호로 모델 호출을 함께 멈춘다.
- 편집 상태는 입력창이 소유한다. 목록 항목 안에 입력칸을 넣지 않는다. 키보드 회피, 입력창 높이 조절, 공백과 중복 전송 막기를 그대로 재사용한다.
- 아이콘은 프로젝트 `Icon`의 이름 표에 더한다. 기능 코드는 `lucide-react-native`를 직접 부르지 않는다.
- 클립보드는 `expo-clipboard`를 더해서 사용한다. React Native 코어에는 클립보드 API가 없다.

## 제외할 범위

- 되돌린 대화를 갈래로 남기는 버전 이동
- 되돌리기 확인 대화상자
- AI 답변 고치기
- 복사 성공 알림과 토스트
- 답변 평가
- 부분 선택을 메뉴에서 시작하는 텍스트 선택 항목
- 길게 누르기를 알려 주는 안내 표시
- 여러 질문을 한 번에 고르는 선택 모드
- Markdown, 코드 블록과 코드 복사
- 첨부, 모델 고르기, 지난 대화 저장과 조회
- 서버 경로, 인증, 모델 라우팅과 스트리밍 프로토콜 변경

## 완료 조건

### 공통 동작

1. 완료된 모든 AI 답변 아래에 복사와 다시 받기가 보이고, 기다리거나 받는 중인 답변에는 보이지 않는다.
2. 답변 복사를 누르면 그 답변의 본문 전체가 클립보드에 들어간다.
3. 답변 다시 받기를 누르면 그 답변과 뒤의 메시지가 사라지고 새 답변이 그 자리에서 이어진다. 대화 중간에서도 같다.
4. 질문을 길게 누르면 메뉴가 열리고, 한 번 누르면 아무 일도 일어나지 않는다.
5. 질문 복사를 누르면 그 질문의 본문 전체가 클립보드에 들어간다.
6. 질문 고치기를 누르면 원문이 입력창에 들어가고, 사라질 범위가 흐리게 보이며, 안내 한 줄과 그만두기가 나타난다.
7. 편집 상태에서 보내면 그 질문부터 다시 시작하고, 그만두면 대화와 원래 초안이 그대로 돌아온다.
8. 답변을 기다리거나 받는 동안 전송 버튼 자리가 중지로 바뀌고, 누르면 받던 답변이 그 자리에 남은 채 멈춘다.
9. 요청이 실패하면 오류 문구 옆 다시 시도로 같은 질문을 다시 보낼 수 있고, 질문을 다시 입력하지 않는다.
10. AI 답변 본문은 길게 눌러 부분 선택할 수 있고, 질문 본문은 대신 메뉴가 열린다.
11. 기존 스크롤 위치 유지, 스트리밍 자동 추적, 최신 메시지 이동, 키보드 회피와 전송 동작이 그대로 유지된다.

### iOS와 Android 확인

- 질문 길게 누르기, 메뉴 열기와 바깥을 눌러 닫기
- 대화 중간과 마지막에서 답변 다시 받기
- 편집 상태 진입, 보내기, 그만두기와 초안 되돌리기
- 답변을 받는 도중 중지와 중지 뒤 이어가기
- 요청 실패 뒤 다시 시도
- 키보드가 열린 상태에서 메뉴와 편집 상태
- 긴 답변과 화면보다 긴 질문에서 아이콘 줄과 메뉴의 위치
- 글자 크기를 확대한 상태에서 아이콘 줄, 메뉴 항목과 편집 상태의 접근성

자동 테스트는 아이콘 줄 표시 조건, 복사 호출, 되돌리기가 자르는 범위, 편집 상태 전환과 초안 되돌리기, 중지와 다시 시도 호출을 확인한다. 길게 누르기 제스처, 메뉴 표시, 실제 클립보드와 플랫폼별 상호작용은 iOS 및 Android Development Build에서 확인한다.

## 가정

- 질문 메뉴에는 복사와 고치기 두 항목을 둔다. 질문 본문의 선택을 끄면 질문을 복사할 길이 고치기밖에 남지 않기 때문이다.
- 중지한 답변은 그대로 두고 중지했다는 별도 표시를 붙이지 않는다.
- 실패한 요청의 질문은 목록에 남긴다.
- 아이콘 줄과 메뉴의 크기, 간격과 색상은 기존 시맨틱 토큰을 따르고, 최종 값은 실제 기기에서 본문과 입력창을 가리지 않는 범위로 정한다.
- 흐리게 보여 주는 정도는 사라질 범위를 알아볼 수 있으면서 본문을 읽을 수 있는 값으로 정한다.

## 남은 위험

- `heroui-native`의 `Menu`는 이 저장소에서 아직 번들해 본 적이 없다. `@gorhom/bottom-sheet`와 `expo-blur`가 optional peer로 빠져 있고 라이브러리가 `src/optional/` 심으로 이를 다루지만, `presentation="popover"`가 Metro에서 문제없이 묶이는지는 첫 Development Build에서 확인한다. 막히면 필요한 패키지를 더한다.
- 오버레이의 흐림 효과는 `expo-blur`가 없어 빠진다. 불투명 오버레이로 충분한지 실제 기기에서 확인한다.
- `stop()`이 받다 만 답변을 대화에 남기는지는 공식 문서가 밝히지 않는다. 남긴다고 보고 만들되 기기에서 확인한다.
- 질문을 길게 눌러야 메뉴가 열린다는 것을 알려 주는 표시가 없다. 널리 쓰이는 방식이지만 찾지 못하는 사용자가 있을 수 있다.
- 대화 중간에서 다시 받기를 잘못 누르면 뒤의 대화가 확인 없이 사라진다. 대화를 저장하지 않으므로 되살릴 방법이 없다. 확인을 두지 않기로 한 결정에 따르는 결과다.
