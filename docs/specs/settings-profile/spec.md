# 설정 공개 프로필 명세

## 목표

Settings를 Apple 기본 설정 앱의 그룹형 목록 구조에 맞춘다. 설정 화면에서 현재 공개 프로필을 크게 보여 주고, 한 화면에서 프로필 사진, 닉네임과 아이디를 수정하게 한다.

승인한 화면과 상태는 [프로토타입](prototype.html)에 보존한다. 프로토타입은 흐름과 배치를 확인하는 기준이며 실제 앱의 네이티브 간격을 픽셀 단위로 고정하지 않는다.

## 참고 기준

- Apple Human Interface Guidelines의 [Settings](https://developer.apple.com/design/human-interface-guidelines/settings)와 [Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables)를 설정 구조의 기준으로 삼는다.
- Expo SDK 57의 [`FieldGroup`](https://docs.expo.dev/versions/v57.0.0/sdk/ui/universal/fieldgroup/)이 제공하는 `Section`, `SectionHeader`, `SectionFooter` 자리를 사용한다.

## 설정 화면

- Settings는 네이티브 `pageSheet`로 열고 제목은 `설정`, 닫기 접근성 이름은 `설정 닫기`로 표시한다.
- 화면 위에는 큰 프로필 사진, 닉네임, 아이디를 차례로 가운데 정렬한다. 닉네임을 먼저 강조하고 아이디는 보조 정보로 표시한다.
- 아이디 앞에는 `@`를 붙이지 않는다.
- 프로필 사진을 누르면 사진 메뉴를 열지 않고 `프로필 수정` 화면으로 이동한다.
- `계정` 섹션의 `프로필 수정`도 같은 화면으로 이동한다.
- 설정 화면의 모든 제품 문구는 한글로 표시한다.

| 섹션 | 항목 |
| --- | --- |
| 계정 | 프로필 수정, 로그아웃 |
| 환경 설정 | 알림, 햅틱 반응 |
| 앱 정보 | 버전 |

## 프로필 수정 화면

- Settings 시트 안에서 네이티브 push 화면으로 연다. 제목은 `프로필 수정`이며 뒤로 가기와 `저장`을 제공한다.
- 큰 프로필 사진과 `사진 편집` 문구를 가운데 배치한다. 두 곳을 누르면 같은 사진 출처 메뉴를 연다.
- 사진 위에는 편집 아이콘이나 배지를 겹쳐 놓지 않는다.
- 사진 출처 메뉴는 `사진 찍기`, `사진 보관함에서 선택`, `현재 사진 삭제`, `취소` 순서로 제공한다.
- 현재 사진을 삭제하면 닉네임의 첫 글자를 원형 배경에 표시한다. 제공자 사진은 이후 로그인에서 자동으로 다시 채우지 않는다.
- `공개 프로필` 섹션에 `닉네임`과 `아이디` 입력을 한 묶음으로 둔다.
- 닉네임은 1~30자다. 아이디는 영문 소문자, 숫자와 밑줄로 3~20자다.
- 형식이 맞는 새 아이디는 입력을 멈춘 뒤 사용 가능 여부를 확인한다. 이미 사용 중이면 사용 가능한 대안 세 개를 제안한다.
- 기본 상태에서는 검증 문구를 위한 빈 높이를 미리 잡지 않는다. 검증 결과가 있을 때만 입력 묶음 아래에 표시한다.

## 아이디 변경 정책

- 아이디는 변경이 성공한 시점부터 30일 동안 다시 바꿀 수 없다.
- 이전 아이디는 같은 시점부터 30일 동안 다른 계정에 배정하지 않는다.
- 기본 설명은 `아이디는 30일에 한 번 바꿀 수 있어요. 이전 아이디는 30일 동안 다른 사람이 사용할 수 없어요.`다.
- 기본 설명은 프로필 입력 묶음의 `FieldGroup.SectionFooter`로 표시한다. 앱이 별도 `margin` 값을 주지 않고 플랫폼의 기본 푸터 간격을 사용한다.
- 아이디를 바꾼 상태에서 `저장`을 누르면 `아이디를 변경할까요?` 확인 대화상자를 보여 준다. 본문에는 새 아이디, 30일 동안 다시 바꿀 수 없다는 점, 이전 아이디를 30일 동안 보호한다는 점을 함께 적는다.
- 확인 대화상자의 버튼은 `취소`와 `변경`이다. `변경`은 삭제 동작이 아니므로 빨간색으로 표시하지 않는다.
- `취소`하면 대화상자만 닫고 입력한 값을 유지한다.
- 변경이 끝나고 제한 기간에 다시 들어오면 아이디 입력만 비활성화한다. 기본 설명 대신 `YYYY년 M월 D일부터 아이디를 다시 바꿀 수 있어요.`처럼 실제 날짜를 표시한다.
- 다시 변경할 수 있는 시각은 서버가 판정하고 화면은 사용자 지역의 날짜로 표시한다.
- 제한 기간에도 프로필 사진과 닉네임은 수정하고 저장할 수 있다.

## 저장과 취소

- 프로필 사진, 닉네임과 아이디의 변경 내용을 한 번에 저장한다.
- 변경 내용이 없거나 입력값이 유효하지 않으면 `저장`을 비활성화한다.
- 아이디가 바뀌지 않았으면 별도 확인 없이 저장한다.
- 뒤로 가면 이번 화면에서 바꾼 초안을 버리고 설정 화면으로 돌아간다.
- 저장이 실패하면 입력한 값과 선택한 사진을 유지하고 같은 화면에서 다시 저장할 수 있게 한다.
- 저장이 끝나면 설정 화면의 프로필 사진, 닉네임과 아이디를 새 값으로 갱신한다.

## 오류와 가장자리 상태

- 카메라 권한을 거부하면 화면 안에서 설정에서 권한을 바꿀 수 있다고 알려 준다. 이후 사진 보관함을 선택하거나 카메라를 허용하면 이 안내를 지운다.
- 사진이 없는 상태에서는 `현재 사진 삭제`를 보여 주지 않는다.
- 긴 닉네임과 20자 아이디는 가운데 정렬을 유지하며 화면 너비 안에서 줄바꿈하거나 줄인다.
- 아이디 확인 중, 아이디 중복, 아이디 변경 제한, 사진 권한 거부와 저장 실패 상태를 각각 확인할 수 있어야 한다.

## 렌더러와 간격

- 네이티브 셸은 Settings `pageSheet`, 화면 push, 헤더와 도구막대를 소유한다.
- `@expo/ui`의 `Host`와 `FieldGroup`은 설정 목록과 프로필 폼을 소유한다.
- 프로필 머리말처럼 직접 구성하는 레이아웃은 기존 Uniwind 간격 눈금을 사용한다. 임의의 `11px` 같은 값을 새로 만들지 않는다.
- 섹션 푸터의 여백은 Uniwind 숫자 눈금으로 맞추지 않는다. `FieldGroup.SectionFooter`가 각 플랫폼에 제공하는 기본 간격을 우선한다.
- HTML 프로토타입의 푸터 간격은 네이티브 결과를 가까이 보여 주는 근사값이다. 실제 앱의 간격 계약으로 사용하지 않는다.

## 공개 범위와 권한

- 로그인한 사용자는 앱 안에서 다른 사용자의 프로필 사진, 닉네임과 아이디를 볼 수 있다.
- 프로필 사진 파일은 공개로 읽을 수 있다. 업로드, 교체와 삭제는 프로필 소유자만 할 수 있다.
- 로그인 없이 여는 웹 프로필, 아이디 기반 주소, 검색과 멘션은 만들지 않는다.

## 완료 조건

- 설정 화면이 승인한 한글 문구와 큰 가운데 정렬 프로필을 보여 준다.
- 설정 화면의 프로필 사진과 `프로필 수정` 항목이 같은 편집 화면을 연다.
- 프로필 사진과 `사진 편집`이 같은 출처 메뉴를 열고 편집 배지는 보이지 않는다.
- 사진 선택, 촬영, 삭제, 권한 거부와 복구 흐름이 동작한다.
- 닉네임과 아이디 형식 검증, 아이디 확인 중, 중복, 제안과 사용 가능 상태가 동작한다.
- 아이디를 바꿀 때 확인 대화상자를 거치며 취소하면 초안을 유지한다.
- 변경 뒤 30일 제한 상태에서는 아이디만 잠기고 실제 재변경 날짜를 보여 준다.
- 저장 실패 뒤 초안을 유지하고 다시 저장할 수 있다.
- iPhone과 iPad 너비, 긴 프로필과 글자 크기 확대한 상태에서도 내용이 잘리거나 빈 초과 스크롤이 생기지 않는다.

## 가정

- 온보딩에서 아이디를 처음 정하는 동작은 아이디 변경 횟수에 포함하지 않는다.
- 날짜 경계와 이전 아이디 보호는 클라이언트 시간이 아니라 서버가 저장한 시각을 기준으로 한다.
- 사진 선택기와 카메라는 운영체제가 제공하는 화면을 사용하며 프로토타입은 진입과 결과만 표현한다.

## 범위 밖

- 다른 사용자가 보는 공개 프로필 화면의 최종 디자인
- 공개 프로필 검색, 멘션과 아이디 기반 주소
- 사진 자르기, 회전과 필터 편집
- 아이디 변경 이력 공개와 이전 아이디 전달
- 데이터베이스 표, 저장소 경로와 API의 구체적인 구현

## 남은 위험

- `@expo/ui`가 플랫폼별 네이티브 푸터 간격을 사용하므로 HTML 프로토타입과 실제 수치는 다를 수 있다. 이 차이는 고정 픽셀로 보정하지 않는다.
- 아이디 확인과 최종 저장 사이에 다른 계정이 같은 값을 가져갈 수 있다. 최종 저장에서 서버와 데이터베이스 제약으로 다시 확인해야 한다.
- 실제 사진 선택기와 카메라 권한 문구는 운영체제 버전과 사용자의 기존 권한 상태에 따라 달라질 수 있다.
