# 웹 랜딩과 법적 고지 페이지 명세

## 목표

- 앱을 설치하지 않은 사람이 브라우저에서 제품 소개, 이용약관, 개인정보 처리방침을
  각각 고유한 주소로 연다.
- 스토어 제출 양식과 앱 화면이 가리킬 수 있는, 앞으로 바뀌지 않을 웹 주소를
  확보한다.
- 실제 문안을 쓰기 전에 세 페이지의 자리와 빌드·검사 경로를 먼저 세운다.

## 확정 범위

- 저장소에 웹 앱을 하나 더한다. 정적 사이트 생성기로 Astro를 쓴다.
- 세 경로를 만든다. `/`는 랜딩, `/terms`는 이용약관, `/privacy`는 개인정보
  처리방침이다.
- 세 페이지 모두 자리표시자만 담는다. 각 페이지는 자기 제목과, 아직 내용을 채우지
  않았다는 뜻이 드러나는 한국어 한두 문장을 보여 준다.
- 정적 출력으로 빌드한다. 배포 어댑터를 넣지 않는다.
- 저장소 루트의 turbo `build`, `check`, `check-types`, `fix` 작업에 이 앱을
  연결한다.
- `AGENTS.md`에 Astro 작업을 시작할 때 공식 문서 MCP를 쓰라는 안내 한 줄을 더한다.
- Astro 공식 문서 MCP 서버는 이 명세를 쓰면서 `.mcp.json`과 `.codex/config.toml`에
  이미 더했다. 구현에서 다시 설치하지 않는다.

## 확정 제약과 이유

- 웹 페이지는 모바일 앱이 아니라 별도 웹 앱이 소유한다.
  [모바일 개발 런타임](../../decisions/mobile-development-runtime.md)이 Expo Web을
  개발하지 않기로 이미 정했고, 이 작업은 그 결정을 바꾸지 않는다. 모바일 앱의 지원
  플랫폼은 iOS와 Android 그대로다. 랜딩과 법적 고지는 제품을 웹에서 돌리는 일이
  아니라 웹에 자리를 두는 일이다.
- 경로는 영문 소문자로 쓴다. 이 주소는 App Store와 Play Console 제출 양식, 앱 화면
  링크에 들어가므로 한 번 정하면 바꾸는 비용이 크다.
- 자리표시자에 진짜처럼 읽히는 약관이나 처리방침 문안을 쓰지 않는다. 법적 효력이
  있는 문서라 실제 문안은 사람이 확정해야 하고, 그럴듯한 초안이 남아 있으면 검토
  없이 배포될 수 있다.
- 정적 출력을 쓴다. 서버가 필요 없는 세 페이지이고, 어댑터를 넣지 않으면 호스팅
  대상을 나중에 골라도 페이지를 다시 만들지 않는다.
- 페이지 이름은 `이용약관`과 `개인정보 처리방침`으로 쓴다. 표기와 띄어쓰기는
  `GLOSSARY.md`를 따른다.
- Astro는 `llms.txt`를 제공하지 않는다. 공식 에이전트 컨텍스트는
  `https://mcp.docs.astro.build/mcp`의 문서 MCP 서버이고 `search_astro_docs` 도구
  하나를 노출한다. 그래서 `.agents/context/` 아래에 파일을 두지 않고 두 도구의
  MCP 설정에 서버를 등록한다.

## 수용 기준

- `/`, `/terms`, `/privacy` 세 주소가 각각 열리고 서로 다른 자리표시자를 보여 준다.
- 세 페이지의 브라우저 탭 제목이 서로를 구분한다.
- 없는 주소는 개발 서버나 호스트의 기본 404로 처리한다. 전용 404 페이지를
  만들지 않는다.
- 저장소 루트에서 `bun run build`, `bun run check`, `bun run check-types`가 이 앱을
  포함한 채로 통과한다.
- 빌드 결과가 서버 런타임 없이 파일만으로 열린다.
- 세 페이지 어디에도 실제 약관이나 처리방침으로 읽힐 문장이 없다.

## 가정

아래는 에이전트가 정한 값이라 사용자가 뒤집을 수 있다.

- 앱은 `apps/web`에 `@repo/web` 이름으로 둔다. `apps/api`, `apps/mobile`과 나란히
  둔다.
- Astro 7을 쓴다. 확인 시점 최신 안정 버전은 7.2.4이고 Node 요구는 `>=22.12`라
  루트 `engines`와 맞는다.
- `.astro` 파일의 타입과 진단 검사는 `astro check`가 맡고, Biome은 이 파일에서
  미사용 변수 규칙을 끈다. `.astro`를 Biome에서 통째로 빼는 방법도 같은 결과를
  낸다.
- 스타일 프레임워크와 디자인 토큰을 넣지 않는다. 브라우저 기본 표현으로 둔다.
- 세 페이지를 서로 오갈 수 있는 최소한의 링크를 둔다. 경로가 실제로 연결되는지
  눈으로 확인하기 위해서다.
- 자리표시자 문구에 제품 이름을 넣지 않는다. 이 저장소는 아직 `bun run setup`을
  실행하지 않은 템플릿 상태라 확정된 이름이 없다.
- Astro 개발 서버는 `bun run dev`의 slot과 포트 체계 밖에 둔다. 이 명령은 API,
  Metro와 기기만 관리한다.

## 제외

- 실제 이용약관과 개인정보 처리방침 문안. 사람이 확정할 법적 문서다.
- 랜딩 페이지의 디자인, 카피와 브랜딩. 제품 방향이 정해진 뒤에 다룬다.
- 배포 설정, 어댑터, 도메인 연결.
- 모바일 앱에서 이 페이지로 가는 링크.
- `bun run setup`이 바꾸는 식별자 목록.
  [템플릿 프로젝트 정체성](../../decisions/template-project-identity.md)이 알려진
  설정 필드만 바꾸도록 정해 두었고, 웹 앱은 아직 그 목록에 없다.
- 기존 제품 코드는 바꾸지 않는다.

## 보류

- 호스팅 대상과 도메인. 정적 출력이라 나중에 골라도 페이지를 다시 만들지 않는다.
  `apps/api`를 모바일과 분리된 Vercel 프로젝트로 두는 선례가
  [AI 서버 경계](../../decisions/ai-server-boundary.md)에 있다.
- Google Play 웹 계정 삭제 요청 경로.
  [모바일 계정 삭제](../../decisions/mobile-account-deletion.md)의 경계가 Android
  스토어 제출 전에 앱 없이 쓸 수 있는 웹 삭제 요청 경로를 요구한다. 이 웹사이트가
  그 경로가 놓일 자리이지만 사용자가 이번 범위에서 빼기로 정했다.
- 웹 표면 소유권을 결정 계약으로 올릴지. 지금은 이 명세 안에만 둔다. 사용자가
  Astro를 지정했을 뿐 Expo Web, Next.js, `apps/api`의 Hono JSX 같은 대안을 함께
  검토하지는 않았다. 웹 페이지가 늘어 같은 질문이 반복되면 그때 계약으로 올린다.

## 남은 위험

- Astro 7.0.0은 2026-06-22에 나온 두 달 된 major다. 정적 페이지 세 개만 쓰므로
  노출 범위는 좁지만 생태계 패키지가 아직 7을 지원하지 않을 수 있다. 막히면
  Astro 6으로 내린다.
- Biome 2.5.6은 `.astro`의 frontmatter만 파싱한다. frontmatter에서 선언하고
  템플릿에서만 쓰는 변수를 미사용으로 잡는 것을 실제 파일로 확인했다. 위 가정의
  규칙 예외는 이 오탐을 피하려는 것이고, Biome이 `.astro` 템플릿을 온전히 지원하면
  다시 본다.
- 자리표시자 상태로 배포하면 스토어 심사에서 빈 법적 문서로 반려될 수 있다. 실제
  문안을 채우기 전에는 제출하지 않는다.
