# 탈퇴 안내 화면 명세

## 목표

탈퇴 안내 화면이 되돌릴 수 없는 결정을 하는 자리로 보이게 한다. 지금 이 화면은
설정 목록과 시각적 무게가 같아서 알림 스위치를 켜는 화면처럼 읽힌다. 되돌릴 수
없다는 사실을 큰 제목으로 먼저 말하고, 무엇이 사라지는지 훑어서 찾을 수 있게 하고,
삭제 버튼을 눌러야 할 만큼 크게 둔다.

[계정 탈퇴 명세](../account-deletion/spec.md)가 정한 삭제 동작, 삭제 범위, 확인
절차와 실패 처리는 그대로 둔다. 이 명세는 안내 화면의 표현만 다룬다.

## 사용자에게 보이는 결과

- 화면을 열면 큰 제목이 가장 먼저 눈에 들어온다. 제목은 헤더에 이미 있는 화면
  이름을 되풀이하지 않고 되돌릴 수 없다는 사실을 말한다.
- 제목 아래 한 문장이 무엇이 지워지는지 예고한다.
- 삭제되는 정보를 목록으로 보여 준다. 각 항목은 아이콘과 이름을 가지며, 이름만으로
  범위가 분명하지 않은 항목은 한 줄 설명을 함께 보여 준다.
- 목록 아래에서 다시 가입해도 이전 정보가 돌아오지 않는다는 것을 알린다.
- 삭제 버튼은 화면 아래에 전폭으로 둔다. 목록 흐름 안의 한 줄이 아니라 화면을
  닫는 마지막 요소로 보인다.
- 삭제 버튼은 테마의 `danger` 색을 채워 쓴다. 설정 목록에서 이 화면으로 들어온
  `계정 탈퇴` 줄과 같은 색으로 읽힌다.
- 삭제 버튼을 누르면 지금과 같은 마지막 확인창이 뜬다. 확인창의 제목, 문구,
  버튼과 동작은 바뀌지 않는다.
- 삭제하는 동안 버튼이 진행 중임을 그 자리에서 보여 주고 다시 눌리지 않는다.
- 삭제를 끝내지 못하면 버튼 가까이에서 다시 시도할 수 있다는 안내를 보여 준다.
  현재 계정으로 남는다.
- 글자 크기를 키우거나 화면이 좁아 내용이 넘치면 스크롤한다. 잘리는 문장이 없다.

## 화면 문구

| 자리 | 문구 |
| --- | --- |
| 큰 제목 | `계정을 지우면 되돌릴 수 없습니다` |
| 안내 문장 | `탈퇴하면 아래 정보가 바로 삭제됩니다.` |
| 항목 1 | `로그인 계정` / `이메일, Google, Apple 연결` |
| 항목 2 | `프로필` / `닉네임과 아이디` |
| 항목 3 | `올린 프로필 사진` |
| 꼬리 문장 | `같은 방법으로 다시 가입해도 이전 정보는 돌아오지 않습니다.` |
| 삭제 버튼 | `계정 탈퇴` |
| 삭제 중 버튼 | `계정 탈퇴 중` |
| 실패 안내 | `계정 탈퇴를 끝내지 못했습니다. 다시 시도해 주세요.` |

큰 제목과 버튼에는 마침표를 붙이지 않고 평서문에는 붙인다. 탈퇴는 사용자가
조심해야 하는 상황이므로 합쇼체를 쓴다. `닉네임`과 `아이디`는 용어집이 정한
이름이며 다른 말로 바꾸지 않는다.

## 확정한 제약과 이유

- 화면은 계속 `@expo/ui`가 소유한다. `FieldGroup`을 걷어내고 같은 렌더러의 세로
  배치로 다시 만든다. `@expo/ui`는 `Column`, `Text`, `Button`, `ScrollView`를
  제공하므로 렌더러 경계 결정을 바꾸지 않고도 이 화면이 나오고, 설정 시트 안의
  다른 화면과 재질이 갈리지 않는다.
- 큰 제목은 `title` 등급의 bold로 시작한다. 헤더 제목이 이미 `계정 탈퇴`라 가장
  큰 등급을 얹으면 제목이 두 개로 보인다. Apple도 가장 큰 등급을 내비게이션 바
  큰 제목 자리로 둔다.
- 헤더의 접히는 Large Title은 쓰지 않는다. 렌더러 경계 결정이 이를 최상위 화면에
  두었고, 이 화면은 설정 시트 안에 푸시된 두 번째 화면이다.
- 확인 문구 입력이나 이메일 입력 단계를 넣지 않는다. 계정 탈퇴 명세가 실수 방지를
  안내 화면과 마지막 확인창 두 단계로 정했고 그 이유가 그대로 유효하다. 더하여,
  Apple 로그인을 비공개 이메일로 한 사람은 자기 계정 주소를 알지 못해 이메일
  입력을 요구하면 탈퇴하지 못한다.
- 삭제 항목을 문장 안으로 녹이지 않는다. 계정 탈퇴 명세의 완료 조건이 안내
  화면에서 삭제 대상을 보여 줄 것을 요구한다. 목록이어야 자기 사진이 지워지는지
  같은 것을 훑어서 찾는다.
- 아이콘은 `@expo/ui`가 그리는 플랫폼 심벌을 쓴다. iOS는 SF Symbol, Android는
  Material Symbol이다. 모양이 서로 달라도 뜻과 접근성 이름은 같다.
- 삭제 버튼의 색은 배경색으로 직접 지정한다. `@expo/ui`의 `Button`에는 destructive
  역할을 뜻하는 prop이 없어서 기본 tint로 두면 파랗게 그려지고, 이 화면으로 들어온
  빨간 `계정 탈퇴` 줄보다 덜 위험해 보인다.

## 완료 조건

1. 설정에서 `계정 탈퇴`를 눌러 안내 화면을 열면 큰 제목이 본문 첫 요소로 보인다.
   헤더 제목과 겹치거나 가려지지 않는다.
2. 삭제되는 정보 세 항목이 각각 아이콘과 이름을 갖고 목록으로 보인다.
3. 삭제 버튼이 화면 아래에 전폭으로 있고 빨간 배경에 흰 글씨다. 설정 목록의
   `계정 탈퇴` 줄과 같은 위험을 뜻하는 색으로 읽힌다.
4. 삭제 버튼을 누르면 지금과 같은 마지막 확인창이 뜬다. `취소`를 누르면 아무것도
   삭제하지 않고 이 화면에 남는다.
5. 마지막 확인창에서 `계정 탈퇴`를 누르면 버튼이 진행 중 상태로 바뀌고 다시
   눌리지 않는다.
6. 삭제에 실패하면 실패 안내가 버튼 가까이에 보이고 사용자는 현재 계정으로
   남는다. 다시 누를 수 있다.
7. iOS에서 시스템 글자 크기를 가장 크게 올려도 제목과 항목이 잘리지 않고 읽힌다.
   내용이 넘치면 스크롤한다.
8. Android에서 제목, 목록, 버튼과 실패 안내가 모두 보이고 글자색이 화면 모드를
   따른다.
9. Light와 Dark 모드에서 배경, 글자, 버튼 색이 모두 읽힌다.
10. 접근성 도구가 각 항목의 이름을 읽고, 삭제 버튼의 이름과 진행 중 상태를 읽는다.

자동 테스트는 항목과 버튼이 화면에 있는지, 버튼이 마지막 확인창을 여는지, 진행 중과
실패 상태가 바뀌는지 확인한다. 실제 글자 크기, 색과 배치는 iOS와 Android
Development Build에서 확인한다.

## 이번 범위에서 제외하는 내용

- 삭제 동작, 삭제 범위, 서버 경로와 실패 복구 방식. 계정 탈퇴 명세가 소유한다.
- 마지막 확인창의 제목, 문구와 버튼
- 설정 화면의 `계정 탈퇴` 줄과 그 위치
- 재로그인, 인증 코드 재입력, 확인 문구 입력
- 탈퇴 사유 묻기와 탈퇴 뒤 안내 화면
- 웹 탈퇴 요청 경로. 계정 탈퇴 명세가 심사 전 미룬 항목으로 들고 있다.
- 설정 시트의 다른 화면. 이 명세는 안내 화면 하나만 바꾼다.

## 가정

- 큰 제목의 등급은 `title` bold에서 시작한다. 실기기에서 보고 한 단계 내리는 것은
  값 하나를 바꾸는 일이므로 되돌리기 쉽다.
- 삭제 항목은 셋이다. 계정 탈퇴 명세가 구현할 때 계정에 연결된 서버 저장 데이터를
  다시 확인하라고 했으므로, 삭제 대상이 늘면 이 목록도 함께 늘린다.
- 표의 문구는 화면 문구 한국어 말투를 따른 시작 초안이다. 실기기에서 줄바꿈과
  길이를 보고 다듬을 수 있으며, 다듬어도 각 자리가 전달해야 하는 내용은 위의
  "사용자에게 보이는 결과"가 정한 그대로다.

## 남은 위험

- Android에서는 제목 글자 크기가 시스템 글자 크기 확대를 따라가지 않는다.
  `@expo/ui`의 Jetpack Compose 모디파이어에 타이포그래피 항목이 없어서 고정 숫자로
  둘 수밖에 없다. iOS는 시맨틱 텍스트 스타일을 지정해 Dynamic Type을 따라간다.
  모바일 타이포그래피가 요구하는 접근성 확대를 두 플랫폼에서 똑같이 지키지 못하는
  상태이며, `@expo/ui`를 올릴 때 다시 확인한다.
- 삭제 버튼의 색을 배경색으로 직접 지정하므로 플랫폼이 파괴적 동작의 버튼 표현을
  바꾸면 따라가지 못한다. `@expo/ui`의 `Button`에 역할 prop이 생기면 그쪽으로
  옮긴다.
- 설정 시트의 헤더가 투명해서 본문이 헤더 아래로 스크롤한다. 큰 제목이 헤더 제목과
  겹쳐 보이지 않는지 실기기에서 확인해야 한다.
- `@expo/ui`의 세로 배치로 이 화면을 만든 전례가 이 앱에 없다. 하단 고정 버튼과
  스크롤을 한 화면에서 함께 두는 방식은 구현 중에 확인이 필요하다.
