# 탈퇴 안내 화면 명세

## 목표

탈퇴 안내 화면이 되돌릴 수 없는 결정을 하는 자리로 보이게 한다. 지금 이 화면은
설정 목록과 시각적 무게가 같아서 알림 스위치를 켜는 화면처럼 읽힌다. 되돌릴 수
없다는 사실을 큰 제목으로 먼저 말하고, 무엇이 사라지는지 훑어서 찾을 수 있게 하고,
삭제 버튼을 눌러야 할 만큼 크게 둔다.

설정 목록의 `계정 탈퇴` 줄도 함께 옮긴다. 지금은 `계정` 섹션 안에 프로필 수정,
로그아웃과 나란히 있어서 성격이 다른 세 동작이 한 묶음으로 보인다.

[계정 탈퇴 명세](../account-deletion/spec.md)가 정한 삭제 동작, 삭제 범위, 확인
절차와 실패 처리는 그대로 둔다. 이 명세는 탈퇴로 들어가는 자리와 안내 화면의
표현만 다룬다.

## 사용자에게 보이는 결과

- 화면을 열면 큰 제목이 가장 먼저 눈에 들어온다. 제목은 헤더에 이미 있는 화면
  이름을 되풀이하지 않고 되돌릴 수 없다는 사실을 말한다.
- 제목 아래 한 문장이 무엇이 지워지는지 예고한다.
- 삭제되는 정보를 목록으로 보여 준다. 각 항목은 아이콘과 이름을 가지며, 이름만으로
  범위가 분명하지 않은 항목은 한 줄 설명을 함께 보여 준다.
- 목록 아래에서 다시 가입해도 이전 정보가 돌아오지 않는다는 것을 알린다.
- 삭제 버튼은 화면 아래에 전폭으로 둔다. 목록 흐름 안의 한 줄이 아니라 화면을
  닫는 마지막 요소로 보인다.
- 삭제 버튼은 테마의 `danger` 색을 채워 쓴다. 설정 목록에서 이 화면으로 들어온
  `계정 탈퇴` 줄과 같은 색으로 읽힌다.
- 삭제 버튼을 누르면 지금과 같은 마지막 확인창이 뜬다. 확인창의 제목, 문구,
  버튼과 동작은 바뀌지 않는다.
- 삭제하는 동안 버튼이 진행 중임을 그 자리에서 보여 주고 다시 눌리지 않는다.
- 삭제를 끝내지 못하면 버튼 가까이에서 다시 시도할 수 있다는 안내를 보여 준다.
  현재 계정으로 남는다.
- 글자 크기를 키우거나 화면이 좁아 내용이 넘치면 스크롤한다. 잘리는 문장이 없다.

## 설정 화면의 탈퇴 진입

- `계정 탈퇴`는 설정 목록의 맨 아래에 라벨 없는 단독 그룹으로 선다. 위의 마지막
  섹션과 그룹이 떨어져 있어 다른 설정 항목과 한 묶음으로 읽히지 않는다.
- 그 그룹에는 `계정 탈퇴` 한 줄만 있다. 라벨도 설명 푸터도 붙이지 않는다.
- 행의 생김새는 지금 그대로다. 위험을 뜻하는 빨간 글씨, 왼쪽 정렬, iOS에서는
  이동을 뜻하는 셰브론을 유지한다.
- `로그아웃`은 `계정` 섹션에 그대로 남는다. 위치, 색과 동작을 바꾸지 않는다.
  로그아웃 실패 안내도 지금 자리에 남는다.
- `계정` 섹션에는 `프로필 수정`과 `로그아웃`이 남는다. 다른 섹션의 순서와 내용은
  바뀌지 않는다.

## 화면 문구

| 자리 | 문구 |
| --- | --- |
| 큰 제목 | `계정을 지우면 되돌릴 수 없습니다` |
| 안내 문장 | `탈퇴하면 아래 정보가 바로 삭제됩니다.` |
| 항목 1 | `로그인 계정` / `이메일, Google, Apple 연결` |
| 항목 2 | `프로필` / `닉네임과 아이디` |
| 항목 3 | `올린 프로필 사진` |
| 꼬리 문장 | `같은 방법으로 다시 가입해도 이전 정보는 돌아오지 않습니다.` |
| 삭제 버튼 | `계정 탈퇴` |
| 삭제 중 버튼 | `계정 탈퇴 중` |
| 실패 안내 | `계정 탈퇴를 끝내지 못했습니다. 다시 시도해 주세요.` |

큰 제목과 버튼에는 마침표를 붙이지 않고 평서문에는 붙인다. 탈퇴는 사용자가
조심해야 하는 상황이므로 합쇼체를 쓴다. `닉네임`과 `아이디`는 용어집이 정한
이름이며 다른 말로 바꾸지 않는다.

## 확정한 제약과 이유

- 화면은 계속 `@expo/ui`가 소유한다. `FieldGroup`을 걷어내고 같은 렌더러의 세로
  배치로 다시 만든다. `@expo/ui`는 `Column`, `Text`, `Button`, `ScrollView`를
  제공하므로 렌더러 경계 결정을 바꾸지 않고도 이 화면이 나오고, 설정 시트 안의
  다른 화면과 재질이 갈리지 않는다.
- 큰 제목은 `title` 등급의 bold로 시작한다. 헤더 제목이 이미 `계정 탈퇴`라 가장
  큰 등급을 얹으면 제목이 두 개로 보인다. Apple도 가장 큰 등급을 내비게이션 바
  큰 제목 자리로 둔다.
- 큰 제목의 크기는 플랫폼마다 다른 방법으로 지정하되 양쪽 다 시스템 글자 크기
  확대를 따라간다. iOS는 시맨틱 텍스트 스타일을 지정해 플랫폼의 타입 램프와
  Dynamic Type을 그대로 받는다. Android는 `@expo/ui`에 대응하는 타이포그래피
  모디파이어가 없어 숫자로 지정하지만, 그 숫자가 `sp`로 렌더링되어 시스템 글자
  크기 설정을 따라간다. 두 플랫폼의 글자 크기가 픽셀 단위로 같을 필요는 없다.
  모바일 타이포그래피가 정한 판단 기준이 같은 역할, 위계와 접근성 동작이다.
- 헤더의 접히는 Large Title은 쓰지 않는다. 렌더러 경계 결정이 이를 최상위 화면에
  두었고, 이 화면은 설정 시트 안에 푸시된 두 번째 화면이다.
- 확인 문구 입력이나 이메일 입력 단계를 넣지 않는다. 계정 탈퇴 명세가 실수 방지를
  안내 화면과 마지막 확인창 두 단계로 정했고 그 이유가 그대로 유효하다. 더하여,
  Apple 로그인을 비공개 이메일로 한 사람은 자기 계정 주소를 알지 못해 이메일
  입력을 요구하면 탈퇴하지 못한다.
- 삭제 항목을 문장 안으로 녹이지 않는다. 계정 탈퇴 명세의 완료 조건이 안내
  화면에서 삭제 대상을 보여 줄 것을 요구한다. 목록이어야 자기 사진이 지워지는지
  같은 것을 훑어서 찾는다.
- 아이콘은 `@expo/ui`가 그리는 플랫폼 심벌을 쓴다. iOS는 SF Symbol, Android는
  Material Symbol이다. 모양이 서로 달라도 뜻과 접근성 이름은 같다.
- 삭제 버튼의 색은 배경색으로 직접 지정한다. `@expo/ui`의 `Button`에는 destructive
  역할을 뜻하는 prop이 없어서 기본 tint로 두면 파랗게 그려지고, 이 화면으로 들어온
  빨간 `계정 탈퇴` 줄보다 덜 위험해 보인다.
- 설정의 `계정 탈퇴`를 라벨 없는 단독 그룹으로 떼는 것은 플랫폼이 이미 쓰는
  방식이다. Apple의 결제 수단 화면도 되돌릴 수 없는 `Remove Payment Method`를
  라벨 없는 그룹에 혼자 두고, 되돌릴 수 있는 동작은 관련 데이터와 같은 그룹 안에
  남긴다. 라벨을 붙이면 그 이름이 무엇의 묶음인지 다시 설명해야 하고, 위 섹션과
  같은 무게로 읽힌다.
- 설정의 `계정 탈퇴` 행에는 셰브론을 유지한다. Apple의 같은 자리 행에는 셰브론이
  없지만 그 행은 누르는 즉시 확인창을 띄운다. 우리 행은 안내 화면으로 이동하므로
  셰브론이 있어야 누른 결과를 바르게 예고한다.
- 설정 화면에서 이 행을 버튼이나 텍스트 링크로 바꾸지 않는다. 버튼은 그 자리에서
  실행된다는 뜻이라 안내 화면을 여는 동작과 어긋난다. 테두리 없는 링크는 그룹형
  목록의 표현이 아니며 `FieldGroup` 바깥으로 나가야 해서 한 화면 한 렌더러 원칙과
  부딪힌다.

## 완료 조건

1. 설정을 열면 `계정 탈퇴`가 목록의 맨 아래 그룹에 혼자 있고 그 그룹에 라벨이
   없다. 위 섹션과 그룹이 떨어져 보인다.
2. `계정` 섹션에는 `프로필 수정`과 `로그아웃`이 남는다. 로그아웃을 누르면 지금과
   같이 즉시 로그아웃하고, 실패 안내도 지금 자리에 나온다.
3. 설정에서 `계정 탈퇴`를 눌러 안내 화면을 열면 큰 제목이 본문 첫 요소로 보인다.
   헤더 제목과 겹치거나 가려지지 않는다.
4. 삭제되는 정보 세 항목이 각각 아이콘과 이름을 갖고 목록으로 보인다.
5. 삭제 버튼이 화면 아래에 전폭으로 있고 빨간 배경에 흰 글씨다. 설정 목록의
   `계정 탈퇴` 줄과 같은 위험을 뜻하는 색으로 읽힌다.
6. 삭제 버튼을 누르면 지금과 같은 마지막 확인창이 뜬다. `취소`를 누르면 아무것도
   삭제하지 않고 이 화면에 남는다.
7. 마지막 확인창에서 `계정 탈퇴`를 누르면 버튼이 진행 중 상태로 바뀌고 다시
   눌리지 않는다.
8. 삭제에 실패하면 실패 안내가 버튼 가까이에 보이고 사용자는 현재 계정으로
   남는다. 다시 누를 수 있다.
9. iOS에서 시스템 글자 크기를 가장 크게 올리면 제목과 항목의 글자가 실제로 커진다.
   잘리는 문장이 없고, 내용이 넘치면 스크롤한다.
10. Android에서 시스템 글자 크기를 가장 크게 올려도 마찬가지다. 제목과 항목의 글자가
    실제로 커지고, 잘리지 않고, 넘치면 스크롤한다.
11. Android에서 제목, 목록, 버튼과 실패 안내가 모두 보이고 글자색이 화면 모드를
    따른다.
12. Light와 Dark 모드에서 설정 목록과 안내 화면의 배경, 글자, 버튼 색이 모두 읽힌다.
13. 접근성 도구가 각 항목의 이름을 읽고, 삭제 버튼의 이름과 진행 중 상태를 읽는다.

자동 테스트는 항목과 버튼이 화면에 있는지, 버튼이 마지막 확인창을 여는지, 진행 중과
실패 상태가 바뀌는지 확인한다. 실제 글자 크기, 색과 배치는 iOS와 Android
Development Build에서 확인한다.

## 이번 범위에서 제외하는 내용

- 삭제 동작, 삭제 범위, 서버 경로와 실패 복구 방식. 계정 탈퇴 명세가 소유한다.
- 마지막 확인창의 제목, 문구와 버튼
- `로그아웃`의 위치, 색과 동작
- 설정 화면의 다른 섹션과 그 순서, 프로필 머리말
- 재로그인, 인증 코드 재입력, 확인 문구 입력
- 탈퇴 사유 묻기와 탈퇴 뒤 안내 화면
- 웹 탈퇴 요청 경로. 계정 탈퇴 명세가 심사 전 미룬 항목으로 들고 있다.
- 설정 시트의 다른 화면. 이 명세는 설정 목록의 탈퇴 줄과 안내 화면만 바꾼다.

## 가정

- 큰 제목의 등급은 `title` bold에서 시작한다. 실기기에서 보고 한 단계 내리는 것은
  값 하나를 바꾸는 일이므로 되돌리기 쉽다.
- 삭제 항목은 셋이다. 계정 탈퇴 명세가 구현할 때 계정에 연결된 서버 저장 데이터를
  다시 확인하라고 했으므로, 삭제 대상이 늘면 이 목록도 함께 늘린다.
- 표의 문구는 화면 문구 한국어 말투를 따른 시작 초안이다. 실기기에서 줄바꿈과
  길이를 보고 다듬을 수 있으며, 다듬어도 각 자리가 전달해야 하는 내용은 위의
  "사용자에게 보이는 결과"가 정한 그대로다.
- 설정 화면에 빨간 글씨가 `로그아웃`과 `계정 탈퇴` 둘로 남는다. Apple은 이
  패턴에서 되돌릴 수 없는 동작 하나에만 빨강을 쓰고 되돌릴 수 있는 동작은
  강조색으로 둔다. 그 기준을 따르려면 `로그아웃`을 강조색으로 바꾸는 선택지가
  있으며, 이번 범위에서는 로그아웃을 건드리지 않기로 해서 미뤄 둔다. 빨강이 둘로
  남는 동안에는 `계정 탈퇴`가 로그아웃보다 더 무겁다는 것을 색이 아니라 위치와
  단독 그룹이 전달한다.

## 남은 위험

- Android의 제목 크기는 우리가 고른 숫자다. 시스템 글자 크기 확대는 따라가지만
  Android가 정한 타입 램프를 따라가지는 않는다. 플랫폼이 기본 타이포그래피를 바꾸면
  이 숫자만 그대로 남는다. `@expo/ui`가 Compose 쪽에 타이포그래피 모디파이어를
  더하면 그쪽으로 옮긴다.
- 삭제 버튼의 색을 배경색으로 직접 지정하므로 플랫폼이 파괴적 동작의 버튼 표현을
  바꾸면 따라가지 못한다. `@expo/ui`의 `Button`에 역할 prop이 생기면 그쪽으로
  옮긴다.
- 설정 시트의 헤더가 투명해서 본문이 헤더 아래로 스크롤한다. 큰 제목이 헤더 제목과
