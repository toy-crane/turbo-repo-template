# 공개 웹 페이지 명세

## 목표

- 스토어 제출에 필요한 공개 웹 주소 네 개를 갖는다.
- 앱을 설치하지 않은 사람도 계정 삭제를 요청할 수 있다.

## 확정 범위

- `apps/web`을 Astro 정적 사이트로 새로 만든다. 소유 앱, 렌더링 방식과 배포 단위는
  [웹 사이트 경계](../../decisions/web-site-boundary.md) 계약을 따른다.
- 페이지 네 장을 만든다: 랜딩, 이용약관, 개인정보처리방침, 계정 삭제 요청.
- 계정 삭제 요청 페이지는 지원 메일 주소를 노출한다. 폼과 로그인을 두지 않는다.
- 계정 삭제 요청 페이지는 요청에 담을 내용을 안내한다: 계정에 등록된 이메일 주소와
  삭제를 원한다는 뜻.
- 계정 삭제 요청 페이지는 앱을 설치한 사람은 앱 안에서 바로 지울 수 있다고
  안내하되, 그 안내가 웹 요청 경로를 대신하지 않는다.
- 계정 삭제 요청 페이지는 무엇이 지워지는지 [모바일 계정 삭제](../../decisions/mobile-account-deletion.md)의
  삭제 범위와 같게 적고, 되돌릴 수 없다고 밝힌다.
- 네 페이지 모두에 스토어 등록 정보와 같은 앱 이름을 적는다.
- 네 페이지 모두 서로를 오갈 수 있게 링크한다.
- 화면 문구는 [화면 문구 한국어 말투](../../decisions/korean-ui-writing.md)를 따른다.

## 수용 기준

- 네 주소가 로그인 없이 오류 없이 열린다.
- 계정 삭제 요청 페이지를 열면 스크롤하지 않고 삭제 요청 방법과 지원 메일 주소가
  보인다.
- 네 페이지 모두에 스토어 등록 정보와 같은 앱 이름이 나온다.
- 개인정보처리방침에 개인정보 보호책임자의 이름 또는 부서 명칭과 연락처가 있다.
- 어느 페이지도 홈으로 리디렉션하지 않고, PDF가 아니라 HTML로 열린다.
- 빌드 결과물이 정적 파일뿐이고 서버 함수가 없다.
- `bun run check`, `bun run check-types`, `bun run build`가 통과한다.

## 가정

- 랜딩은 최소 구성이다: 앱 이름, 한 문단 소개, 스토어 링크 자리, 세 법적 페이지로
  가는 링크. 스크린샷과 기능 소개는 넣지 않는다. 필요해지면 그때 늘린다.
- 언어는 한국어 하나다.
- 약관과 방침의 초안은 개인정보보호위원회 「개인정보 처리방침 작성지침」을 바탕으로
  쓰고, 내보내기 전에 사람이 검토한다.
- 지원 메일 주소는 사용자가 정해 주는 값을 쓴다. 정해지기 전에는 자리표시자를 두고
  수용 기준을 통과시키지 않는다.
- `bun run dev`의 worktree 개발 세션에 웹을 넣지 않는다. 정적 사이트라 전용 포트와
  기기 배정이 필요 없다. `apps/web`에서 Astro 개발 서버를 직접 띄운다.
- 경로는 `/`, `/terms`, `/privacy`, `/delete-account`다.

## 제외

- 접수한 삭제 요청을 확인하고 실행하는 절차. 아래 미룬 결정을 따른다.
- 도메인 연결과 Vercel 프로젝트 생성. 저장소 밖 작업이다.
- Play Console Data safety 양식 작성.
- 앱 안에서 이 페이지들로 링크 걸기. `apps/mobile` 변경이라 별도 작업이다.
- 다국어.
- `apps/mobile`, `apps/api`, `supabase`는 바꾸지 않는다.

## 미룬 결정

접수한 삭제 요청을 확인하고 실행하는 절차를 정하지 않았다. 스토어 제출 전에
정해야 한다. 조사한 근거를 남긴다.

- 본인 확인은 의무다. 개인정보보호법 제38조는 삭제를 요구한 자가 본인이거나 정당한
  대리인인지 확인하도록 한다.
- 확인은 이메일이면 충분하다. GDPR 제12조 6항은 확인을 허용하되 비례성을 요구하고,
  아일랜드 DPC는 신분증 사본 요구를 위반으로 보면서 이메일 확인을 덜 침해적인
  수단으로 지목했다.
- 확인 메일은 요청이 온 주소가 아니라 계정에 등록된 주소로 보내야 한다. 발신 주소
  위조는 보내는 쪽만 속이고 받는 쪽을 가로채지 못한다.
- 응답으로 계정 존재 여부를 알려주지 않는다. 계정이 있든 없든 같은 문구로 답한다.
- 기한이 짧다. 개인정보보호법 제21조와 시행령은 정당한 사유가 없으면 5일 이내
  파기하도록 한다.
- 실행은 `supabase/functions/delete-account/delete-account.ts`의
  `deleteCurrentAccount(admin, userId)`를 재사용해야 한다. 이 함수는 쓰기 차단
  표시, `avatars` 폴더 재귀 삭제, Auth 계정 삭제를 순서대로 한다. 이미 `userId`를
  받는 함수라 관리자 쪽에서 그대로 쓸 수 있다.
- Supabase 대시보드에서 Auth 사용자만 지우면 `avatars` 버킷에 프로필 사진이 남아
  [모바일 계정 삭제](../../decisions/mobile-account-deletion.md)의 삭제 범위를
  어긴다. 수동 처리를 기본 절차로 삼지 않는다.

## 남은 위험

- Biome 2.5.6의 `.astro` 지원은 실험 단계다. 첫 `bun run check`에서 오탐이나
  미검사가 드러날 수 있다. 드러나면 `biome.jsonc`에서 범위를 좁히고, 그래도 막히면
  [웹 사이트 경계](../../decisions/web-site-boundary.md)의 프레임워크 선택을 다시
  연다.
- 약관과 방침 문구의 법적 충분성은 이 작업이 보장하지 않는다. 사람 검토가 필요하다.
- 계정 삭제 요청 페이지의 주소는 Play Console Data safety 양식에 등록한 뒤 바꾸면
  안 된다. 등록 전에 경로를 확정한다.
- 웹 삭제 요청 창구는 앱 안 삭제에 없던 사칭 위험을 만든다. 앱 안 삭제는 로그인한
  사용자가 자기 계정만 지운다. 위 미룬 결정이 이 위험을 다룬다.
