# Expo 참조 저장소 색인 명세

## 목표

- 에이전트와 사용자가 Expo 작업을 시작할 때 참고할 공개 구현 예시 다섯 개를 한
  문서에서 찾는다.
- 결정 계약이 아직 없는 새 작업에서도 색인이 발견되도록 `AGENTS.md`가 색인을
  안내한다.

## 확정 범위

- `docs/references/expo-reference-repos.md`에 얇은 참조 색인을 만든다.
- 다섯 저장소를 모두 싣는다: SchroederNathan/expo-ui-examples,
  margelo/ai-chat-demo, SchroederNathan/clarity, SchroederNathan/amber,
  EvanBacon/expo-ai.
- 색인 서두에 규칙을 둔다: 색인은 규범이 아니라 지도이며, 결정 계약과 충돌하면
  결정 계약이 이긴다.
- 항목은 네 줄 형식을 쓴다: 무엇, 고정 사본, 이럴 때 본다, 들여오지 않는다.
- amber와 expo-ai는 들여오지 않는 부분이 중심인 경고 항목으로 쓴다.
- margelo 항목은 [모바일 AI 채팅 표현](../../decisions/mobile-ai-chat-rendering.md)
  계약의 기존 인용을 원본으로 가리키고 내용을 옮기지 않는다.
- `AGENTS.md` 프로젝트 결정 섹션에 색인 안내 한 줄을 더한다.
- 색인의 역할, 항목 형식, 커밋 고정 방식은
  [Expo 참조 저장소 색인](../../decisions/expo-reference-repo-index.md) 결정
  계약으로 보존한다.

## 수용 기준

- 색인 서두에서 규범 아님과 결정 계약 우선 규칙을 읽을 수 있다.
- 다섯 항목 모두 검토 시점 커밋을 가리키는 고정 링크가 있고, 링크가 실제
  커밋으로 열린다.
- 이럴 때 본다에 적은 파일과 폴더 경로가 고정 커밋 기준으로 실제로 존재한다.
- amber와 expo-ai 항목의 들여오지 않는다 줄이 근거 결정 계약 파일로 링크된다.
- `AGENTS.md`의 색인 링크가 색인 문서로 열린다.

## 가정

- 위치와 이름은 `docs/references/expo-reference-repos.md`다. 참조 문서가 늘면
  `docs/references/` 아래에 같은 방식으로 둔다.
- 갱신 규칙은 색인 끝에 둔다: 저장소를 추가할 때 같은 형식을 쓰고, Expo SDK를
  올릴 때 고정 커밋을 갱신하거나 낡은 항목을 지운다.

## 제외

- 결정 계약 본문은 바꾸지 않는다. margelo 인용은 계약에 그대로 둔다. 계약이
  원본이기 때문이다.
- 저장소의 코드 패턴을 색인으로 옮겨 적지 않는다. 공식 Expo 스킬과 겹치고 SDK가
  오르면 낡기 때문이다.
- 제품 코드는 바꾸지 않는다.

## 남은 위험

- 참조 저장소가 삭제되면 고정 링크에 접근할 수 없다. 항목의 무엇 줄만으로도
  어떤 저장소였는지 알 수 있게 유지한다.
- 이럴 때 본다의 경로는 2026-08-18 검토 시점 기준이다. 고정 커밋 링크가 이후
  변경의 영향을 막는다.
