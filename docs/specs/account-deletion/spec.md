# 계정 탈퇴 명세

## 목표

로그인한 사용자가 모바일 앱의 설정에서 자기 계정과 연결된 데이터를 즉시 영구
삭제한다. 실수로 탈퇴하지 않도록 삭제 결과를 먼저 알리고 한 번 더 확인하지만,
재로그인이나 별도 문구 입력은 요구하지 않는다.

## 사용자에게 보이는 결과

- 설정의 `계정` 섹션에 `계정 탈퇴`를 둔다. 로그아웃과 구분되는 항목이며 쉽게
  찾을 수 있어야 한다.
- `계정 탈퇴`를 누르면 별도 화면에서 삭제되는 데이터와 복구할 수 없다는 점을
  알린다.
- 사용자가 탈퇴를 시작하면 마지막 확인창을 연다. 사용자는 `취소`로 돌아가거나
  `계정 탈퇴`로 영구 삭제를 시작한다.
- 마지막 확인 뒤에는 재로그인, 인증 코드 입력이나 `탈퇴` 문구 입력을 요구하지
  않는다.
- 삭제하는 동안 같은 요청을 다시 시작할 수 없게 하고, 탈퇴 작업이 진행 중임을
  시작한 자리에서 보여 준다.
- 삭제가 끝나면 이 기기에 남은 로그인 상태와 사용자별 캐시를 지우고 로그인
  화면을 보여 준다.
- 삭제를 끝내지 못하면 성공한 것처럼 로그아웃하지 않는다. 현재 계정으로 돌아와
  다시 시도할 수 있는 안내를 보여 준다.

## 삭제 범위와 동작

- 마지막 확인과 동시에 삭제를 시작한다. 유예 기간, 탈퇴 취소와 복구 기능은 두지
  않는다.
- 요청을 보낸 로그인 사용자의 계정만 삭제한다. 사용자가 삭제할 계정 식별자를
  따로 고르거나 입력하지 않는다.
- 인증 계정, 로그인 신원, 프로필, 닉네임, 아이디, 이전 아이디 기록과 사용자가
  올린 프로필 사진을 영구 삭제한다.
- 구현할 때 계정에 연결된 서버 저장 데이터를 다시 확인하고, 이 명세 뒤에 추가된
  사용자 데이터도 삭제 대상에서 빠뜨리지 않는다.
- 다른 기기의 새 세션 발급도 끝낸다. 이미 발급된 access token이 만료 전까지
  남더라도 삭제된 계정은 개인정보를 읽거나 비용이 드는 기능을 사용할 수 없어야
  한다.
- 같은 삭제 요청을 여러 번 받거나, 삭제를 마친 뒤 응답만 전달되지 않은 경우에도
  사용자는 탈퇴한 상태로 끝나야 한다.
- 삭제한 로그인 방법으로 다시 가입하면 이전 데이터가 돌아오지 않는 새 계정으로
  시작한다.

## 확정한 제약과 이유

- 현재 제품에는 구독, 결제나 법에 따라 보관해야 한다고 정한 계정 데이터가 없다.
  따라서 즉시 영구 삭제를 기본으로 한다. 유예 삭제에 필요한 예약 상태와 복구
  흐름은 만들지 않는다.
- 실수 방지는 안내 화면과 마지막 확인창의 두 단계로 처리한다. 재인증을 더하면
  비밀번호가 없는 이메일 코드, Google과 Apple 로그인을 각각 다시 다뤄야 하고
  탈퇴를 불필요하게 어렵게 만든다.
- 계정을 지울 수 있는 관리자 비밀 값은 서버만 가진다. 모바일 앱, 공개 환경 변수,
  공유 패키지와 사용자 응답에 넣지 않는다.
- 서버는 로그인 상태에서 확인한 현재 사용자만 대상으로 삼는다. 모바일 앱이 보낸
  사용자 식별자를 관리자 권한으로 그대로 믿지 않는다.
- 프로필 사진 삭제와 계정 삭제 중 일부만 끝날 수 있으므로 부분 실패를 성공으로
  처리하지 않는다. 다시 시도하면 남은 삭제를 안전하게 끝낼 수 있어야 한다.

## 완료 조건

1. 로그인한 사용자가 설정에서 `계정 탈퇴`를 찾아 안내 화면을 연다.
2. 안내 화면은 삭제 대상과 복구할 수 없다는 점을 보여 준다.
3. 마지막 확인창에서 `취소`를 누르면 아무 데이터도 삭제하지 않고 안내 화면에
   남는다.
4. 마지막 확인창에서 `계정 탈퇴`를 누르면 요청을 한 번만 시작하고 진행 중 상태를
   보여 준다.
5. 탈퇴가 끝나면 해당 인증 계정, 프로필과 프로필 사진이 더는 존재하지 않고 앱은
   로그인 화면을 보여 준다.
6. 다른 기기에 남은 refresh token으로 새 access token을 발급받지 못한다.
7. 탈퇴 전에 받은 access token으로 개인정보를 읽거나 비용이 드는 AI 요청을 보낼
   수 없다.
8. 연결이 끊기거나 서버가 실패하면 완료로 표시하지 않는다. 사용자는 계정이 남은
   상태에서 다시 시도할 수 있다.
9. 서버에서 삭제가 끝난 직후 응답이 끊겨도 다음 앱 상태는 로그인 화면이며, 같은
   요청이 다른 계정이나 데이터에 영향을 주지 않는다.
10. 이메일 인증 코드, Google과 Apple로 만든 계정을 각각 탈퇴할 수 있다.
11. iOS와 Android에서 안내, 취소, 진행 중, 성공과 실패 상태를 확인한다.

## 이번 범위에서 제외하는 내용

- 탈퇴 유예 기간, 탈퇴 취소와 계정 복구
- 탈퇴 전 재로그인, 인증 코드 재입력과 확인 문구 입력
- Apple REST API를 통한 Sign in with Apple 토큰 취소
- Google 또는 Apple의 외부 계정 자체 삭제
- 계정 데이터 내려받기
- 운영자용 사용자 검색, 일괄 삭제와 강제 탈퇴
- 구독 해지, 환불과 법적 보관 데이터 처리
- 앱 밖에서 사용하는 웹 탈퇴 요청 경로

## 심사 전 미룬 항목

Google Play에 앱을 제출하기 전에는 앱을 설치하지 않은 사용자도 접근할 수 있는
웹 탈퇴 요청 경로를 추가하고 그 주소를 Play Console의 Data Safety 양식에 등록해야
한다. 웹 경로는 정상적으로 열리고 앱 또는 개발자 이름을 표시하며, 사용자가 앱을
다시 설치하지 않고 탈퇴를 요청할 수 있어야 한다.

이번 구현은 모바일 앱 안의 탈퇴만 다룬다. 웹 경로를 만들고 Data Safety 신고를
마치기 전에는 Android 스토어 제출에 필요한 계정 삭제 절차를 완료한 것으로 보지
않는다.

- [Google Play 사용자 데이터 정책](https://support.google.com/googleplay/android-developer/answer/10144311)
- [Google Play 계정 삭제 요구사항](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en)

## 가정

- 현재 서버는 대화 내용을 계정 데이터로 저장하지 않는다.
- 탈퇴할 때 따로 보관해야 하는 결제, 보안, 부정 사용 방지나 법정 보관 기록이 없다.
- 나중에 이런 데이터나 구독을 추가하면 탈퇴 안내, 삭제 범위와 보관 정책을 함께
  다시 정한다.

## 남은 위험

- Sign in with Apple 토큰을 취소하지 않는다. Apple 권한이 남아 재가입 때 최초
  동의 화면이 다시 나오지 않을 수 있고 App Store 심사에서 추가 설명이나 변경을
  요구받을 수 있다. 구현 복잡성을 줄이기 위해 받아들인 위험이다.
- 프로필 사진 저장소와 인증 계정 삭제는 하나의 원자적 작업이 아니다. 중간 실패와
  응답 유실을 반복 실행으로 복구할 수 있는지 구현 검증이 필요하다.
- 이미 발급된 access token은 계정을 삭제해도 만료 전까지 서명 자체는 유효할 수
  있다. 삭제된 세션을 확인하지 않는 서버 기능이 생기면 탈퇴 뒤에도 잠시 호출될
  수 있다.
- Google Play용 웹 탈퇴 요청 경로를 미뤘으므로, 심사 준비에서 이 항목을 놓치면
  Android 앱 제출이나 업데이트가 거절될 수 있다.
