# 모바일 작업 진행 표시 명세

## 목표

모바일 앱의 버튼과 자동 실행 작업이 진행 중임을 같은 원칙으로 알린다. 작업의 뜻과 화면 배치를 유지하고, 무엇을 기다리는지 분명하게 연결하며, 빠른 작업에는 불필요한 깜빡임을 만들지 않는다.

## 확정한 범위

### React Native UI의 일반 버튼

- 앱 공통 컴포넌트의 공개 이름은 `Button`이다. 진행 상태만을 뜻하는 `PendingButton`이나 주요 작업만을 뜻하는 `CTAButton`으로 나누지 않는다.
- 앱 공통 `Button`은 HeroUI Native 버튼의 크기, 강조 단계, 누름 반응과 화면 모드를 유지한다.
- `isPending`은 일반 버튼이 가질 수 있는 상태다. 진행 중에는 원래 문구와 버튼 크기를 유지하고 작은 회전 진행 표시를 문구 앞에 둔다.
- 버튼에 작업 아이콘이 있으면 진행 중에는 그 아이콘 대신 회전 진행 표시를 보여 준다. 작업의 뜻을 담은 문구는 유지한다.
- 진행 중인 버튼은 같은 작업을 다시 실행하지 못한다. 화면 읽기 기능에는 버튼의 이름과 함께 진행 중이며 사용할 수 없는 상태를 전달한다.
- 버튼은 기본 너비를 강제하지 않는다. 전폭 버튼은 부모 배치나 해당 사용처의 스타일이 정한다.
- `className`, `style`, 크기와 강조 단계처럼 화면이 정해야 하는 기존 버튼 속성은 계속 사용할 수 있다.

### 자동 실행 작업

- 자동 실행 작업은 공통 버튼으로 표현하지 않는다. 처리하는 입력, 콘텐츠나 상태 영역이 진행 상태를 소유한다.
- 실제 작업과 상호작용 차단은 즉시 시작하지만 시각적인 진행 표시는 1초 뒤에 보여 준다.
- 작업이 1초 안에 끝나면 시각적인 진행 표시를 보여 주지 않는다. 1초가 지난 뒤 표시한 상태는 작업이 끝나면 바로 없앤다.
- 진행 상태는 기존 대상의 영역과 정렬을 유지한다. 새 줄을 추가해 화면 높이를 바꾸지 않는다.
- 상태 문구가 필요하면 `로딩 중` 같은 포괄적인 말 대신 실제 작업을 쓴다.

### 인증 코드 자동 확인

- 여섯 자리 인증 코드가 채워지면 지금처럼 바로 확인을 시작한다.
- 확인을 시작하면 코드 입력을 즉시 막아 같은 코드를 중복 확인하지 않는다.
- 1초 안에 확인이 끝나면 별도 진행 표시 없이 다음 상태로 이동한다.
- 1초를 넘기면 여섯 칸 입력 영역이 같은 크기와 위치에서 회전 진행 표시와 `코드를 확인하고 있어요` 문구로 바뀐다.
- 확인에 성공하면 별도 완료 문구 없이 다음 화면으로 이동한다.
- 확인에 실패하면 빈 여섯 칸 입력과 해결 방법을 담은 기존 오류 문구로 돌아간다.

### 렌더러별 표현

- Google, Apple과 이메일 로그인 선택은 기존 `LoginButton`의 브랜드 색상, 로고와 전폭 배치를 유지한다. 진행 중인 제공자 버튼은 로고 대신 회전 진행 표시를 보여 주고 원래 문구를 유지한다.
- 프로필 저장처럼 아이콘만 있는 `Stack.Toolbar.Button` 작업은 진행 중에 같은 툴바 자리의 시스템 진행 표시로 바뀐다.
- Settings의 로그아웃처럼 `@expo/ui` 행으로 표현한 작업은 해당 행이 진행 상태를 알린다. React Native UI의 앱 공통 `Button`으로 바꾸지 않는다.
- 채팅 전송 버튼은 기존 채팅 명세의 생성 중 비활성화 규칙을 유지하며 이번 공통 버튼으로 바꾸지 않는다.

### 중복 실행 차단

- 화면의 진행 상태는 누를 수 없음을 바로 표현한다.
- 작업을 실행하는 상태 계층도 같은 화면 프레임에 들어온 두 번 이상의 요청을 한 번으로 줄인다.
- 성공, 실패, 취소와 예외가 발생한 모든 경로에서 진행 상태를 끝낸다.

## 완료 조건

- React Native UI의 일반 텍스트 버튼이 앱 공통 `Button`을 사용하고 정상, 비활성화와 진행 중 상태에서 기존 크기와 문구를 유지한다.
- 앱 공통 `Button`은 배치에 따라 전폭 또는 내용 너비로 표시할 수 있다.
- 진행 중인 버튼과 자동 실행 작업을 빠르게 여러 번 실행해도 실제 요청은 한 번만 시작한다.
- 인증 코드 확인이 1초 안에 끝나면 진행 표시가 깜빡이지 않는다.
- 인증 코드 확인이 1초를 넘기면 새 줄 없이 입력 영역 자체에서 진행 상태를 보여 준다.
- 화면 읽기 기능이 일반 버튼의 진행 상태, 인증 코드 확인 상태와 렌더러별 작업 이름을 알 수 있다.
- Light, Dark와 글자 크기 확대 상태에서 버튼 문구, 진행 표시와 버튼 경계가 겹치거나 잘리지 않는다.
- iOS와 Android Development Build에서 인증 코드 받기, 코드 자동 확인, 온보딩 저장, 로그인 선택, 프로필 저장과 로그아웃을 확인한다.

## 가정

- 현재 작업은 완료량을 알 수 없는 짧은 서버 요청이므로 회전 진행 표시를 사용한다.
- 세부 크기, 간격과 색상은 각 렌더러의 기존 시맨틱 스타일을 따른다.
- 자동 실행 작업의 지연 표시 규칙은 인증 코드 확인에 먼저 적용한다. 두 번째 실제 사용처가 생기기 전에는 공통 훅을 만들지 않는다.

## 범위 밖

- 업로드와 다운로드의 정확한 완료량, 남은 시간과 취소 기능
- 전체 화면 첫 로딩, 목록 Skeleton과 당겨서 새로고침
- 기존 UI 렌더러 경계, 버튼 강조 단계와 인증 흐름 변경
- 네트워크 요청, TanStack Query와 Supabase API 구조 변경
- 채팅 생성 중지와 다시 시도 작업 추가

## 남은 위험

- 매우 느린 인증 확인은 회전 진행 표시만으로 남은 시간을 알려 주지 못한다. 실제 지연이 반복되면 재시도나 시간 초과 안내를 따로 정해야 한다.
- HeroUI Native와 `@expo/ui`를 올리면 공식 진행 상태 API가 생기거나 접근성 전달 방식이 바뀔 수 있다.
- 글자 크기를 크게 키우면 회전 진행 표시와 긴 버튼 문구가 한 줄 안에서 경쟁할 수 있으므로 실제 기기 확인이 필요하다.
