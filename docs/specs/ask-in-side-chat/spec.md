# Ask in side chat 명세

## 목표

AI 답변의 일부를 읽다가 원래 대화를 바꾸지 않고 그 구절만 더 물어볼 수 있게 한다. 선택한 구절과 그 답변까지의 부모 대화를 읽기 전용 문맥으로 이어받은 별도 Side chat을 열고, 부모 채팅이 살아 있는 동안 닫았다가 다시 연다.

이 명세는 [채팅 메시지 동작 명세](../chat-message-actions/spec.md)가 제외했던 "부분 선택을 메뉴에서 시작하는 텍스트 선택 항목" 가운데 `Ask in side chat` 하나만 새 범위로 되살린다. 기존 복사, 수정, 다시 받기, 중지, 다시 시도와 나머지 제외 범위는 그대로 유지한다.

승인한 화면은 [prototype.html](prototype.html)이다. 화면과 상태를 직접 눌러 볼 수 있으며, 이 문서와 어긋나면 이 문서를 따른다.

## 확정한 범위

### 시작점

- 완료된 부모 AI 답변의 본문 일부를 선택하면 시스템 텍스트 선택 메뉴에 `Ask in side chat`을 표시한다.
- `Ask in side chat`은 선택한 구절마다 새 Side chat의 임시 상태를 연다. 같은 부모 답변에서 다시 시작해도 기존 Side chat에 합치지 않는다.
- 첫 질문을 보내면 Side chat을 부모 답변에 연결하고 수 표시에 포함한다. 첫 질문을 보내기 전에 닫으면 임시 상태와 초안을 버리고 수 표시에 포함하지 않는다.
- 답변을 기다리거나 받는 동안에는 Side chat을 시작하지 않는다. 기존 답변 선택 제한과 메시지 동작 비활성화 조건을 그대로 따른다.
- 시스템이 제공하는 복사, 찾기와 번역 같은 선택 메뉴 항목은 그대로 둔다.

### 이어받는 문맥

- Side chat은 선택한 구절을 눈에 보이는 읽기 전용 출처로 보여 준다.
- Side chat은 부모 대화의 처음부터 출처가 된 AI 답변 전체까지를 읽기 전용 스냅샷으로 이어받는다.
- 스냅샷은 Side chat을 만든 순간의 내용으로 고정한다. 이후 Side chat에서 묻거나 답변을 다시 받아도 부모 대화와 스냅샷을 바꾸지 않는다.
- 부모 스냅샷은 Side chat의 메시지 목록에는 표시하지 않는다. Side chat에서 새로 주고받은 메시지만 대화 목록에 표시한다.
- AI에 요청할 때는 부모 스냅샷과 Side chat 메시지를 함께 문맥으로 보낸다. 서버에 지난 대화를 저장하거나 조회하지 않는다.

### Side chat 화면

- Side chat은 Expo Router Stack의 `pageSheet` presentation으로 연다.
- 첫 화면 제목은 `Side chat`이다. 부모 채팅으로 돌아가는 동작은 뒤로 가기가 아니라 닫기다.
- 닫기 버튼과 플랫폼의 시트 닫기 제스처는 Side chat 화면만 닫는다. 첫 질문을 보낸 Side chat 대화는 지우지 않으며, 첫 질문을 보내기 전의 임시 상태는 버린다.
- 화면이 열린 뒤 입력창이 포커스를 받고 키보드가 올라온다. 진입 시점과 움직임은 모바일 진입 키보드 결정을 따른다.
- 첫 질문을 보내기 전에는 선택한 출처와 입력창만 표시한다. 별도 빈 화면 안내, 추천 질문과 시작 카드는 두지 않는다.
- 첨부, 모델 고르기와 음성 입력은 추가하지 않는다.
- 네이티브 Stack이 시트 배경, 모서리, 전환과 닫기 제스처를 소유한다. 별도 BottomSheet 컴포넌트나 커스텀 시트 모양을 겹쳐 만들지 않는다.

### Side chat 안의 대화

- Side chat에서 새로 주고받은 메시지는 기존 채팅과 같은 표현, 스크롤, 키보드와 스트리밍 동작을 사용한다.
- Side chat의 사용자 메시지는 복사와 수정을 제공한다.
- 완료된 Side chat AI 답변은 답변 복사와 다시 받기를 제공한다.
- 답변 대기, 생성 중지, 실패 뒤 다시 시도와 최신 메시지 이동을 기존 채팅과 같이 제공한다.
- Side chat AI 답변 본문도 선택할 수 있지만, 선택 메뉴에 `Ask in side chat`을 넣지 않는다. Side chat 안에서 또 다른 Side chat을 만들 수 없다.
- 선택한 출처와 부모 스냅샷에는 메시지 수정, 답변 다시 받기와 그 밖의 부모 대화 동작을 붙이지 않는다.

### 닫기, 다시 열기와 수명

- 첫 질문을 보낸 Side chat은 부모 채팅 화면이 살아 있는 동안 메모리에만 보관한다.
- 첫 질문을 보낸 뒤에는 pageSheet를 닫아도 Side chat의 메시지, 작성 중인 초안, 전송 상태, 수정 대상과 수정 전 초안을 유지한다.
- pageSheet를 닫은 동안에도 진행 중인 답변 생성을 계속한다. 다시 열면 그동안 받은 내용과 현재 상태를 보여 준다.
- 첫 질문을 보낸 Side chat이 하나라도 있으면 부모 채팅의 입력창 위에 그 대화 전체의 Side chat 수를 `Side chat 1개`, `Side chat 2개`처럼 떠 있는 표시로 보여 준다. 최신 메시지 이동 버튼과 같은 자리에 쌓고 같은 표면을 쓴다.
- 수 표시는 개별 부모 답변이 아니라 부모 대화 하나를 센다. 어느 답변에서 시작했는지는 다시 열기 목록의 구절로 구분한다.
- 하나도 없으면 수 표시를 보여 주지 않는다.
- Side chat이 하나면 수 표시를 눌러 바로 다시 연다.
- Side chat이 여러 개면 수 표시를 눌러 다시 열기 목록을 열고, 고른 Side chat을 다시 연다. 각 항목은 선택한 구절과 그 Side chat에서 마지막으로 오간 말을 함께 보여 주고, 눌러서 이동한다는 것을 알린다.
- 부모 채팅에서 나가거나 로그아웃하거나 앱 프로세스가 끝나면 그 부모 대화의 모든 Side chat을 지운다. 다시 앱을 열었을 때 복구하지 않는다.
- 부모 답변을 다시 받거나 앞선 사용자 메시지를 수정해 출처 답변이 부모 대화에서 사라지면, 그 답변에서 만든 모든 Side chat도 지운다. 답변을 받는 중인 Side chat이 있으면 먼저 생성을 멈춘다.

### 서로 다른 Side chat

- 각 Side chat은 선택한 구절, 부모 스냅샷, 메시지, 초안, 전송 상태, 수정 대상과 수정 전 초안을 따로 가진다.
- 한 Side chat에서 메시지를 수정하거나 답변을 다시 받아도 같은 부모 답변에서 만든 다른 Side chat에는 영향을 주지 않는다.
- Side chat 수와 다시 열기 목록은 현재 부모 대화에 남아 있는 Side chat만 반영한다.

## 선택한 구성과 이유

- Side chat은 짧은 선택 메뉴가 아니라 키보드, 긴 메시지와 계속되는 대화를 가진 독립 흐름이다. 부분 높이와 높이 전환이 중심인 BottomSheet보다 전체 대화 공간과 route 수명을 제공하는 `pageSheet`가 맞다.
- 부모 대화를 그대로 표시하면 Side chat 메시지와 수정 가능한 범위가 섞인다. 전체 스냅샷은 AI 문맥으로만 두고 선택한 구절만 읽기 전용 출처로 보여 준다.
- 선택한 구절마다 별도 Side chat을 만들면 서로 다른 질문과 답변이 한 갈래에 섞이지 않는다.
- 수 표시를 답변 아래가 아니라 입력창 위에 띄우면 대화 어디를 읽고 있어도 돌아갈 길이 같은 자리에 있다. 답변 아래에 두면 출처 답변을 화면에서 찾아야 다시 열 수 있고, 그 답변이 대화 끝에 있을 때는 입력창에 얹힌 것처럼 보인다. 대신 답변 하나에 몇 개가 달렸는지는 화면에서 알 수 없고, 목록을 열어 구절로 구분한다.
- 다시 열기 목록의 한 항목이 구절과 마지막으로 오간 말을 함께 보여 주면, 비슷한 구절에서 시작한 Side chat도 지금 어디까지 갔는지로 갈린다.
- Side chat을 부모 채팅의 메모리 수명에 묶으면 DB 없이 다시 열 수 있고, 현재 채팅의 앱 재시작 뒤 복구하지 않는 계약도 유지한다.
- 출처 답변이 사라질 때 Side chat도 함께 지우면 새로운 부모 답변에 예전 문맥을 잘못 연결하거나 다시 들어갈 길이 없는 대화를 남기지 않는다.

## 화면 문구와 접근성 이름

| 이름 | 화면에 보이나 | 자리 |
| --- | --- | --- |
| `Ask in side chat` | 보인다 | 부모 AI 답변의 시스템 텍스트 선택 메뉴 |
| `Side chat` | 보인다 | pageSheet 제목 |
| `Side chat 1개` | 보인다 | 부모 채팅 입력창 위에 떠 있는 다시 열기 표시 |
| `Side chat 2개` 이상 | 보인다 | 부모 채팅 입력창 위에 떠 있는 다시 열기 표시 |
| `Side chat 1개 다시 열기` | 아니다 | Side chat이 하나인 수 표시의 접근성 이름 |
| `Side chat 2개 고르기` 이상 | 아니다 | Side chat이 여러 개인 수 표시의 접근성 이름 |
| `Side chat 닫기` | 아니다 | pageSheet 닫기 버튼의 접근성 이름 |

- Side chat 수는 실제 개수에 맞춰 숫자를 바꾼다.
- 수 표시는 접근성 역할을 버튼으로 알린다. 하나일 때는 `Side chat 1개 다시 열기`, 여러 개일 때는 실제 수를 넣은 `Side chat N개 고르기`를 접근성 이름으로 사용한다.
- 다시 열기 목록의 각 항목은 선택한 구절을 알아볼 수 있게 보여 주고, 접근성 이름에서 해당 구절과 `Side chat 열기` 동작을 함께 알린다. 마지막으로 오간 말은 눈으로 고를 때 돕는 보조 정보이므로 접근성 이름에 넣지 않는다.
- 기존 채팅의 메시지, 입력, 전송과 오류 접근성 이름을 Side chat에도 그대로 적용한다.
- 새 접근성 이름은 기존 채팅의 접근성 이름 목록에도 함께 등록한다.

## 제외할 범위

- Side chat 안에서 또 다른 Side chat 만들기
- Side chat과 부모 대화를 합치거나 Side chat 답변을 부모 대화로 보내기
- 부모 스냅샷의 메시지 수정, 답변 다시 받기와 메시지 동작
- Side chat 저장용 DB, Supabase 테이블, 지난 Side chat 조회 API와 기기 간 동기화
- AsyncStorage, SecureStore와 파일을 이용한 앱 재시작 뒤 복구
- 부모 채팅을 나간 뒤 Side chat을 찾는 전체 목록과 검색
- 첨부, 이미지, 음성 입력과 모델 고르기
- push 화면, `formSheet`, BottomSheet 컴포넌트와 커스텀 시트 구현
- 서버 경로, 인증, 모델 라우팅과 스트리밍 프로토콜 변경
- Expo Web 지원

## 완료 조건

1. 완료된 부모 AI 답변의 일부를 선택하면 시스템 선택 메뉴에 `Ask in side chat`이 보이고 기존 시스템 항목도 남아 있다.
2. `Ask in side chat`을 누르면 선택한 구절과 해당 답변까지의 부모 대화 스냅샷을 가진 새 `Side chat` pageSheet가 열린다.
3. Side chat에는 선택한 구절과 새로 주고받은 메시지만 보이고, 부모 메시지 목록과 부모 메시지 동작은 보이지 않는다.
4. 첫 질문을 보내기 전에는 별도 빈 화면 안내 없이 입력을 시작할 수 있고, 첨부, 모델과 음성 입력은 보이지 않는다. 이때 닫으면 임시 상태를 버리고 부모 답변에 Side chat 수 표시를 만들지 않는다.
5. Side chat의 메시지 전송, 스트리밍, 중지, 다시 시도, 복사, 수정, 답변 다시 받기, 최신 메시지 이동과 키보드 동작이 기존 채팅과 같다.
6. Side chat 답변의 일부를 선택해도 `Ask in side chat`은 보이지 않는다.
7. 첫 질문을 보낸 뒤 pageSheet를 닫아도 부모 대화는 바뀌지 않고, 진행 중인 답변은 계속되며, `Side chat 1개`를 눌러 같은 대화, 초안과 수정 상태를 다시 연다.
8. 같은 부모 답변에서 새 Side chat을 만들면 기존 것과 합치지 않고 수 표시가 늘어난다. 서로 다른 답변에서 만든 Side chat도 같은 수 표시에 함께 센다. 여러 개일 때 목록의 각 항목이 구절과 마지막으로 오간 말로 갈리고, 고른 Side chat을 정확히 연다.
9. 서로 다른 Side chat의 메시지 수정, 답변 다시 받기와 전송 상태가 서로 영향을 주지 않는다.
10. 출처 답변을 다시 받거나 앞선 메시지를 수정해 출처가 사라지면 그 답변에서 만든 Side chat, 대화와 진행 중인 요청이 함께 사라지고 수 표시가 그만큼 줄어든다. 남은 Side chat이 없으면 수 표시도 사라진다.
11. 부모 채팅을 나갔다가 새 채팅을 열거나 앱을 다시 시작하면 이전 Side chat과 수 표시가 남아 있지 않다.
12. iOS에서는 시스템 `pageSheet`로 보이고 Android에서는 플랫폼의 modal 표현을 사용하며, 양쪽에서 닫기와 다시 열기 흐름이 동작한다.

자동 테스트는 문맥 스냅샷 경계, Side chat 분리, 첫 전송 전 임시 상태 정리, 수 계산, 하나와 여러 개의 다시 열기, 화면을 닫은 동안의 초안·전송·수정 상태 유지, 부모 메시지 제거에 따른 정리, 부모 채팅 종료에 따른 메모리 해제를 확인한다. 실제 시스템 텍스트 선택 메뉴, 네이티브 pageSheet, 닫기 제스처, 키보드와 백그라운드 스트리밍은 iOS 및 Android Development Build에서 확인한다.

## 가정

- 첫 질문을 보내기 전에 Side chat을 닫으면 대화로 세지 않고 임시 상태를 버린다. 보내지 않은 빈 Side chat이 수 표시에 쌓이지 않게 하는 기본값이다.
- 여러 Side chat의 다시 열기 목록은 최근에 만든 순서로 보여 준다. 한 항목은 선택한 구절과 마지막으로 오간 말을 각각 한 줄로 줄여 보여 준다. 목록의 정확한 폭, 항목 높이와 말줄임 값은 실제 기기에서 정한다.
- 마지막으로 오간 말은 Markdown 기호 없이 한 줄 평문으로 보여 준다. 렌더러가 그 평문을 주면 그것을 쓴다. 구현 시점의 `react-native-enriched-markdown@1.0.1`과 `remend@1.3.0`은 그리는 텍스트를 밖으로 내주지 않아, 앱이 짝을 이룬 Markdown 기호만 걷어 내 한 줄로 만든다. 짝이 아닌 낱개 기호는 그대로 두어 `owner_id`나 `a => b` 같은 말이 상하지 않게 한다. 렌더러가 평문을 제공하면 그때 그쪽으로 옮긴다.
- 선택한 구절을 보여 주는 출처의 카드나 칩 모양은 기존 시맨틱 토큰을 따른다. 읽기 전용이라는 동작과 보이는 원문만 계약으로 고정한다.
- Side chat을 닫아 둔 동안에는 수 표시 외에 별도 생성 진행 표시를 추가하지 않는다. 어느 Side chat에 새 답변이 왔는지 알리는 표시도 두지 않는다.

## 남은 위험

- 부모 스냅샷 전체와 Side chat 메시지를 요청마다 함께 보내므로 매우 긴 대화는 모델 문맥 한도, 요청 크기와 비용에 닿을 수 있다. 첫 버전은 요약하거나 일부를 자르지 않는다.
- 여러 Side chat의 스트림을 동시에 계속 받으면 메모리와 네트워크 사용량이 늘어난다. 부모 채팅을 나가거나 출처를 지울 때 모두 멈추고 정리해야 한다.
- 앱이 백그라운드에 있어도 운영체제가 프로세스를 종료하면 Side chat을 복구할 수 없다. DB에 저장하지 않기로 한 범위의 의도한 한계다.
- iOS의 `pageSheet`와 Android의 modal 표현은 크기와 전환이 다르다. 두 플랫폼에서 같은 모양을 흉내 내지 않고 같은 동작만 맞춘다.
- 여러 Side chat을 고르는 목록의 긴 선택 문장과 큰 글자 설정은 실제 기기에서 읽기와 선택 가능성을 확인해야 한다.
- 수 표시가 대화 단위라 한 답변에 Side chat이 몇 개 달렸는지는 화면에서 알 수 없다. 한 대화에서 Side chat을 많이 만들면 목록이 길어지고 구절만으로는 찾기 어려워질 수 있다.
- 시스템 텍스트 선택 메뉴는 기본 항목과 `Ask in side chat`을 합쳐 390pt 기기 폭의 대부분을 쓴다. 큰 글자 설정이나 다른 언어에서 항목이 잘리거나 넘침 메뉴로 밀리는지 실제 기기에서 확인해야 한다.
