# 최소 채팅 화면 명세

## 목표

채팅 화면을 처음부터 다시 만든다. 이번 범위에는 사용자가 일반 텍스트를 입력해 보내고, 서버가 보내는 일반 텍스트 답변을 대화 순서대로 읽는 데 필요한 요소만 남긴다. 기존 채팅 화면에 있던 문서 표시와 부가 작업은 모두 제거한다.

## 확정한 범위

### 화면 진입과 수명

- Home 왼쪽 위의 `+` 버튼은 루트 스택에 `/chat` 화면을 연다.
- 채팅 화면에는 네이티브 뒤로 가기와 `대화` 제목만 둔다. 하단 탭바는 보이지 않는다.
- 메시지와 작성 중인 초안은 채팅 화면이 살아 있는 동안에만 유지한다.
- 뒤로 가면 현재 대화와 초안을 확인 없이 버린다. 다시 들어오면 빈 대화로 시작한다.

### 메시지

- 메시지 목록은 사용자 메시지와 AI 답변을 시간 순서대로 보여준다.
- 사용자 메시지와 AI 답변은 역할을 구분할 수 있는 가장 단순한 배치로 표시한다.
- 본문은 일반 텍스트로만 표시한다. Markdown 문법을 해석하지 않는다.
- 서버가 스트리밍하는 AI 답변은 받은 텍스트부터 같은 메시지에 이어서 표시한다.
- 대화가 비어 있을 때는 별도 안내, 추천 질문, 시작 카드를 표시하지 않는다.
- 메시지 목록은 세로로 스크롤할 수 있고 새 답변을 받을 때 최신 메시지를 보여준다.

### 입력과 전송

- 화면 아래에는 여러 줄 일반 텍스트 입력창과 전송 버튼만 둔다.
- 입력창은 키보드와 Safe Area에 가리지 않는다.
- 공백뿐인 내용은 전송하지 않는다.
- 전송하면 입력창을 비우고 사용자 메시지를 즉시 목록에 표시한다.
- 같은 전송을 빠르게 여러 번 눌러도 요청은 한 번만 보낸다.
- 응답을 기다리거나 스트리밍하는 동안 전송 버튼은 비활성화한다.
- 요청이 실패하면 내부 정보가 없는 짧은 오류 문구만 표시한다. 별도 다시 시도 버튼은 두지 않고 사용자가 새 메시지를 보낼 수 있게 한다.

### 유지할 연결

- 기존 `POST /ai/chat`, Supabase Auth 인증과 AI SDK UI message stream을 그대로 사용한다.
- 서버는 텍스트 답변만 보낸다는 현재 계약을 유지한다.
- 대화 저장, 서버 초기화 요청과 지난 대화 조회는 추가하지 않는다.

## 제거할 범위

- Markdown 문단, 제목, 강조, 인용, 목록과 표 표시
- 링크 열기, 인라인 코드, 코드 블록, 문법 강조와 코드 복사
- 파일, 출처 URL, 출처 문서, 도구, 사용자 정의 데이터와 알 수 없는 part 표시
- 도구별 렌더러 등록점과 도구 실행 상태 표시
- 메시지 복사, 편집 후 다시 보내기와 다시 생성
- 생성 중지, 다시 시도 버튼과 편집 상태
- 최신 메시지 이동 버튼과 복잡한 읽기 위치 보존
- 이미지, 파일과 음성 입력
- 추천 질문, 시작 카드와 별도 빈 화면 안내
- 대화 저장, 지난 대화 목록과 대화 복구

## 완료 조건

- Home의 `+` 버튼으로 빈 채팅 화면을 열고 네이티브 뒤로 가기로 Home에 돌아온다.
- iOS와 Android에서 일반 텍스트를 입력하고 한 번만 전송할 수 있다.
- 보낸 사용자 메시지가 즉시 나타나고, 스트리밍되는 AI 일반 텍스트 답변이 같은 대화에 순서대로 나타난다.
- 키보드가 입력창과 전송 버튼을 가리지 않는다.
- 공백 전송과 생성 중 중복 전송이 일어나지 않는다.
- 화면을 나갔다가 다시 열면 이전 메시지와 초안이 남지 않는다.
- Markdown, 파일, 출처, 도구와 메시지 작업 UI가 화면과 접근성 트리에 남아 있지 않는다.
- 모바일 검사, 타입 검사와 테스트가 통과하고 iOS 및 Android Development Build에서 핵심 흐름을 확인한다.

## 가정

- 세부 간격, 색상과 글자 크기는 기존 시맨틱 토큰과 플랫폼 설정을 따른다.
- 일반 텍스트에 Markdown 문법이 들어오면 기호를 포함한 원문 그대로 표시한다.
- 오류 문구는 실패를 알리는 최소 안전장치로 남기지만 오류 전용 작업은 제공하지 않는다.
- Home의 Lorem ipsum 본문, 왼쪽 `+` 버튼과 오른쪽 프로필 버튼은 이번 변경 대상이 아니다.

## 범위 밖

- 서버 경로, 인증, 모델 라우팅과 스트리밍 프로토콜 변경
- Home과 다른 앱 화면의 재설계
- 채팅 화면의 최종 시각 디자인
- 대화 저장, 검색, 이름 변경과 기기 간 동기화
- 멀티모달 입력, RAG, 검색, 도구 호출과 출처 표시
- 모델 선택, system prompt와 장기 기억
- Expo Web 지원

## 남은 위험

- 생성 중지 기능이 없으므로 긴 응답은 요청이 끝나거나 실패할 때까지 기다려야 한다.
- 다시 시도 기능이 없으므로 실패한 요청은 사용자가 새 메시지로 다시 보내야 한다.
- Markdown을 해석하지 않으므로 모델 답변에 문법 기호가 그대로 보일 수 있다.
- 긴 대화용 가상 목록과 읽기 위치 보존을 제거하면 메시지가 매우 많을 때 성능을 다시 다뤄야 한다.

## 구현 결과

- `ChatPanel`은 일반 텍스트 메시지 목록, 여러 줄 입력창과 전송 버튼만 표시한다.
- `useChatSession`은 초안, 메시지, 전송 상태와 짧은 오류만 화면에 제공한다. 공백 전송과 같은 화면 프레임의 중복 전송을 막는다.
- Markdown, 파일, 출처, 도구와 메시지 작업 렌더러를 삭제했다. 더는 쓰지 않는 목록, 클립보드, 브라우저와 Markdown 파서 패키지도 제거했다.
- `bun run check`, `bun run check-types`와 `bun run test`를 통과했다. 모바일 테스트 34개 묶음의 테스트 176개가 통과했다.
- 새 빌드 없이 기존 iOS와 Android Development Build에서 Home 진입, 키보드 위 입력창, 일반 텍스트 원문, 실제 메시지 전송과 AI 답변 표시를 확인했다.
