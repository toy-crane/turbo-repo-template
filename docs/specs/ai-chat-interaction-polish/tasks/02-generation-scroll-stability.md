# 02 — 생성 행과 읽던 위치를 지키는 스트리밍

## Outcome

사용자가 메시지를 보내면 그 아래의 한 AI 답변 행이 대기, 스트리밍, 중지, 오류와 재시도
상태를 이어서 보여 준다. 답변이 자라더라도 사용자가 읽던 위치를 앱이 함부로 바꾸지 않으며,
필요할 때만 최신 메시지로 돌아갈 수 있다.

## Blockers

- 01이 대화 영역과 측정된 입력창 하단 공간을 확정해야 한다. 답변 자리의 높이와 목록 끝
  판단은 이 최종 가시 영역을 기준으로 계산하므로 01의 네이티브 검토를 통과하기 전에는
  안정적으로 구현할 수 없다.

## Acceptance criteria

- [x] 사용자 메시지를 보낸 직후 같은 질문 아래에 임시 AI 답변 행을 만들고, 24×24 고정
  영역 안의 12 크기 점 하나로 응답 대기를 표시한다.
- [x] 대기 점은 약 1초 간격으로 transform과 opacity만 바꾸며, 모션 줄이기에서는 크기 변화
  없이 약한 opacity 변화만 사용한다. 점 자체는 화면 읽기 프로그램이 읽지 않는다.
- [x] 첫 텍스트가 오면 대기 점을 같은 행의 실제 답변으로 교체한다. 스트리밍 중에는 마지막
  텍스트 끝에 레이아웃 크기를 바꾸지 않는 accent 색 세로 표시를 둔다.
- [x] 생성 중에는 전송 버튼과 같은 44×44 자리에 중지 아이콘을 표시하고 입력창 높이를
  바꾸지 않는다.
- [x] 첫 텍스트 전에 중지하면 빈 임시 행을 제거하고 오류를 표시하지 않는다. 일부 텍스트
  뒤에 중지하면 받은 내용을 일반 AI 답변으로 남기고 복사와 마지막 답변 다시 생성 작업을
  표시한다.
- [x] 첫 텍스트 전 실패와 일부 텍스트 뒤 실패를 해당 질문 바로 뒤의 같은 AI 답변 행에
  표시한다. 일부 답변은 유지하되 오류 행에는 일반 복사와 다시 생성 대신 작은
  `다시 보내기` 작업만 표시한다.
- [x] `다시 보내기`는 같은 사용자 메시지로 새 답변을 요청하고 실패한 행을 새 답변으로
  교체한다. 오류 행은 재시도하거나 새 메시지를 보낼 때까지 남는다.
- [x] 생성 시작과 실패를 화면 읽기 프로그램에 각각 한 번만 알리고 스트리밍 조각마다
  반복하지 않는다.
- [x] 새 사용자 메시지는 네이티브 헤더 아래 16 간격에 자리한다. 그 아래부터 입력창 위까지
  남은 높이를 새 답변 자리로 확보하고, 짧게 완료된 답변도 그 자리를 바로 줄이지 않는다.
- [x] 답변이 확보한 자리보다 길어질 때 사용자가 대화 끝을 보고 있는 경우에만 새 내용을
  따라간다. 사용자가 위로 스크롤하면 자동 이동을 멈추고 읽던 위치를 유지한다.
- [x] 사용자가 다시 대화 끝에 도달하거나 최신 메시지 이동 버튼을 누르면 자동 따라가기를
  다시 시작한다.
- [x] 최신 메시지 이동 버튼은 대화 화면 정중앙과 입력창 표면 위 12 간격에 나타난다.
  키보드와 함께 움직이고, 누를 때 키보드를 닫지 않는다.
- [x] 최신 메시지 이동 버튼은 짧은 opacity와 scale 전환을 사용한다. 모션 줄이기에서는
  scale 전환을 생략한다.
- [x] 대기, 스트리밍, 오류, 복사 완료와 최신 메시지 이동 버튼의 표시 여부가 입력창 높이와
  목록 하단 inset을 바꾸지 않는다.
- [x] 스트리밍 중인 답변 행만 다시 렌더링하는 현재 성능 특성과 50ms 갱신 제한을 유지한다.

## Constraints

- 기존 `POST /ai/chat`, AI SDK UI message 프로토콜과 서버 API는 바꾸지 않는다. 화면 상태는
  현재 `useChat()` 상태와 메시지를 질문별 답변 행으로 연결해 표현한다.
- 생성 오류만 답변 행에 넣는다. 인증, 결제와 계정 오류의 새 화면은 만들지 않는다.
- 마지막 AI 답변만 다시 생성하는 현재 범위와 중지 뒤 부분 답변을 보존하는 동작을 유지한다.
- 답변 자리 확보를 위해 가짜 본문이나 화면에 읽히는 빈 메시지를 만들지 않는다.
