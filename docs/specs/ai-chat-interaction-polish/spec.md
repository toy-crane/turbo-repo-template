# AI 채팅 상호작용 다듬기 명세

## 목표

AI 채팅 화면에서 키보드, 메시지 생성, 편집과 스크롤이 하나의 안정된 대화 화면처럼
움직이게 한다. 상태가 바뀔 때 입력창과 대화가 서로 밀지 않으며, 사용자가 읽던 위치를
앱이 함부로 바꾸지 않는다. 메시지 작업 아이콘과 입력창 배경은 현재 모바일 화면의
둥글고 단단한 인상에 맞춘다.

이 명세는 [기존 AI 채팅 명세](../ai-chat/spec.md)를 바탕으로 하는 후속 변경이다. 두
명세가 충돌하면 메시지 편집 범위와 방식, 생성·오류 표시 위치, 빈 대화 배치, 키보드
여백과 스크롤 동작에는 이 명세를 적용한다. API, 인증, 대화 수명과 메시지 part 계약은
기존 명세를 그대로 따른다.

## 확인한 원인

| 문제 | 현재 원인 |
| --- | --- |
| 키보드와 입력창이 붙음 | 키보드가 열렸을 때 유지할 시각적 간격이 별도 값으로 정해져 있지 않고, Safe Area 보정과 입력창 이동이 한 묶음으로 처리된다. |
| 키보드가 열려도 빈 화면 문구가 제자리임 | 빈 대화는 메시지 목록 밖의 별도 화면이다. 키보드는 하단 입력창을 옮기지만 빈 화면이 가운데를 계산하는 영역은 같은 방식으로 줄지 않는다. |
| 첫 메시지 위쪽이 과하게 빔 | iOS의 투명 헤더가 콘텐츠를 덮는다는 가정으로 네이티브 헤더 높이를 목록 위쪽 inset에 다시 넣고, 목록 자체의 16 간격도 더한다. |
| 메시지 작업 아이콘이 가늘고 서로 멂 | 아이콘은 18 크기의 기본 굵기로 그리며 각 작업이 44 너비를 따로 차지한다. 복사 뒤에는 `복사됨` 문구가 추가되어 작업 줄의 폭도 바뀐다. |
| 생성 상태의 위치가 어색함 | `답변을 만드는 중`을 답변이 생길 자리 대신 측정 대상인 하단 입력창 묶음 안에 표시한다. |
| 대화 중 화면 이동이 큼 | 생성 상태와 오류가 생길 때마다 입력창 묶음의 높이와 목록 하단 inset이 함께 바뀐다. 새 답변이 자랄 자리도 미리 확보하지 않아 스트리밍되는 내용이 보이는 영역을 계속 밀어낸다. |
| 최신 메시지 이동 버튼이 오른쪽에 있음 | 버튼 위치를 화면 기준이 아니라 `right: 20`으로 고정한다. |
| 입력창 뒤에 흰 띠가 보임 | 실제 입력칸뿐 아니라 입력창 바깥 묶음 전체에도 화면 배경색을 칠한다. |
| 편집이 마지막 메시지에만 있고 입력창으로 이동함 | 대화 상태가 마지막 사용자 메시지만 찾고, 원문을 하단 입력창 초안으로 옮기는 구조다. |
| 오류가 대화 전체를 밀어 올림 | 오류 문구와 큰 다시 보내기 버튼도 높이를 측정하는 입력창 묶음 안에 들어 있다. |

## 확정한 동작

### 하나의 대화 영역

- 빈 대화와 메시지가 있는 대화는 항상 같은 대화 목록 영역을 사용한다.
- 빈 대화 문구는 별도 화면이 아니라 대화 목록의 빈 내용이다.
- 빈 대화 문구는 네이티브 헤더 아래부터 입력창 위까지 남은 영역의 가운데에 놓인다.
- 키보드가 열리면 같은 영역의 높이가 키보드 움직임에 맞춰 연속해서 줄어든다. 빈 대화
  문구는 줄어든 영역의 가운데로 자연스럽게 이동한다.
- 키보드 열림 여부에 따라 서로 다른 화면 구조를 렌더링하지 않는다. 키보드 진행도와
  대화 영역의 크기 변화가 같은 애니메이션을 사용한다.
- 모션 줄이기 설정에서는 위치 변화는 유지하되 별도의 장식 애니메이션을 줄인다.

### 키보드와 위아래 여백

- 키보드가 닫혀 있을 때 입력창은 기기의 하단 Safe Area를 지킨다. 홈 인디케이터가 있는
  기기에서도 입력과 전송 버튼이 그 영역을 침범하지 않는다.
- 키보드가 열려 있을 때 입력창과 키보드 위쪽 사이에는 8 레이아웃 단위의 간격을 둔다.
  iOS에서는 8pt, Android에서는 8dp에 해당한다.
- 키보드를 상호작용으로 내릴 때 입력창과 대화 영역도 키보드와 함께 움직인다. 키보드가
  완전히 열린 뒤 위치를 한 번에 바꾸지 않는다.
- 첫 메시지의 위쪽에는 네이티브 헤더 아래부터 16 레이아웃 단위만 둔다. iOS 헤더
  높이를 수동으로 한 번 더 더하지 않는다.

### 메시지 작업 아이콘과 복사

- React Native 대화 화면의 아이콘은 기존 공용 `Icon` 경계를 유지한다. iOS는 SF
  Symbols, Android는 같은 의미의 Material Symbols를 사용한다. 새 아이콘 폰트나 공통
  SVG 아이콘 세트를 추가하지 않는다.
- 메시지 작업 아이콘은 20 크기와 semibold에 해당하는 시각적 무게를 기준으로 한다.
  Android는 같은 무게로 보이는 공식 Material Symbol 형태를 고른다.
- 복사와 편집 작업은 36 크기의 시각 셀 안에서 추가 간격 없이 한 묶음으로 붙인다. 실제
  누르기 영역은 각 작업이 44 크기를 확보하되, 보이는 아이콘 간격을 다시 벌리지 않고
  이웃 작업이 잘못 실행되지 않아야 한다.
- 편집은 각 플랫폼의 부드럽고 둥근 연필 심벌을 사용한다. 연필은 36 크기의 옅은 원형
  표면 안에 둔다.
- 복사에 성공하면 같은 자리에 있던 복사 아이콘을 체크 아이콘으로 바꾼다. `복사됨`
  문구를 옆에 추가하지 않는다.
- 체크 아이콘은 2초 동안 유지한 뒤 복사 아이콘으로 돌아온다. 아이콘이 바뀌어도 작업
  줄의 너비와 메시지 높이는 바뀌지 않는다.
- 화면 읽기 프로그램에는 체크 상태를 `복사됨`으로 알린다. 색만으로 성공을 구분하지
  않는다.

### 사용자 메시지 인라인 편집

- 마지막 메시지뿐 아니라 모든 사용자 메시지에 편집 작업을 제공한다.
- 편집을 누르면 해당 사용자 말풍선이 같은 자리에서 여러 줄 입력으로 바뀌고 기존
  내용을 선택할 수 있는 상태로 연다.
- 인라인 입력 안에는 `취소`와 `보내기` 작업을 둔다. 하단 입력창을 편집 입력으로
  재사용하거나 하단에 `메시지를 고치는 중` 표시를 추가하지 않는다.
- 한 번에 사용자 메시지 하나만 편집할 수 있다. 편집 중에는 새 메시지 전송이나 다른
  메시지 편집을 동시에 시작할 수 없다.
- `취소`는 원문과 이후 대화를 그대로 되돌린다.
- `보내기`는 편집한 사용자 메시지와 그 뒤의 모든 메시지를 대화에서 제거하고, 고친
  메시지를 같은 대화의 새 마지막 메시지로 보낸다. 제거한 이후 대화는 별도 갈래나
  기록으로 보존하지 않는다.
- 공백뿐인 내용은 보낼 수 없다. 생성 중에는 편집을 시작하거나 확정할 수 없다.

### 생성, 부분 답변과 오류

사용자 메시지를 보낸 뒤 그 아래에 임시 AI 답변 행을 만든다. 이 한 행이 요청 상태에
따라 다음처럼 바뀐다.

| 상태 | 같은 AI 답변 행의 내용 |
| --- | --- |
| 응답 대기 | 진행 표시와 `답변을 만드는 중` |
| 첫 텍스트 수신 | 진행 표시를 없애고 실제 답변으로 교체 |
| 스트리밍 | 들어온 답변을 같은 행 안에서 늘림 |
| 첫 텍스트 전 실패 | 같은 자리에 오류와 작은 `다시 보내기` 작업 표시 |
| 일부 텍스트 뒤 실패 | 받은 답변을 남기고 같은 행에 오류와 `다시 보내기` 작업 표시 |
| 사용자 중지 | 받은 답변이 있으면 남기고 오류는 표시하지 않음 |

- 생성 상태와 생성 오류는 하단 입력창 묶음 안에 표시하지 않는다.
- 오류는 어느 질문의 답변이 실패했는지 알 수 있도록 해당 사용자 메시지 바로 뒤의 AI
  답변 행에 남긴다.
- 오류 문구는 기존 해결 방법인 `잠시 뒤에 다시 보내 주세요.`를 유지하고, 큰 전체 너비
  버튼 대신 같은 행의 작은 `다시 보내기` 작업을 사용한다.
- 다시 보내면 같은 사용자 메시지로 답변을 새로 요청한다. 실패한 부분 답변은 재시도를
  누르기 전까지 읽을 수 있으며, 재시도를 시작하면 새 답변으로 교체한다.
- 오류와 다시 보내기 작업은 재시도하거나 새 메시지로 대화를 이어 갈 때까지 남긴다.
- 계정, 인증과 결제처럼 특정 답변에 속하지 않는 오류는 이 행에 넣지 않는다. 이 명세는
  AI 답변 생성 실패만 다룬다.

### 전송 뒤 배치와 스트리밍 스크롤

- 사용자 메시지를 보내면 새 사용자 메시지의 위쪽을 네이티브 헤더 아래 16 간격에
  맞춘다. 앞선 대화는 위로 스크롤되어 남아 있다.
- 새 사용자 메시지 아래부터 입력창 위까지의 남은 높이를 새 답변 자리로 확보한다.
- 답변이 확보한 자리 안에서 자라는 동안 새 사용자 메시지는 제자리를 유지한다.
- 답변이 확보한 자리보다 길어지면 사용자가 대화 끝을 보고 있을 때만 새 내용을 따라
  아래로 이동한다.
- 사용자가 위로 스크롤하면 자동 따라가기를 바로 멈춘다. 이후 스트리밍 조각이나
  Markdown 높이 변화가 사용자가 읽는 위치를 대화 끝으로 끌고 가지 않는다.
- 사용자가 다시 대화 끝까지 내리거나 최신 메시지 이동 버튼을 누르면 자동 따라가기를
  다시 시작한다.
- 생성 상태, 오류, 복사 완료와 최신 메시지 이동 버튼의 표시 여부는 입력창 높이 또는
  대화 목록의 하단 여백을 바꾸지 않는다.

### 최신 메시지 이동 버튼

- 사용자가 대화 끝에서 벗어났을 때만 버튼을 표시한다.
- 버튼의 가로 위치는 입력칸이나 전송 버튼이 아니라 대화 화면 전체 너비의 정중앙을
  기준으로 한다.
- 버튼은 입력창 표면 위 12 간격에 떠 있고, 키보드가 움직일 때 입력창과 함께 움직인다.
- 버튼을 누르면 키보드를 닫지 않고 최신 메시지까지 이동한다.
- 나타나고 사라질 때 짧은 투명도와 크기 전환을 사용한다. 모션 줄이기 설정에서는 크기
  전환을 생략한다.
- 버튼 표시 여부 때문에 대화 하단 여백을 새로 늘리거나 줄이지 않는다.

### 투명한 입력창 영역과 대화 하단 보호

- 입력창 바깥 묶음은 투명하게 한다. 실제 입력칸과 전송·중지 버튼은 기존 시맨틱 표면색을
  유지한다.
- 투명하게 만드는 것은 배경색뿐이다. 대화 목록은 측정된 입력창 높이와 Safe Area를
  계속 하단 공간으로 확보한다.
- 대화 끝에 도달했을 때 마지막 메시지의 작업 영역과 입력칸 표면 사이에는 16 간격이
  보여야 한다.
- 입력 내용과 글자 크기 때문에 입력창 높이가 달라져도 목록 하단 공간을 같은 프레임에
  맞춘다. 마지막 답변이 입력칸 뒤에 멈추거나 입력칸을 덮지 않는다.
- 생성 상태와 오류를 대화 목록으로 옮긴 뒤에는 일반 전송 상태 변화만으로 입력창 묶음의
  높이가 바뀌지 않는다.

## 접근성과 화면 적응

- 복사, 편집, 취소, 편집 후 보내기, 다시 보내기, 생성 중지와 최신 메시지 이동에
  VoiceOver와 TalkBack이 읽을 수 있는 이름과 역할을 둔다.
- 생성 시작과 실패는 한 번만 알린다. 스트리밍 조각마다 화면 읽기 프로그램 알림을
  반복하지 않는다.
- 인라인 편집을 열면 포커스를 해당 입력으로 옮기고, 취소하거나 보낸 뒤에는 맥락을 잃지
  않는 위치로 돌려보낸다.
- 글자 크기를 키워 입력창과 인라인 편집기의 높이가 늘어나도 마지막 메시지와 작업이
  가려지지 않는다.
- 밝은 화면, 어두운 화면과 고대비 설정에서 투명한 입력창 바깥과 실제 입력칸의 경계를
  구분할 수 있어야 한다.

## 완료 조건

- iOS와 Android에서 키보드가 닫히면 하단 Safe Area를 지키고, 열리면 키보드와 입력창
  사이에 8 간격이 보인다.
- 빈 대화 문구는 키보드가 열리고 닫히는 동안 남은 대화 영역의 가운데를 자연스럽게
  따라간다.
- 첫 메시지는 두 플랫폼 모두 네이티브 헤더 아래 16 간격에서 시작하며 iOS에만 큰 추가
  여백이 생기지 않는다.
- 메시지 작업 아이콘은 플랫폼 심벌을 유지하면서 20 크기의 더 단단한 무게로 보이고,
  복사와 편집이 한 묶음으로 가깝게 놓인다.
- 복사에 성공하면 레이아웃 변화 없이 2초 동안 체크 아이콘과 접근성 상태가 나타난다.
- 모든 사용자 메시지를 그 자리에서 편집할 수 있다. 과거 메시지를 고쳐 보내면 그
  메시지부터 이후 대화를 잘라 내고 새 답변을 받는다.
- 사용자 메시지를 보내면 그 메시지가 화면 위쪽 16 간격에 자리하고, 답변이 남은 영역을
  채우는 동안 위치가 움직이지 않는다.
- 사용자가 대화 끝을 보고 있을 때만 긴 스트리밍 답변을 따라가고, 위로 스크롤하면 자동
  이동이 멈춘다.
- 생성 상태와 생성 오류는 해당 답변 행에 나타나며 입력창 높이와 대화 하단 inset을
  바꾸지 않는다.
- 오류 행의 `다시 보내기`로 같은 사용자 메시지를 다시 요청할 수 있다.
- 최신 메시지 이동 버튼은 화면 정중앙과 입력창 위 12 간격에 나타나며 키보드를 닫지
  않고 대화 끝으로 이동한다.
- 입력창 바깥은 투명하지만 마지막 메시지와 입력칸 사이의 16 간격은 유지된다.
- 긴 답변, 여러 줄 입력, Dynamic Type, 스트리밍 Markdown과 키보드 상호작용 닫기를
  조합해도 마지막 내용이 입력창에 가리거나 화면이 크게 튀지 않는다.
- 관련 상태와 화면 테스트가 통과하고, 각 플랫폼의 한 `agent-device` 세션 안에서 전송,
  인라인 편집, 실패 재시도, 자동 따라가기 중단과 키보드 동작을 확인한다.

## 가정

- 간격 값은 React Native의 밀도 독립 레이아웃 단위를 사용한다.
- 기존 `react-native-keyboard-controller`와 LegendList 연결이 키보드 진행도, 입력창 높이
  측정과 목록 위치 보존을 계속 맡는다.
- 마지막 AI 답변만 제공하는 `다시 생성` 범위와 생성 중지 뒤 부분 답변을 보존하는 동작은
  바꾸지 않는다.
- 메시지 편집으로 제거한 이후 대화는 서버와 기기에 저장하지 않으므로 복구할 수 없다.
- 아이콘의 세부 선 모양은 플랫폼 사이에서 달라도 의미, 시각적 무게와 접근성 이름은
  같게 유지한다.

## 이번 범위에서 제외할 기능

- 대화 갈래 저장, 편집 전 대화 복구와 버전 탐색
- 대화 영구 저장, 지난 대화 목록과 기기 간 동기화
- 과거 AI 답변의 다시 생성 범위 확대
- 생성 오류가 아닌 인증, 결제와 계정 오류의 새 화면
- 아이콘 라이브러리 교체와 프로젝트 전역 아이콘 디자인 개편
- 파일, 음성, 이미지 입력과 도구 실행 UI 변경
- 서버 API, 모델, system prompt와 스트리밍 프로토콜 변경

## 남은 위험

- 스트리밍 Markdown이 표, 코드 블록이나 이미 읽은 문단의 높이를 크게 바꾸면 목록의 위치
  보존과 대화 끝 추적이 동시에 흔들릴 수 있다. 실제 기기의 긴 혼합 답변으로 확인해야
  한다.
- 새 사용자 메시지를 화면 위에 고정하고 답변 자리를 확보하는 동작은 짧은 화면, 큰 글자와
  매우 긴 사용자 메시지에서 확보할 수 있는 높이가 작다. 이때도 편집과 중지 작업이
  가려지지 않는지 확인해야 한다.
- iOS의 상호작용 키보드 닫기와 Android의 드래그 닫기는 진행 이벤트가 다르다. 같은 간격과
  읽던 위치가 유지되는지 두 플랫폼의 Development Build에서 각각 확인해야 한다.
- 누르기 영역을 유지하면서 보이는 아이콘 간격을 줄이면 두 작업의 확장 영역이 가까워진다.
  아이콘 사이와 가장자리 탭이 이웃 작업을 실행하지 않는지 기기에서 확인해야 한다.
- 과거 메시지 편집은 여러 메시지 ID와 스트리밍 상태를 함께 잘라 낸다. 편집 취소, 편집
  전송 실패와 연속 편집에서 잘못된 대화가 남지 않도록 상태 테스트가 필요하다.
