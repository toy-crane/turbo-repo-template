# 디자인 시스템 생성 스킬 명세

## 목표

`create-design-system` 스킬은 참고 이미지나 URL에서 사용자가 원하는 시각적 특징을
읽고, 현재 프로젝트에 맞는 디자인 시스템 후보를 만든다. 후보는 독립 실행형 HTML에서
비교하며, 사용자가 명시적으로 승인한 뒤에만 프로젝트의 공식 테마 원본에 적용한다.

첫 버전은 Expo, HeroUI Native와 Uniwind를 사용하는 이 템플릿과 파생 앱을 지원한다.
새 컴포넌트 라이브러리를 만드는 것이 아니라 HeroUI Native가 제공하는 시맨틱 역할 안에서
색상, 모서리, 입력 요소 모서리, 테두리, 그림자와 정보 밀도를 정한다.

승인한 미리보기 구조와 두 예시는 [prototype.html](prototype.html)에 있다.

## 적용할 결정

- [모바일 색상 시맨틱](../../decisions/mobile-color-semantics.md)
- [모바일 타이포그래피](../../decisions/mobile-typography.md)
- [모바일 UI 렌더러 경계](../../decisions/mobile-ui-renderer-boundaries.md)
- [모바일 아이콘 렌더링](../../decisions/mobile-icon-rendering.md)
- [모바일 테스트와 런타임 검증](../../decisions/mobile-testing-and-verification.md)

프로젝트에 같은 주제의 결정이 더 있으면 해당 결정이 스킬의 일반 규칙보다 우선한다.

## 입력

기본 입력은 다음 두 가지다.

1. 참고 이미지 또는 참고 URL
2. 참고 자료에서 가져오고 싶은 특징을 적은 한 문장

예시는 다음과 같다.

- `이케아처럼 강한 색 대비와 단순한 구성을 원해`
- `이 화면의 따뜻한 주황색과 편안한 밀도만 가져와`

참고 자료는 스타일 근거일 뿐 편집 대상이 아니다. 스킬은 참고 화면의 문구, 사진, 로고,
내비게이션과 제품 구조를 복제하지 않는다.

사용자가 글로만 요청하면 먼저 현재 프로젝트에서 사용할 수 있는 방향 두세 개를 짧은
이름과 한 문장으로 제안한다. 사용자가 방향을 고르면 HTML 미리보기를 만든다. 참고 자료와
요청이 분명하면 후보 하나를 기본으로 만들며, 사용자가 여러 방향을 요청하면 최대 세 개를
같은 HTML에 넣는다.

## 프로젝트 확인

스킬은 후보를 만들기 전에 다음 내용을 확인한다.

- 설치된 Expo, HeroUI Native, Uniwind와 React Native 버전
- `global.css`와 HeroUI Native가 제공하는 현재 시맨틱 변수
- Light와 Dark에 정의된 변수 집합
- 테마 값을 읽는 공통 연결 지점
- 시스템 폰트와 시맨틱 텍스트 역할
- 원시 색상값, 별도 팔레트와 컴포넌트별 예외

HeroUI Native와 Uniwind의 현재 공식 문서를 확인하고 설치된 버전에서 지원하지 않는 변수나
API를 가정하지 않는다.

## 생성할 디자인 시스템

### 시맨틱 토큰

- 현재 HeroUI Native 버전이 제공하는 시맨틱 변수 이름과 의미를 유지한다.
- Light와 Dark는 같은 변수 집합을 가진다.
- 배경과 전경 쌍, 표면과 전경 쌍, 강조색과 전경 쌍을 함께 정한다.
- 입력, 포커스, 기본 상태, 성공, 경고와 오류의 의미를 서로 바꾸지 않는다.
- 새 시맨틱 역할은 기존 역할로 제품 의미를 표현할 수 없을 때만 제안한다. 사용자의 승인
  없이 추가하지 않는다.
- 기본 팔레트가 필요하면 `global.css` 안의 구현 세부사항으로 두며 컴포넌트가 원시
  색상값을 직접 사용하게 하지 않는다.

### 형태와 밀도

후보마다 다음 값을 하나의 관계로 정한다.

- 전체 콘텐츠 표면의 모서리
- 입력 요소 모서리
- 테두리와 입력 요소 테두리 두께
- 표면, 입력 요소와 오버레이 그림자
- 정보 밀도와 기본 간격
- 제목, 본문과 보조 문구의 시맨틱 강조

시스템 폰트를 유지한다. 브랜드 폰트나 임의의 글꼴 선택기를 만들지 않는다. 특정 형태를
표현하기 위해 화면 구조, 내비게이션, 제품 동작과 컴포넌트 종류를 바꾸지 않는다.

### 내부 제약

프로젝트 결정에 맞지 않는 특징은 후보를 만드는 과정에서 제외하거나 약하게 바꾼다. 이
판단은 스킬의 내부 생성 규칙이며 리뷰 화면에 설명하지 않는다. 사용자는 결과가 이
프로젝트에 어울리는지만 판단한다.

## HTML 미리보기

스킬의 리뷰 결과물은 PNG나 앱 안의 임시 라우트가 아니라 독립 실행형
`preview.html`이다.

- HTML, CSS와 JavaScript를 한 파일에 넣는다.
- 외부 폰트, 프레임워크, CDN, 이미지 생성 결과와 네트워크 요청에 의존하지 않는다.
- `build-prototype`의 화면, 상태, viewport 조작부나 템플릿을 사용하지 않는다.
- 후보 값과 비교용 가짜 데이터만 임시 HTML에 둔다.
- 후보 이름, 화면 표현 값과 Light 및 Dark 토큰은 `PREVIEW_DATA` 한 곳에 둔다.
  후보 선택기와 내보낼 CSS는 이 데이터에서 만든다.
- HTML을 보여 주기 전에 전용 검사 도구로 필수 화면 값, Light 및 Dark 변수 집합과 현재
  HeroUI Native 시맨틱 변수 누락을 확인한다.
- 승인 전에는 `global.css`, 앱 라우트, Metro 설정과 제품 컴포넌트를 바꾸지 않는다.

### 상단 영역

- 현재 후보 이름
- 후보 선택기
- `Overview`, `Components`, `Patterns` 탭
- `Export` 버튼

후보가 하나면 후보 선택기를 숨길 수 있다. 후보가 여러 개면 같은 HTML에서 바로
전환한다.

### Overview

`Overview`는 분석 보고서나 token 표가 아니라 디자인 시스템의 전체 인상을 보여 주는
시각 견본이다.

- 대표 제목
- 핵심 색상 견본
- Display, Heading, Body와 Caption 위계
- 주요 및 보조 행동
- 검색 입력
- 선택 chip
- 카드
- 목록
- 성공, 경고와 오류
- Light와 Dark 표면 견본

### Components

`Components`는 같은 문구와 구조로 다음 상태를 보여 준다.

- 주요, 보조와 비활성 버튼
- 기본 입력과 포커스
- 선택 chip
- 켜짐과 꺼짐 선택 상태
- 성공, 경고와 오류 피드백

### Patterns

`Patterns`는 특정 제품 화면 대신 여러 앱에서 반복되는 조합을 보여 준다.

- 검색과 필터
- 콘텐츠 목록
- 입력과 저장 행동

Home, Settings나 특정 제품 도메인을 기본 미리보기 화면으로 고정하지 않는다.

### Export

`Export`는 별도 서랍에서 다음 값을 CSS로 보여 준다.

- Light와 Dark의 전체 시맨틱 변수
- 모서리, 입력 요소 모서리와 테두리 두께
- 표면, 입력 요소와 오버레이 그림자
- 후보가 추가한 승인 전 기본 팔레트

HTML 본문에는 다음 내용을 보여 주지 않는다.

- 참고 이미지나 URL
- 가져온 특징과 제외한 특징
- 후보를 만든 이유
- 플랫폼 UI, 렌더러 경계와 소유권
- 구현 방법과 적용 계획

## 검토와 수정

- 후보는 같은 내용, 컴포넌트, 배치와 상태를 사용한다. 디자인 시스템 값만 바꾼다.
- 사용자는 `노란색을 줄여줘`, `모서리를 더 각지게 해줘`처럼 자연어로 수정할 수 있다.
- 스킬은 선택한 후보만 고치고 같은 HTML을 다시 만든다.
- 후보 선택은 수정할 방향을 고른 것이며 프로젝트 적용 승인이 아니다.
- 사용자가 적용을 명시적으로 승인하기 전까지 HTML과 후보 데이터는 임시 결과다.

## 승인 뒤 적용

- 승인한 Light와 Dark 값을 HeroUI Native와 Uniwind가 읽는 공식 `global.css`에 반영한다.
- 이미 시맨틱 클래스를 사용하는 컴포넌트는 수정하지 않는다.
- 하드코딩된 값이나 끊어진 연결이 승인한 값을 막을 때만 해당 예외를 고친다.
- 같은 예외가 반복되면 화면마다 값을 넣지 않고 기존 공통 연결 지점에서 해결한다.
- 후보 선택기, 임시 HTML, 후보용 앱 라우트와 임시 테마 등록은 제품에 남기지 않는다.
- 테마와 관계없는 화면 구조, 문구, 기능과 내비게이션은 함께 바꾸지 않는다.

## 검증

- Light와 Dark가 같은 시맨틱 변수 집합을 정의하는지 확인한다.
- 배경과 전경, 강조색과 전경, 상태 색상의 대비를 확인한다.
- 기본, 눌림, 선택, 포커스, 비활성, 로딩, 성공, 경고와 오류 상태를 확인한다.
- iOS와 Android에서 시스템 글자 크기, 고대비와 모션 줄이기 설정을 확인한다.
- 대표 제품 화면을 표본으로 확인해 전역 값이 읽기와 상태 구분을 해치지 않는지 확인한다.
- 프로젝트의 정적 검사, 타입 검사와 관련 테스트를 통과한다.

## 완료 조건

- 참고 이미지 또는 URL과 한 문장으로 디자인 시스템 후보를 만든다.
- 글만 입력하면 두세 방향을 먼저 제안하고 선택한 방향으로 진행한다.
- 후보는 현재 HeroUI Native의 시맨틱 역할과 같은 Light 및 Dark 변수 집합을 사용한다.
- 독립 실행형 HTML 하나에서 후보와 세 탭을 전환하고 CSS를 확인할 수 있다.
- 리뷰 HTML에는 결과물만 보이며 생성 근거와 내부 제약을 노출하지 않는다.
- 사용자는 자연어로 선택한 후보를 반복해서 다듬을 수 있다.
- 명시적 승인 전에는 공식 테마 원본과 앱 코드를 바꾸지 않는다.
- 승인 뒤에는 공식 테마 원본과 필요한 공통 연결만 수정하고 임시 결과를 제거한다.

## 가정

- 대상 프로젝트는 Expo, HeroUI Native와 Uniwind를 사용한다.
- 대상 프로젝트가 HeroUI Native의 시맨틱 변수 문법을 공식 색상 이름으로 사용한다.
- 사용자는 최종 디자인 시스템을 시각적으로 판단한다.
- HTML 미리보기는 검토용 임시 결과이며 제품 기능이 아니다.

## 이번 범위에서 제외할 기능

- Expo, HeroUI Native와 Uniwind 이외의 기술 스택
- 새 컴포넌트 라이브러리나 새 시맨틱 토큰 분류 체계
- 참고 브랜드의 로고, 화면 구조, 사진과 문구 복제
- PNG 미리보기를 기본 결과물로 생성
- 앱 안에 미리보기 라우트나 영구 테마 편집기 추가
- Home 또는 Settings를 고정 미리보기로 사용
- 리뷰 HTML에 생성 이유나 플랫폼 제약 표시
- 사용자 승인 없는 `global.css` 변경
- 시스템 폰트와 접근성 동작 변경

## 남은 위험

- HTML은 디자인 시스템을 빠르게 비교하기 위한 견본이므로 실제 React Native 렌더링과
  픽셀이 완전히 같지는 않다. 승인 뒤 실제 iOS와 Android 화면 검증이 필요하다.
- 고정 견본에 없는 긴 문구, 복잡한 데이터와 제품별 상태에서 정보 위계가 달라질 수 있다.
- 참고 자료의 정체성이 플랫폼이 소유하는 형태에 크게 의존하면 남길 수 있는 특징이 적어
  후보가 원본보다 절제되어 보일 수 있다.
- HeroUI Native가 시맨틱 변수 집합이나 계산 규칙을 바꾸면 HTML 템플릿과 내보내기 형식을
  함께 갱신해야 한다.
