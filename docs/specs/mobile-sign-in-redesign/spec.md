# 모바일 로그인 화면 재설계 명세

## 목표

로그인 화면을 한 화면에서 세 화면으로 나누고, 다크 모드에서 글자가 사라지는 문제와
키보드가 버튼을 가리는 문제를 없앤다. 제공자 버튼을 직접 그려 세 갈래를 같은 모양으로
보여 준다. 화면 문구는 [화면 문구 한국어 말투](../../decisions/korean-ui-writing.md)를 따른다.

[모바일 인증 명세](../mobile-authentication/spec.md)의 인증 방식, 세션 생명주기, 프로필
스키마, 로컬 검증 경로는 그대로 둔다. 이 명세는 그중 "인증 화면과 보호 경로",
"오류, 중복 실행과 접근성"의 화면 부분만 다시 정한다.

## 필요한 최종 상태

### 화면 구성

로그인은 세 화면으로 나뉜다. 셋 다 인증 route group 안의 Native Stack 화면이다.

| 화면 | 하는 일 | 뒤로가기 |
| --- | --- | --- |
| 로그인 방법 | Google, Apple, 이메일 중 고른다 | 없음. 스택의 첫 화면이다 |
| 이메일 주소 | 주소를 입력하고 코드를 요청한다 | 네이티브 Stack 툴바 |
| 인증 코드 | 6자리 코드를 입력한다 | 네이티브 Stack 툴바 |

- 뒤로가기는 네이티브 Stack 툴바가 소유한다. 화면 안에 뒤로가기 컨트롤을 만들지 않는다.
- 각 화면은 제목을 위에, 주 동작을 화면 하단에 둔다. 키보드가 올라오면 주 동작은
  키보드 바로 위에 남는다.
- 화면 제목은 이 화면에서 할 일을 말한다. 첫 화면만 앱 이름을 제목으로 쓴다.
- 이전에 쓰던 "다른 이메일 사용" 버튼과 "또는" 구분선을 두지 않는다.

### 로그인 방법 화면

- 제목은 앱 이름 하나뿐이다. 설명 문구를 두지 않는다. 세 버튼이 무엇을 하는지 스스로 말한다.
- 화면 하단에 Google, 이메일 순서로 버튼을 쌓는다. iOS는 Google과 이메일 사이에
  Apple을 둔다.
- 세 버튼은 같은 높이, 같은 폭, 같은 모서리, 같은 글자 크기를 쓴다. 하나만 더 강조하지
  않는다.
- 버튼 색은 제공자 규칙을 따른다.

| 버튼 | Light 채움 | Light 테두리 | Dark 채움 | Dark 테두리 |
| --- | --- | --- | --- | --- |
| Google | `#FFFFFF` | `#747775` | `#131314` | `#8E918F` |
| Apple | `#FFFFFF` | Google과 같다 | `#000000` | Google과 같다 |
| 이메일 | Google과 같다 | Google과 같다 | Google과 같다 | Google과 같다 |

- Google 로고는 공식 컬러 자산을 쓰고 크기와 색을 바꾸지 않는다. Apple 로고는 Apple
  Design Resources의 자산을 쓰고 배경에 맞춰 검정 또는 흰색으로만 쓴다.
- 버튼 문구는 "Google로 계속하기", "Apple로 계속하기", "이메일로 계속하기"다. 앞의 두
  개는 각 제공자가 허용한 "Continue with ..."의 한국어 현지화다.

### 이메일 주소 화면

- 제목은 "이메일 주소를 입력해 주세요", 그 아래 "인증 코드를 보낼게요."를 둔다.
- 입력칸 위에 별도 레이블을 두지 않는다. placeholder와 접근성 이름이 그 일을 한다.
- 화면을 열면 입력칸에 커서가 들어가 키보드가 바로 올라온다.
- 하단 버튼 문구는 "인증 코드 받기"다. 주소가 비어 있으면 누를 수 없다.
- 키보드의 전송 키는 하단 버튼과 같은 동작을 한다.
- 주소 형식이 틀리면 입력칸 테두리를 오류 색으로 바꾸고 입력칸 바로 아래에
  "이메일 주소를 다시 입력해 주세요."를 보여 준다. 이 문구는 안내 문구 자리를 대신 쓴다.
- 사용자가 주소를 고치기 시작하면 오류 표시를 지운다.

### 인증 코드 화면

- 제목은 "코드를 입력해 주세요", 그 아래 "{주소}으로 보냈어요."를 둔다.
- 여섯 칸이 콘텐츠 폭을 고르게 채운다. 고정 폭을 쓰지 않는다.
- 화면을 열면 첫 칸에 커서가 들어가 키보드가 바로 올라온다.
- 여섯 자리가 채워지면 바로 확인한다. 확인 버튼을 두지 않는다.
- 클립보드에 코드만 들어 있으면 붙여넣기가 여섯 칸을 채우고 바로 확인한다.
- 클립보드에 다른 글자가 섞여 있으면 숫자만 뽑아 채운다. 다만 iOS가 붙여넣기를 코드
  길이만큼 먼저 잘라 넘기므로 앞 여섯 글자 안의 숫자까지만 들어간다.
- 확인이 실패하면 여섯 칸을 비우고 테두리를 오류 색으로 바꾼 뒤 첫 칸에 커서를 되돌린다.
- 오류 문구는 "코드를 다시 입력해 주세요."다. 새 코드를 받으라고 말하지 않는다.
- 화면 하단에는 코드 다시 받기 하나만 둔다. 기다리는 동안은 "{남은 초}초 후 다시 받기"로
  잠기고, 풀리면 "코드 다시 받기"가 된다.
- 코드 유효 시간을 화면에 적지 않는다.
- 주소를 바꾸는 별도 컨트롤을 두지 않는다. 네이티브 뒤로가기가 그 일을 한다.

### 색상 이름

- 화면에서 쓰는 색은 [모바일 색상 시맨틱](../../decisions/mobile-color-semantics.md)이 정한
  이름만 쓴다. `text-muted-foreground`처럼 존재하지 않는 이름을 쓰지 않는다.
- 흐린 글자는 `muted`를 쓴다. 이 이름이 없으면 글자가 테마 색을 받지 못하고 검정으로
  떨어진다. 같은 실수가 `chat-panel.tsx`에도 있으므로 함께 고친다.

### 세션 상태

- 앱은 저장된 Supabase 세션을 읽는 동안, 로그인됨, 로그아웃됨, 그리고 Supabase 공개
  설정이 잘못된 상태를 구분한다.
- 설정 오류는 로그아웃 상태와 다르게 보여 준다. 로그인 화면을 열어 봐야 사용자가 할 수
  있는 일이 없기 때문이다.

### 접근성

- 세 화면의 버튼과 입력에는 안정된 접근성 이름을 둔다. 이 이름은 React Native Testing
  Library와 `agent-device`가 함께 쓰는 검증 계약이다.
- 직접 그린 제공자 버튼에도 버튼 역할과 이름을 붙인다.

## 완료 조건

- 다크 모드에서 세 화면의 모든 글자가 배경과 구분된다.
- 이메일 화면과 코드 화면에서 키보드가 올라와도 하단 버튼이 가려지지 않는다.
- 이메일 화면과 코드 화면은 열자마자 키보드가 올라온다.
- 코드 화면에서 코드만 담긴 클립보드를 붙여넣으면 여섯 칸이 채워지고 바로 확인한다.
  구분 기호나 문장이 섞이면 앞 여섯 글자 안의 숫자까지만 채워진다. 어느 쪽이든 칸이
  비워지지는 않는다.
- 코드를 틀리면 칸이 비워지고 커서가 첫 칸으로 돌아간다.
- 빈 이메일로는 다음으로 갈 수 없고, 주소를 고치면 오류 표시가 사라진다.
- 세 로그인 버튼의 폭과 높이가 같다.
- Android에서는 Apple 버튼이 보이지 않는다.
- React Native Testing Library 테스트가 세 화면의 이동, 자동 확인, 붙여넣기, 오류 복구,
  중복 실행 방지를 사용자 관점에서 검증한다.
- `agent-device`가 `auth:otp` 명령과 함께 세 화면을 지나 로그인하고 로그아웃하는 전체
  흐름을 한 세션에서 검증한다.
- `bun run check`, `bun run check-types`, `bun run test`가 통과한다.

## 가정

- 앱 이름과 로고는 아직 템플릿 기본값이다. 브랜드 영역은 이 명세에 넣지 않는다.
- HeroUI Native의 `InputOTP`를 계속 쓴다. 붙여넣기는 이 컴포넌트가 노출하는
  `pasteTransformer`로 고친다. `maxLength`는 이 컴포넌트가 타입에서 막아 둬서
  바꿀 수 없고, 그래서 긴 문장 붙여넣기는 처리할 수 없다.

## 이번 구현에서 제외할 범위

- 로고와 브랜드 영역
- 이용약관과 개인정보 처리방침 문구
- 코드 만료를 따로 알리는 오류 갈래
- 화면 전환 애니메이션 손질

## 남은 위험

- Google과 Apple의 브랜드 규칙은 바뀔 수 있다. 이번 구현은 2026년 8월 기준
  [Google branding guidelines](https://developers.google.com/identity/branding-guidelines)와
  Apple Human Interface Guidelines의 Sign in with Apple 버튼 규칙을 따랐다. 자산과 색을
  바꿀 때 원문을 다시 확인한다.
- Supabase가 틀린 코드와 만료된 코드에 같은 오류를 돌려준다. 그래서 화면은 만료를
  구분해 말하지 않는다. 한 시간 뒤에 돌아온 사용자는 다시 받기 링크로만 회수한다.
- `InputOTP`의 붙여넣기 동작은 라이브러리 내부 구현에 기댄다. HeroUI Native를 올릴 때
  `maxLength`와 `pasteTransformer` 처리 방식을 다시 확인한다.
