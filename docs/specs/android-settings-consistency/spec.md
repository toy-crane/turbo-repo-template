# Android Settings 일관성 명세

## 목표

Android Settings가 Android의 기본 표현을 유지하면서도 iOS와 같은 정보 위계를 갖게 한다. 프로필은 화면의 주제로 보이고, 아래 설정 항목은 각각 하나의 목록 행으로 읽혀야 한다.

## 참고 근거

- [Expo UI Examples의 Universal Settings 예제](https://github.com/SchroederNathan/expo-ui-examples/blob/f5293ead47a983694b2837b9a99b6e2ca60a951f/src/examples/universal-settings/universal-settings.tsx)는 같은 정보 구조를 두 플랫폼의 기본 표현으로 보여 주는 참고 구현이다. 변경될 수 있는 `main` 대신 조사한 커밋을 고정해서 연결한다.
- [Expo `FieldGroup` 공식 문서](https://docs.expo.dev/versions/latest/sdk/ui/universal/fieldgroup/)는 섹션 머리말과 꼬리말을 설정 행 바깥에 두고, 섹션의 자식은 각 목록 행으로 다루는 기준을 확인하는 데 사용한다.
- 참고 구현과 문서는 설계 의도를 확인하는 자료다. 이 명세의 완료 조건과 저장소의 결정 계약을 바꾸지 않는다.

## 사용자에게 보이는 결과

- 프로필 사진, 닉네임과 아이디는 별도 카드나 설정 행 안에 넣지 않고 화면 배경 위에 바로 표시한다.
- 프로필 사진이 있으면 별도 바탕색, 카드와 테두리를 더하지 않는다. 사진은 원형으로 잘라 보여 준다.
- 프로필 사진이 없으면 이니셜이나 사람 아이콘을 알아볼 수 있도록 원형 바탕을 유지한다.
- 프로필 사진 원본의 색상과 배경은 바꾸지 않는다. 앱이 사진 배경을 지우거나 새 배경을 합성하지 않는다.
- 프로필 사진, 닉네임과 아이디는 화면 가운데에 하나의 묶음으로 정렬한다.
- 프로필 사진과 `프로필 수정` 항목은 지금처럼 같은 `프로필 수정` 화면을 연다.
- `프로필 수정`, `로그아웃`, `알림`, `햅틱 반응`과 `버전`은 각각 하나의 목록 행으로 보인다. 한 행 안에 또 다른 카드나 행이 겹쳐 보이지 않는다.
- 목록의 좌우 여백, 높이와 항목 사이 간격은 Android 설정 화면 안에서 일관되어야 한다.
- 일반 항목, 보조 정보와 위험한 동작은 서로 다른 의미가 드러나야 한다. 일반 항목은 기본 글자색, 버전 값은 보조 글자색, `로그아웃`은 위험한 동작의 색상을 사용한다.
- Light 및 Dark 모드에서 프로필 영역과 설정 목록 사이에 흰색 또는 다른 화면 모드의 배경이 끼어 보이지 않는다.

## 플랫폼 표현

- 두 플랫폼은 같은 정보 순서와 강조를 유지한다.
- iOS는 현재의 SwiftUI 설정 표현을 유지하고 Android는 Material 3 설정 표현을 사용한다.
- Android에 iOS의 카드 모양, 간격과 셰브론을 그대로 복사하지 않는다.
- Android의 설정 묶음은 Material 3의 모양을 유지하되 각 항목이 한 번만 그려져야 한다.
- 화면 제목, 닫기 동작, 시트 표시 방식과 화면 전환은 현재 동작을 유지한다.

## 완료 조건

1. Android Settings의 프로필 영역 뒤에 둥근 설정 카드나 흰색 목록 행 배경이 보이지 않는다.
2. 사진이 있는 아바타에는 앱이 만든 별도 바탕색이나 테두리가 보이지 않고 사진만 원형으로 표시된다.
3. 사진이 없는 아바타에는 이니셜 또는 사람 아이콘과 이를 구분할 수 있는 원형 바탕이 보인다.
4. 계정, 환경 설정과 앱 정보의 각 항목은 한 개의 행과 한 개의 누르기 영역만 가진다.
5. `프로필 수정` 행 전체를 누르면 프로필 수정 화면이 열리고, `로그아웃` 행 전체를 누르면 로그아웃을 시작한다.
6. 버전 값은 항목 이름보다 약하게 보이고 `로그아웃`은 다른 일반 항목과 구분된다.
7. Android의 Light 및 Dark 모드에서 프로필, 섹션 배경, 글자와 Switch가 같은 화면 모드로 보인다.
8. iOS Settings의 현재 프로필 배치, 목록 표현과 동작이 달라지지 않는다.
9. 기본 글자 크기와 큰 접근성 글자 크기에서 닉네임, 아이디와 설정 항목이 겹치거나 잘리지 않는다.
10. Android와 iOS Development Build에서 실제 화면과 누르기 동작을 확인한다. 자동 테스트는 사진 유무, 이동과 동작, 글자 역할을 확인한다.

## 가정

- 사진이 있는 상태에서 말하는 `배경 없음`은 앱이 사진 뒤에 별도 색상이나 카드를 그리지 않는다는 뜻이다.
- 사진 파일 자체에 포함된 색과 배경은 사진의 일부다.
- 사진이 없을 때의 원형 바탕은 빈 상태를 알아보기 위한 표현이므로 유지한다.
- Android와 iOS의 픽셀 모양이 같아야 하는 것은 아니다. 같은 정보 구조, 강조와 동작을 일관성의 기준으로 삼는다.

## 제외할 범위

- 사진 속 배경 제거, 인물 분리, 색상 보정과 다른 이미지 편집
- 프로필 사진 저장 형식, 업로드, 다운로드와 캐시 방식 변경
- 프로필 항목의 이름, 순서, 값과 동작 변경
- 알림과 햅틱 설정의 실제 저장 기능 추가
- Android에 iOS 전용 셰브론이나 SwiftUI 모양 복제
- 앱의 전역 색상값, 화면 모드 정책과 글꼴 변경
- Settings 밖의 아바타와 다른 화면 디자인 변경

## 남은 위험

- 투명한 사진은 이미지 안의 투명한 부분을 통해 화면 배경이 보인다. 이는 앱이 별도 아바타 배경을 그리는 것과 다르다.
- 자동 테스트는 Compose와 SwiftUI가 실제로 그리는 배경과 행 중첩을 보여 주지 못한다. `@expo/ui`나 HeroUI를 올릴 때 Development Build에서 다시 확인해야 한다.

## 검증 결과

- Android Development Build에서 프로필 영역이 App Bar 아래에서 시작하고 화면 가운데에 놓이는 것을 확인했다.
- Android의 Light 및 Dark 모드에서 실제 사진과 사진이 없는 상태, 행 중첩, 버전 값과 위험 동작 색상, Switch를 확인했다.
- 실제 사진 뒤에는 앱이 만든 바탕이 보이지 않았고, 사진을 불러오지 못하면 이니셜 원형 바탕으로 돌아가는 동작을 자동 테스트로 확인했다.
- Android의 기본 글자 크기와 큰 글자 크기에서 프로필과 설정 항목이 겹치거나 잘리지 않는 것을 확인했다.
- Android에서 `프로필 수정`과 `로그아웃` 행의 빈 오른쪽 부분을 눌러도 각 동작이 실행되는 것을 확인했다.
- 최신 `main`의 Material Symbols 닫기 아이콘을 합친 뒤 Android Settings에 X가 표시되고 Home으로 닫히는 것을 확인했다.
- iOS Development Build에서 기존 프로필 배치와 목록 표현, 설정 닫기, 프로필 수정 뒤로가기와 로그아웃을 확인했다.
- 모바일 테스트 57개 묶음의 테스트 382개, TypeScript 검사와 모바일 Ultracite 검사를 통과했다.
- 저장소 `bun run check`의 코드 검사 전 단계는 기준 브랜치의 Expo 패치 버전이 현재 Expo CLI 권장 버전보다 낮아 멈췄다. 이번 변경과 관련된 코드 검사는 따로 통과했다.
