# 계정 삭제 이름과 진행 표시

## 사용자에게 보이는 결과

- 계정을 지우는 동작을 앱 어디서나 `계정 삭제`로 부른다. `계정 탈퇴`라는 표현은 화면에서 사라진다.
- `계정 삭제`와 `로그아웃`은 누른 뒤에도 문구가 그대로다. 진행 중이라는 사실은 컨트롤 안의 진행 표시가 말한다.
- 두 동작 모두 `FieldGroup.Section` 안의 단독 그룹에 선다. 아이콘과 셰브론은 없고 문구는 왼쪽에 서며, 행 전체를 누를 수 있다.
- 실패하면 지금처럼 같은 그룹의 설명 자리에 실패 문구가 서고, 사용자는 다시 시도할 수 있다.

## 승인한 범위

- `프로필` 화면의 계정 삭제
- `설정` 화면의 로그아웃
- 두 동작이 쓰는 화면 문구 전체와 확인창 문구

## 확인할 수 있는 기준

- `프로필` 화면 맨 아래 버튼의 이름이 `계정 삭제`다. 확인창 제목은 `계정을 삭제할까요?`, 실행 버튼은 `계정 삭제`, 취소 버튼은 `취소`다.
- 삭제가 도는 동안 버튼의 이름이 `계정 삭제` 그대로이고 버튼 안에 진행 표시가 보인다.
- 삭제가 도는 동안 같은 버튼을 다시 눌러도 확인창이 열리지 않고 요청이 한 번만 나간다.
- 삭제가 성공하면 이 기기의 로그인 상태와 사용자별 캐시가 지워지고 로그인 화면이 열린다.
- 삭제가 실패하면 현재 계정과 화면이 유지되고 설명 자리에 `계정 삭제를 끝내지 못했습니다. 다시 시도해 주세요.`가 선다.
- `설정` 화면 맨 아래 버튼의 이름이 `로그아웃`이고, 로그아웃이 도는 동안에도 이름이 그대로이며 진행 표시가 보인다.
- 로그아웃은 확인창 없이 바로 실행된다.
- 로그아웃이 실패하면 설명 자리에 실패 문구가 선다.
- 화면 읽기가 진행 중인 버튼을 읽을 때 진행 중이라는 사실이 전달된다.

## 정한 것과 이유

- **문구를 바꾸지 않는다.** 문구를 바꾸면 같은 컨트롤이 상태마다 다른 이름을 갖는다. Apple 설정 앱은 행의 이름을 고정한 채 상태를 별도 요소나 값으로 붙인다. 이 앱의 React Native `Button`도 처음부터 같은 방식이었다.
- **`계정 삭제`로 부른다.** Apple은 버튼 문구를 지정하지 않으므로 이는 제품의 언어 결정이다. 앱이 이미 설명과 확인창, 사진 메뉴에서 `삭제`를 쓰고 코드도 `account-deletion`과 `delete-account`를 쓴다. 라벨만 `탈퇴`였다.
- **`ListItem`으로 만든다.** iOS에서 `ListItem`은 SwiftUI `Button`을 감싸므로 Apple 설정의 `Remove from Account`와 같은 형태이면서 행 전체가 눌린다. 범용 `Button`은 자기가 그린 글자에서만 press를 받아 행의 오른쪽이 눌리지 않았다.
- **진행 중임은 `accessibilityValue`로 알린다.** 진행 표시만으로는 접근성 트리에 아무것도 남지 않아 바쁠 때와 아닐 때가 똑같이 읽힌다.
- **삭제가 도는 동안 화면의 나머지를 막지 않는다.** 로컬에서 잰 삭제 시간이 1–1.5초였고, 그 사이 저장을 눌러도 결과가 곧 지워지므로 실제 피해가 작다.

## 가정

되돌릴 수 있는 판단이며 어긋나면 바꾼다.

- 버튼 문구는 왼쪽에 세운다. 진행 표시가 오른쪽 끝에 서므로 가운데 정렬이면 문구가 치우쳐 보인다.
- 진행 표시는 플랫폼 기본 크기와 색을 쓴다.
- 로그아웃과 계정 삭제는 같은 형태를 쓴다. 설정 영역의 파괴적 동작이 두 모양으로 갈리지 않게 한다.

## 건드리지 않는 것

- 삭제 범위와 서버 처리 순서. [계정 삭제 서버 경계](../../decisions/account-deletion-server-boundary.md)가 소유한다.
- 확인창의 본문과 설명 문구. 이미 정해진 내용이며 이번 변경의 대상이 아니다.
- 계정 삭제와 로그아웃이 각각 어느 화면에 있는지. 자리는 그대로다.
- 프로필 저장, 로그인, 채팅의 진행 표시. 각자의 계약을 따른다.

## 미룬 것

- Sign in with Apple 토큰 취소. Apple이 계정 삭제 시 요구하지만 [모바일 계정 삭제](../../decisions/mobile-account-deletion.md)가 범위 밖으로 정해 두었다. iOS 심사 전에 풀어야 한다.
- 앱을 설치하지 않은 사용자의 웹 삭제 요청 경로. Google Play 제출 조건이며 같은 계약이 미뤄 두었다.
- 채팅 `다시 시도` 버튼에는 진행 표시가 없다. 이번 범위 밖이다.

## 확인한 것

iOS Simulator와 Android Emulator의 Development Build에서 각각 확인했다.

- 두 동작 모두 기존 행과 같은 모양으로 그려지고 행 전체가 눌린다.
- 진행 중에는 문구가 그대로이고 trailing 자리에 플랫폼 진행 표시가 돈다. iOS는 SwiftUI 활동 표시, Android는 Material 3 Expressive `LoadingIndicator`다.
- 삭제와 로그아웃 모두 끝나면 로그인 화면으로 돌아간다.
- iOS 접근성 트리가 label `계정 삭제`와 `로그아웃`에 value `진행 중`을 함께 보고한다.

## 남은 위험

- **Android는 진행 중임을 화면 읽기에 알리지 못한다.** `accessibilityValue`는 SwiftUI modifier이고 `@expo/ui 57.0.11`의 Compose 쪽에는 대응하는 modifier가 없다. 접근성 트리에도 진행 표시가 남지 않는다. React Native의 `AccessibilityInfo.announceForAccessibility`가 대안이지만 아직 넣지 않았고, 넣어도 화면 읽기로 직접 확인하기 어렵다.
- 실패 상태는 기기에서 재현하지 않았다. 단위 테스트로만 확인했다.
