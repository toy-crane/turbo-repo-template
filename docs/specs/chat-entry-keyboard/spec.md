# 채팅 진입 키보드 명세

## 목표

채팅 화면을 열면 입력창을 따로 누르지 않고 바로 질문을 쓴다. 화면이 자리를 잡은 뒤 키보드와 입력창이 아래에서 같이 올라와 움직임의 방향이 하나로 보인다.

이 명세는 [최소 채팅 화면 명세](../ai-chat/spec.md)와 [AI 채팅 스크롤 명세](../ai-chat-scrolling/spec.md)의 입력, 전송, 키보드 동작을 그대로 두고 화면에 처음 들어올 때의 포커스만 더한다.

## 적용할 결정

- [모바일 진입 키보드](../../decisions/mobile-keyboard-entry-focus.md)
- [모바일 키보드 회피](../../decisions/mobile-keyboard-avoidance.md)
- [모바일 테스트와 런타임 검증](../../decisions/mobile-testing-and-verification.md)

## 확정한 범위

- 채팅 화면을 스택에 올릴 때 입력창이 포커스를 받고 키보드가 올라온다.
- 화면 전환이 끝난 뒤에 포커스를 준다. 키보드와 입력창이 아래에서 같이 올라오고, 전환이 끝나기 전에는 키보드가 보이지 않는다.
- 진입할 때 한 번만 포커스를 준다. 사용자가 키보드를 내린 뒤나 앱에서 돌아온 뒤에 이 기능이 다시 포커스를 주지 않는다. 앱 복귀 시 키보드 복원은 플랫폼 기본 동작을 따른다.
- 뒤로 나갔다가 새 대화를 다시 열면 새 화면이므로 다시 키보드가 올라온다.
- 전송 뒤 키보드를 닫고 사용자가 입력창을 다시 눌러야 여는 기존 동작을 바꾸지 않는다.
- 진입 키보드가 메시지 목록의 위치나 입력창 높이를 바꾸지 않는다. 대화가 비어 있어 올릴 메시지가 없다.
- 기존 입력, 전송, 오류 안내와 접근성 이름을 그대로 둔다.

## 선택한 구성

- 진입 포커스의 방식과 시점은 [모바일 진입 키보드](../../decisions/mobile-keyboard-entry-focus.md)를 그대로 따른다. `autoFocus`를 쓰지 않는 이유와 upstream 근거도 그 계약에 있다.
- 채팅 화면이 `useFocusOnArrival()`로 ref를 만들어 `ChatPanel`에 넘긴다. 패널은 그 ref를 입력창에 붙이기만 하고 포커스를 알지 않는다.

## 제외할 범위

- 전송 뒤 키보드 유지 또는 자동으로 다시 열기
- 앱 복귀나 화면 재진입 시 다시 포커스 주기
- 지난 대화를 복원한 상태의 진입 동작
- 스크린리더, Reduce Motion, 외장 키보드 전용 분기
- 입력창의 초기 높이, 위치와 배치 변경

## 완료 조건

1. Home에서 새 대화를 열면 입력창에 커서가 놓이고 키보드가 올라온다. 사용자가 입력창을 누르지 않는다.
2. iOS에서 화면이 밀려 들어오는 동안에는 키보드가 보이지 않고, 전환이 끝난 뒤 키보드와 입력창이 아래에서 같이 올라온다. 키보드가 화면과 함께 옆에서 들어오지 않는다.
3. Android에서도 진입과 함께 키보드가 실제로 보인다. 커서만 놓이고 키보드가 뜨지 않는 상태가 없다.
4. 진입 직후 목록을 끌어 키보드를 닫고 뒤로 가기를 하는 동작이 바로 반응한다.
5. 첫 질문을 보내면 키보드가 닫히고, 입력창을 다시 누르면 열린다.
6. 뒤로 나간 뒤 대화를 다시 열면 키보드가 다시 올라온다.

자동 테스트는 도착 판정과 포커스 요청, 입력창이 스스로 포커스를 잡지 않는지, 기존 입력·전송 동작이 그대로인지 확인한다. 키보드 애니메이션과 Android의 실제 표시 여부는 iOS 및 Android Development Build에서 확인한다.

## 가정

- 대화는 화면 수명 동안만 유지되므로 진입 시점의 대화는 항상 비어 있다. 진입과 빈 대화를 따로 구분하지 않는다.

## 남은 위험

- 키보드가 전환 시간만큼 늦게 올라온다. 화면이 자리를 잡은 뒤 키보드가 올라오는 것이 목표한 움직임이므로 받아들이는 비용이다.
- 콜드 스타트 딥링크로 채팅을 바로 여는 경로는 확인하지 못했다. Development Build에서는 dev client가 그 실행을 가로챈다. 지금은 Home의 새 대화 버튼이 유일한 진입점이라 이 경로가 없고, 알림이나 외부 링크로 채팅을 여는 기능을 더할 때 확인한다.
- 실제로 눈에 보이는 키보드는 자동 테스트가 확인하지 못한다. 포커스 요청까지는 `useFocusOnArrival`의 테스트가 확인하고, 키보드 애니메이션은 Development Build에서 확인한다.
