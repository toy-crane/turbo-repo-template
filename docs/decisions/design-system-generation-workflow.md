# 디자인 시스템 생성 작업 흐름

## 결정

- 테마 생성은 `.agents/skills/create-design-system/SKILL.md`를 원본으로 두는 프로젝트 공용 Skill이 맡는다. Claude는 `.claude/skills/create-design-system` 심볼릭 링크로 같은 Skill을 읽는다.
- 참고 이미지나 URL과 가져오고 싶은 시각적 특징을 받는다. 글로만 요청하면 먼저 두세 가지 방향을 제안하고, 참고 자료와 요청이 분명하면 후보 하나를 만든다. 한 번에 비교하는 후보는 최대 세 개다.
- 후보를 만들기 전에 설치된 Expo, HeroUI Native와 Uniwind 버전, 전역 CSS의 시맨틱 변수, Light와 Dark 변수 집합과 공통 테마 연결 지점을 확인한다.
- 후보는 HeroUI Native의 시맨틱 역할을 유지하고 Light와 Dark에 같은 변수 집합을 사용한다. 시스템 폰트와 현재 화면 구조, 내비게이션과 제품 동작은 바꾸지 않는다.
- 검토 결과는 외부 네트워크에 의존하지 않는 독립 실행형 HTML 한 파일로 만든다. 같은 내용과 상태를 `Overview`, `Components`, `Patterns`에서 비교하고 `Export`에서 전체 Light와 Dark 변수를 확인할 수 있게 한다.
- 후보 이름, 화면 표현 값과 내보낼 변수는 미리보기 데이터 한 곳에서 관리한다. 사용자에게 보여 주기 전에 전용 검사로 필수 화면 값과 시맨틱 변수 누락을 확인한다.
- 사용자는 선택한 후보를 자연어로 반복해서 고칠 수 있다. 후보 선택은 수정할 방향을 고른 것이며 프로젝트 적용 승인이 아니다.
- 사용자가 적용을 명시적으로 승인하기 전에는 `global.css`, 앱 라우트와 제품 컴포넌트를 바꾸지 않는다. 승인 뒤에는 공식 `global.css`와 필요한 공통 연결 지점만 고치고 임시 미리보기와 후보 데이터를 제품에 남기지 않는다.

## 경계

- 참고 자료는 시각적 특징의 근거로만 사용한다. 로고, 사진, 문구, 화면 구조와 제품 흐름은 복제하지 않는다.
- 새 시맨틱 역할은 기존 역할로 제품 의미를 표현할 수 없을 때만 제안하고 사용자 승인 없이 추가하지 않는다.
- 디자인 시스템 후보를 보여 주기 위해 앱 안에 임시 라우트나 영구 테마 편집기를 만들지 않는다.
- HTML 미리보기와 실제 React Native 렌더링은 픽셀 단위로 같다고 가정하지 않는다. 승인한 테마는 iOS와 Android의 대표 화면에서 다시 확인한다.

## 이유

같은 내용과 상태를 독립 실행형 미리보기에서 비교하면 화면 기능을 함께 바꾸지 않고 색상, 형태와 밀도만 판단할 수 있다. 후보 선택과 실제 적용 승인을 나누면 검토 중인 값이 공식 테마나 제품 코드에 섞이지 않는다.

HeroUI Native의 시맨틱 역할과 공통 연결 지점을 유지하면 승인한 값이 기존 컴포넌트에 일관되게 적용된다. Light와 Dark의 변수 집합을 함께 검증하면 한 화면 모드에만 있는 역할이나 끊어진 대비 쌍을 적용 전에 찾을 수 있다.

## 재검토 조건

- 모바일 앱이 Expo, HeroUI Native 또는 Uniwind를 더 이상 사용하지 않을 때
- 독립 실행형 HTML로 판단한 결과가 실제 React Native 화면과 반복해서 크게 다를 때
- 제품에서 사용자가 직접 테마를 만들고 저장하는 기능이 필요할 때

## 계속 제외하는 대안

- PNG를 기본 검토 결과로 사용: 후보와 화면 모드, 상태를 한자리에서 바꾸어 볼 수 없다. 정적인 공유물만 필요한 작업에서 별도로 만들 수 있다.
- 앱 안에 미리보기 라우트를 추가: 승인 전 후보 코드가 제품 라우트와 번들에 섞인다. 실제 사용자용 테마 편집기가 제품 요구가 될 때만 다시 검토한다.
