# 모바일 Side chat

## 결정

- 완료된 부모 AI 답변에서 구절을 선택하면 시스템 텍스트 선택 메뉴에
  `Ask in side chat`을 표시한다. 복사, 찾기와 번역 같은 시스템 항목은 유지한다.
  답변을 기다리거나 받는 동안에는 새 Side chat을 시작하지 않는다.
- 선택한 구절마다 새 Side chat을 만든다. 같은 답변에서 다시 시작해도 기존 대화와
  합치지 않는다. 첫 질문을 보내기 전에 닫으면 임시 대화와 초안을 버리고 Side chat
  수에 포함하지 않는다.
- Side chat은 만든 순간의 부모 대화 처음부터 출처 AI 답변 전체까지를 읽기 전용
  스냅샷으로 이어받는다. 선택한 구절만 화면에 읽기 전용 출처로 보여 주고, 부모
  스냅샷은 메시지 목록에 표시하지 않는다. AI 요청에는 고정한 부모 스냅샷과 Side chat
  메시지를 함께 보내며 부모 대화와 스냅샷을 바꾸지 않는다.
- Side chat은 [모바일 UI 렌더러 경계](mobile-ui-renderer-boundaries.md)에 따라 Expo
  Router Stack의 `pageSheet`로 연다. 제목은 `Side chat`이고 부모
  채팅으로 돌아갈 때는 뒤로 가기가 아니라 닫기를 사용한다. 화면이 열린 뒤 입력창에
  포커스를 주는 시점은 [모바일 진입 키보드](mobile-keyboard-entry-focus.md)를 따른다.
  첫 질문 전에는 선택한 출처와 입력창만 보여 준다.
- Side chat의 새 메시지는 부모 채팅과 같은 표현, 스크롤, 키보드, 스트리밍과 메시지
  동작을 사용한다. 구체적인 동작은
  [모바일 AI 채팅 표현](mobile-ai-chat-rendering.md),
  [모바일 채팅 스크롤](mobile-chat-scrolling.md),
  [모바일 채팅 메시지 동작](mobile-chat-message-actions.md)을 따른다. Side chat의 AI
  답변도 선택할 수 있지만 그 선택 메뉴에는 `Ask in side chat`을 넣지 않는다.
- 첫 질문을 보낸 Side chat은 부모 채팅 화면이 살아 있는 동안 메모리에 보관한다.
  시트를 닫아도 메시지, 초안, 전송 상태와 수정 상태를 유지하고 진행 중인 답변도 계속
  받는다. 각 Side chat은 이 상태를 따로 가진다.
- 첫 질문을 보낸 Side chat이 있으면 부모 채팅 입력창 위에 대화 전체의 수를
  `Side chat N개`로 표시한다. 하나면 바로 다시 열고, 여러 개면 최근에 만든 순서의
  목록에서 고른다. 목록은 선택한 구절과 마지막으로 오간 말을 각각 한 줄 평문으로
  보여 준다.
- 부모 채팅을 나가거나 로그아웃하거나 앱 프로세스가 끝나면 그 부모 대화의 모든
  Side chat을 지운다. 부모 메시지 수정이나 답변 다시 받기로 출처 답변이 사라지면
  해당 Side chat의 진행 중인 답변을 먼저 멈추고 함께 지운다.
- 수 표시는 접근성 역할을 버튼으로 알린다. 하나일 때는 `Side chat 1개 다시 열기`,
  여러 개일 때는 `Side chat N개 고르기`를 접근성 이름으로 쓴다. 목록 항목은 선택한
  구절과 `Side chat 열기`를 함께 알리고, 시트 닫기 버튼은 `Side chat 닫기`로 알린다.

## 경계

- Side chat은 현재 부모 채팅의 메모리 수명만 따른다. DB, Supabase 테이블, 기기 저장소,
  지난 Side chat 조회 API, 앱 재시작 뒤 복구와 기기 간 동기화를 추가하지 않는다.
- Side chat 안에서 다른 Side chat을 만들거나, 부모 대화와 합치거나, 답변을 부모
  대화로 보내지 않는다. 부모 스냅샷에는 수정, 다시 받기와 메시지 동작을 붙이지 않는다.
- 첨부, 이미지, 음성 입력과 모델 고르기를 추가하지 않는다.
- [AI 채팅 프로토콜](ai-chat-protocol.md)의 기존 `POST /ai/chat`, 인증, 모델 라우팅과
  UI message 스트리밍 프로토콜을 그대로 사용한다. Expo Web은 지원하지 않는다.
- 네이티브 Stack이 시트 배경, 모서리, 전환과 닫기 제스처를 소유한다. `push`,
  `formSheet`, BottomSheet와 커스텀 시트 모양으로 바꾸지 않는다.

## 이유

Side chat은 선택 메뉴에서 끝나는 짧은 작업이 아니라 키보드, 긴 메시지와 계속되는
대화를 가진 독립 흐름이다. `pageSheet`는 이 대화 공간과 라우트 수명을 제공하고,
네이티브 Stack의 닫기와 전환 동작도 유지한다.

부모 대화 전체를 메시지 목록에 보여 주면 읽기 전용 문맥과 수정 가능한 Side chat
메시지가 섞인다. 부모 대화는 고정한 AI 문맥으로만 보내고 선택한 구절만 출처로 보여
주면 원래 대화를 바꾸지 않으면서 질문의 출발점을 확인할 수 있다.

Side chat을 선택한 구절마다 분리하고 부모 채팅 수명에 묶으면 서로 다른 질문의 상태가
섞이지 않는다. 입력창 위의 대화 단위 수 표시는 부모 답변을 다시 찾지 않아도 같은
자리에서 돌아갈 길을 제공한다.

## 재검토 조건

- 앱을 다시 시작하거나 다른 기기에서 지난 Side chat을 이어야 할 때
- 부모 스냅샷과 Side chat 메시지를 함께 보내는 요청이 모델 문맥 한도, 비용 또는
  전송 크기 문제를 반복해서 만들 때
- 한 부모 대화에 Side chat이 많이 생겨 현재 수 표시와 목록으로 찾기 어려울 때
- Side chat을 중첩하거나 부모 대화와 합쳐야 한다는 제품 요구가 생길 때
- 네이티브 `pageSheet`가 필요한 대화 공간이나 플랫폼 동작을 안정적으로 제공하지 못할 때

## 계속 제외하는 대안

- BottomSheet 또는 `formSheet`: 부분 높이와 높이 전환에 맞지만 긴 대화 공간과 독립
  라우트 수명이 부족하다.
- 부모 대화 전체를 Side chat 목록에 표시: 읽기 전용 문맥과 수정 가능한 메시지가
  섞이고 같은 대화를 화면에 반복한다.
- 같은 부모 답변의 Side chat을 하나로 합치기: 서로 다른 구절과 질문의 상태가 한
  대화에 섞인다.
- 출처 답변 아래에 다시 열기 표시 두기: 대화 어디에서나 돌아가려면 출처 답변을 다시
  찾아야 한다.
- 첫 버전부터 Side chat 저장: 현재 부모 채팅보다 긴 수명과 동기화 규칙을 새로 만든다.

## 보존할 근거

- `react-native-enriched-markdown@1.0.1`은 렌더링한 평문을 밖으로 내주지 않는다.
  다시 열기 목록은 마지막 말을 한 줄 평문으로 보여 주기 위해 짝이 맞는 Markdown
  표시만 제거하고, `owner_id`나 `a => b`처럼 짝이 아닌 낱개 문자는 보존한다.
  렌더러가 평문을 제공하게 되면 이 변환을 렌더러 출력으로 바꾼다.
