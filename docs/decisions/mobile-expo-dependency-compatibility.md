# 모바일 Expo 의존성 호환

## 결정

- 모바일 앱은 Expo SDK가 권장하는 Expo, React Native와 알려진 네이티브 패키지 버전을 기본값으로 사용한다.
- `CI=1 expo install --check`를 모바일 `check`에 포함해 루트의 `bun run check`가 버전 차이에서 실패하게 한다.
- 의존성 검사는 변경을 제안하거나 적용하지 않고 종료 코드로만 결과를 알린다.
- Expo 권장 버전과 다른 패키지는 경고를 숨기기 위해 제외하지 않는다. 권장 버전에서 실제 회귀가 재현되고 다른 버전에서 해결됨을 iOS와 Android Development Build로 확인한 경우에만 `expo.install.exclude`에 넣는다.
- 현재 Expo 권장 버전보다 새로운 `react-native-keyboard-controller`는 먼저 권장 버전으로 맞춰 로그인 입력, 채팅 입력, 키보드 회피, 스크롤과 닫기를 두 플랫폼에서 확인한다. 실제 회귀가 있을 때만 새 버전을 복구하고 예외 근거를 이 결정에 남긴다.
- `react-native-keyboard-controller`는 `1.22.3`을 사용하고 `expo.install.exclude`에 등록한다. Expo 권장 버전 `1.21.9`의 Android Development Build에서는 목록을 드래그해 키보드를 닫은 뒤 입력창이 키보드 높이에 남았다. `1.22.3`을 넣어 새로 만든 iOS와 Android Development Build에서는 키보드가 닫힌 뒤 입력창이 화면 아래로 돌아왔고 메시지 전송도 이어졌다.

## 경계

- Expo 의존성 검사는 알려진 호환 조합을 확인할 뿐 실제 네이티브 동작을 보장하지 않는다. 네이티브 의존성을 바꾼 뒤에는 Development Build를 다시 만들고 영향을 받는 흐름을 실제 기기에서 확인한다.
- Expo CLI가 동적 앱 설정을 읽을 때 필요한 제품 환경 변수와 의존성 호환 검사의 입력은 분리한다. 깨끗한 자동 검사도 제품 자격 증명 없이 버전 차이를 확인할 수 있어야 한다.
- Expo가 호환 목록을 관리하지 않는 일반 JavaScript 패키지는 이 검사의 범위가 아니다.

## 이유

lockfile은 모든 환경이 같은 버전을 설치하게 하지만 그 조합이 현재 Expo SDK와 맞는지는 판단하지 않는다. Expo 호환 검사를 일반 코드 검사에 포함하면 JavaScript 검사에서는 보이지 않는 네이티브 버전 차이를 빌드 전에 찾을 수 있다. 권장 버전과 다른 선택은 실제 기기 근거를 요구해 자동 검사와 필요한 예외를 함께 유지한다.

## 재검토 조건

- Expo가 `expo install --check`를 다른 공식 호환 검사로 바꿀 때
- Expo의 권장 목록이 반복해서 검증된 패키지 조합을 잘못 판단해 예외 관리 비용이 검사 이점보다 커질 때
- 모바일 앱이 Expo SDK의 버전 관리 경계에서 벗어날 때

## 계속 제외하는 대안

- 패키지 설치 때만 사람이 버전을 확인: 이후 SDK 패치와 직접 편집으로 생긴 차이를 자동으로 막지 못한다.
- 모든 Expo 경고를 `expo.install.exclude`로 숨기기: 실제 호환 차이와 의도한 예외를 구분하지 못한다.
- Expo 권장 목록만 통과하면 기기 검증 생략: 호환 목록은 앱 고유의 키보드, 인증과 내비게이션 동작을 증명하지 않는다.
