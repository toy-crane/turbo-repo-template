# 모바일 환경 설정

## 결정

- `apps/mobile/.env.example`에 선언한 모든 변수는 모바일 앱의 필수 설정이다. 하나라도 없거나 유효하지 않으면 완전한 앱으로 실행할 수 있다고 보지 않는다.
- `apps/mobile/env.ts`가 모바일 공개 환경 변수의 이름, 형식과 타입을 하나의 Zod 스키마로 소유한다.
- 원시 값은 `process.env.EXPO_PUBLIC_...` 점 표기법으로 각각 정적으로 읽는다. 앱 코드는 `process.env`를 다시 읽지 않고 검증된 환경 설정만 사용한다.
- 개발 세션 전용 API와 Supabase URL은 선택 설정으로 같은 스키마에서 검증한다. 값이 있으면 일반 API와 Supabase URL보다 우선해 앱의 최종 환경 설정을 만든다.
- `app.config.ts`는 같은 환경 설정 계약을 확인한다. 누락되거나 유효하지 않은 값이 있으면 `expo start`, `expo run:*`, `expo prebuild`와 `expo export`가 앱을 실행하거나 결과물을 만들기 전에 실패해야 한다.
- 환경 설정 검증에는 Zod만 사용한다. `@t3-oss/env-core`는 함께 사용하지 않는다.

## 경계

- 이 계약은 앱 번들에 포함해도 되는 `EXPO_PUBLIC_` 값만 다룬다. 서버 비밀값, 빌드 작업 전용 토큰과 Provider secret은 모바일 환경 설정에 포함하지 않는다.
- `apps/mobile/.env.local`은 Git에서 제외하고 실제 값을 저장한다. `apps/mobile/.env.example`은 필수 이름과 설명만 공개한다.
- `EXPO_PUBLIC_DEV_SESSION_API_PORT`와 `EXPO_PUBLIC_DEV_SESSION_SUPABASE_PORT`는 루트 개발 세션이 넣는 선택 설정이므로 `.env.example`의 사용자 필수 설정에 포함하지 않는다. 이 값은 포트만 담고 호스트는 앱이 자기 플랫폼에 맞게 정한다.
- 테스트는 개발자의 `.env.local`에 기대지 않고 명시적인 테스트 값을 사용한다. 테스트 편의를 위해 실제 앱과 빌드의 검증을 약하게 만들지 않는다.
- EAS 환경별 값 저장과 동기화 방식은 EAS Build나 EAS Update를 도입할 때 별도로 결정한다.

## 이유

모든 환경 변수가 있어야 앱의 전체 기능이 동작하므로 기능을 사용할 때까지 오류를 미루면 부분적으로만 작동하는 앱을 정상 실행처럼 보이게 한다. 한 스키마에서 이름, 빈 값과 형식을 함께 검사하면 Expo 설정과 앱 코드가 서로 다른 필수 목록을 갖지 않는다. `app.config.ts`에서도 같은 계약을 확인하면 개발자와 CI가 잘못된 결과물을 만들기 전에 원인을 알 수 있다.

개발 세션 전용 포트는 Expo SDK 57 개발 번들의 `.env.local` 우선 병합을 피하기 위해 일반 URL과 다른 이름을 사용한다. 앱은 포트를 검증한 뒤 자기 플랫폼의 호스트와 조합한다.

Zod는 필수값, URL과 문자열 형식을 검사하고 TypeScript 타입을 만드는 데 충분하다. `@t3-oss/env-core`의 접두사별 서버·클라이언트 분리와 접근 프록시는 공개 모바일 변수만 다루는 현재 범위에서 겹치는 기능과 의존성만 추가한다.

## 재검토 조건

- 모바일 설정에 공개값과 빌드 전용 비밀값을 함께 다루는 복잡한 경계가 생길 때
- 여러 앱이나 런타임이 같은 환경 설정 계약을 공유해야 할 때
- Zod 스키마만으로 막기 어려운 접두사나 서버·클라이언트 접근 오류가 반복될 때
- Expo가 정적 환경 변수 접근과 검증을 함께 제공하는 공식 계약 도구를 도입할 때

## 계속 제외하는 대안

- 기능별 직접 검사: 누락을 늦게 발견하고 필수 목록과 오류 문구가 여러 파일에 흩어진다. 일부 설정이 실제로 선택 사항으로 바뀔 때만 해당 기능 경계에서 다시 검토한다.
- `app.config.ts`와 앱 코드가 별도 목록을 검사: 두 목록이 달라질 수 있다. Expo 설정과 앱 번들이 같은 스키마를 사용할 수 없게 될 때만 다시 검토한다.
- `@t3-oss/env-core`와 Zod를 함께 사용: 현재는 모든 값이 공개 모바일 설정이라 Zod 위에 실질적인 경계를 더하지 않는다. 서버·클라이언트 환경을 한 계약에서 강제해야 할 때 다시 검토한다.
- TypeScript non-null assertion만 사용: 컴파일 오류만 숨기고 누락된 런타임 값은 검증하지 않는다.
- 개발 세션과 일반 설정에 같은 환경 변수 이름 사용: Expo SDK 57 개발 번들에서 `.env.local` 값이 세션 값을 덮어쓴다.

## 보존할 근거

- Expo는 앱 코드의 `process.env.EXPO_PUBLIC_NAME` 점 표기법만 번들 값으로 정적으로 바꾼다. 대괄호 접근, 구조 분해와 동적으로 만든 이름은 지원하지 않는다.
- 공개 Expo 프로젝트에서는 Zod 스키마에 각 `EXPO_PUBLIC_` 값을 정적으로 나열하고 파싱하는 중앙 `env.ts` 방식과, 그 모듈을 `app.config.ts`에서도 읽는 방식을 사용한다.
