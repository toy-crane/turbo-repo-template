# 모바일 계정 삭제

## 결정

- `계정 삭제`는 `프로필` 화면 맨 아래의 라벨 없는 단독 그룹에 둔다.
  `FieldGroup.Section` 안의 `ListItem`으로 만들고 아이콘과 셰브론을 두지 않는다.
  누르면 다른 화면으로 이동하지 않은 채 플랫폼 기본 확인창을 연다.
- 버튼 아래 설명은 `로그인 계정, 프로필과 올린 사진이 모두 삭제됩니다. 되돌릴 수
  없습니다.`다. 확인창 제목은 `계정을 삭제할까요?`, 본문은 `지금 삭제하면 되돌릴
  수 없습니다. 다시 가입해도 이전 정보는 돌아오지 않습니다.`다.
- 사용자는 확인창의 `계정 삭제`로 즉시 영구 삭제를 시작하거나 `취소`로 돌아간다.
  재로그인, 인증 코드, 비밀번호와 별도 확인 문구를 요구하지 않는다.
- 삭제하는 동안 버튼의 문구는 `계정 삭제` 그대로 두고 진행 표시만 더한다. 같은
  요청을 다시 시작하지 못하게 한다. 진행 표시 방식은
  [모바일 작업 진행 표시](mobile-action-progress.md)를 따른다. 실패하면 현재 계정과
  화면을 유지하고 `계정 삭제를 끝내지 못했습니다. 다시 시도해 주세요.`를 같은
  그룹에 보여 준다.
- 삭제가 끝나면 이 기기의 로그인 상태와 사용자별 캐시를 지우고 로그인 화면을
  보여 준다. 같은 로그인 방법으로 다시 가입해도 이전 데이터가 돌아오지 않는 새
  계정으로 시작한다.
- 인증 계정, 로그인 신원, 프로필, 닉네임, 아이디, 이전 아이디 기록과 사용자가 올린
  프로필 사진을 삭제한다. 계정에 연결된 서버 저장 데이터를 추가할 때는 삭제 범위도
  함께 갱신한다.
- 삭제 요청의 서버 권한과 삭제 순서는 [계정 삭제 서버 경계](account-deletion-server-boundary.md)를
  따른다.

## 경계

- 계정 삭제는 즉시 영구 삭제다. 유예 기간, 삭제 취소, 계정 복구와 데이터 내려받기는
  제공하지 않는다.
- Google 또는 Apple의 외부 계정 자체는 삭제하지 않는다. Sign in with Apple 토큰
  취소도 현재 범위에 넣지 않는다.
- 현재 제품에는 삭제와 함께 처리할 구독, 결제 또는 법정 보관 데이터가 없다. 이런
  데이터가 생기면 삭제 범위, 안내, 보관과 복구 정책을 먼저 다시 정한다.
- Google Play에 앱을 제출하기 전에는 앱을 설치하지 않아도 쓸 수 있는 웹 삭제 요청
  경로를 만들고 Play Console의 Data Safety 양식에 등록해야 한다. 이 경로가 없으면
  Android 스토어 제출 준비가 끝난 것이 아니다.

## 이유

무엇이 사라지는지는 사용자가 누르기 전에 버튼 아래에서 읽고, 되돌릴 수 없다는 점은
마지막 확인창에서 다시 확인한다. 아무 일도 하지 않는 안내 화면을 한 번 더 거치지
않아도 실수 방지 정보는 유지된다.

계정을 보는 `프로필` 화면과 계정을 없애는 동작을 한곳에 두고, 되돌릴 수 있는
`로그아웃`은 설정 화면 맨 아래에 따로 둔다. 성격이 다른 두 동작을 한 목록에 섞지
않으면서 각 화면에는 위험한 동작이 하나만 남는다.

## 재검토 조건

- 구독, 결제, 부정 사용 방지 또는 법에 따라 보관해야 하는 계정 데이터가 생길 때
- 앱을 설치하지 않은 사용자의 웹 삭제 요청 경로를 만들 때
- Apple 토큰 취소가 심사 또는 재가입 흐름에 필요해질 때
- 계정 삭제를 되돌리거나 유예해야 한다는 제품 또는 법적 요구가 생길 때

## 계속 제외하는 대안

- 별도 삭제 안내 화면: 삭제 전에 읽을 내용은 버튼 아래 설명과 확인창이 이미 나눠
  전달하므로, 실행하지 않는 화면 한 단계를 더 만든다.
- 재로그인이나 확인 문구 입력: 이메일 코드, Google과 Apple 로그인을 각각 다시
  다뤄야 하고 삭제를 불필요하게 어렵게 만든다. 더 강한 재인증 요구가 생길 때 다시
  검토한다.
- 설정 첫 화면에 로그아웃과 계정 삭제를 함께 두기: 되돌릴 수 있는 동작과 없는
  동작이 나란히 서서 서로의 의미를 흐린다.
