# 모바일 설정 공개 프로필

## 결정

- Settings는 네이티브 `pageSheet` 안에서 한글 제목 `설정`을 사용한다. 화면 위에는 큰 프로필 사진, 닉네임과 아이디를 가운데 정렬해 표시한다.
- 설정 화면의 프로필 사진과 `프로필 수정` 목록 항목은 모두 같은 `프로필 수정` 화면으로 이동한다. 설정 화면의 프로필 사진을 눌러 사진 메뉴를 바로 열지 않는다.
- `프로필 수정` 화면은 프로필 사진, 닉네임과 아이디를 한 화면에서 바꾼다. 프로필 사진과 `사진 편집`을 누르면 사진 출처 메뉴를 연다. 사진 위에 별도 편집 배지를 겹쳐 놓지 않는다.
- 프로필 입력 묶음의 설명은 `FieldGroup.SectionFooter`에 둔다. `@expo/ui`와 운영체제가 제공하는 섹션 푸터 간격을 사용하며 Uniwind 여백으로 덮어쓰지 않는다.
- 아이디가 바뀌는 저장은 30일 동안 다시 바꿀 수 없다는 점만 짧게 알리는 확인 대화상자를 먼저 보여 준다. 이전 아이디 보호 안내는 섹션 푸터에만 둔다. 제한 기간에는 아이디만 비활성화하고 다시 바꿀 수 있는 날짜를 일반 설명 대신 표시한다.

## 경계

- 네이티브 셸은 Settings 시트, 헤더, 뒤로 가기, 저장 도구막대와 화면 전환을 소유한다. `@expo/ui`는 설정 목록과 프로필 입력 섹션을 소유한다.
- 프로필 머리말처럼 직접 구성하는 영역은 프로젝트의 Uniwind 간격 눈금을 사용한다. 네이티브 컴포넌트 안쪽 간격에는 같은 눈금을 강제로 적용하지 않는다.
- 프로필 사진 출처 메뉴는 `사진 찍기`, `사진 보관함에서 선택`, `현재 사진 삭제`, `취소`를 제공한다. 현재 사진이 없으면 삭제 항목을 보여 주지 않는다.
- 설정 화면은 프로필 값을 보여 주고 수정 화면으로 이동하는 곳이다. 다른 사용자가 보는 공개 프로필 화면은 이 결정에 포함하지 않는다.

## 이유

설정 화면에서 프로필 사진만 바로 바꾸게 하면 같은 공개 프로필의 닉네임과 아이디가 서로 다른 수정 경로로 갈린다. 모든 진입점을 한 편집 화면으로 모으면 사용자가 현재 공개 프로필을 한 번에 확인하고 저장하거나 취소할 수 있다.

설명문을 섹션 푸터에 두면 iOS의 그룹형 Settings 구조와 플랫폼별 기본 간격을 그대로 따른다. 임의의 픽셀 여백을 추가하면 `@expo/ui`가 운영체제에 맞춰 제공하는 배치와 어긋난다.

## 재검토 조건

- 프로필 사진 변경이 설정 밖의 자주 쓰는 독립 작업이 될 때
- 공개 프로필 편집을 사진, 닉네임과 아이디별 화면으로 나눌 필요가 생길 때
- `@expo/ui`가 프로필 입력이나 섹션 푸터에 필요한 동작을 지원하지 못할 때

## 계속 제외하는 대안

- 설정 화면의 프로필 사진에서 사진 메뉴 바로 열기: 공개 프로필 수정 경로가 사진과 텍스트로 갈리고 저장과 취소의 범위가 달라진다.
- 프로필 사진 위에 편집 배지 겹치기: 큰 사진 자체와 `사진 편집` 문구가 이미 같은 동작을 알려 주므로 장식과 터치 대상이 중복된다.
- 섹션 설명에 고정 픽셀 여백 두기: 플랫폼이 제공하는 푸터 배치와 중복되고 렌더러별 차이를 앱이 다시 관리해야 한다.

## 보존할 근거

- Expo SDK 57의 `FieldGroup.SectionFooter`는 iOS에서 SwiftUI `Section`의 푸터로 전달되고, Android와 Web에서는 각 플랫폼 구현이 자체 여백을 적용한다. 모든 플랫폼에 공통인 숫자형 푸터 간격 값은 없다.
