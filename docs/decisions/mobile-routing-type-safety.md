# 모바일 라우팅 타입 안전성

## 결정

- 모바일 앱은 Expo Router의 `experiments.typedRoutes`를 켜서 실제 경로 파일을 기준으로 `Link`, `Redirect`, `router`와 경로 매개변수를 타입 검사한다.
- `check-types`는 `expo customize tsconfig.json`으로 경로 타입을 먼저 만든 뒤 `tsc --noEmit`을 실행한다. 개발 서버를 한 번도 실행하지 않은 깨끗한 checkout에서도 같은 검사를 보장한다.
- 고정된 내부 경로는 절대 경로로 쓴다. 동적 경로는 `pathname`과 `params`를 나눈 객체로 쓴다.
- 타입 오류를 피하려고 내부 경로를 `Href`로 강제 변환하지 않는다.
- Expo가 만드는 `.expo/types/router.d.ts`와 `expo-env.d.ts`는 Git에 올리지 않고 실행 환경에서 다시 만든다.

## 경계

- 이 결정은 Expo Router가 소유하는 내부 앱 경로에 적용한다. 외부 URL과 운영체제가 여는 URL은 내부 경로와 구분한다.
- Typed routes는 컴파일 단계의 검사만 추가한다. 화면 구성, 내비게이션 기록과 네이티브 전환 방식은 바꾸지 않는다.
- Expo Router가 자동으로 알 수 없는 query parameter는 사용하는 코드에서 별도 타입으로 선언한다.

## 이유

문자열 경로만 사용하면 화면 파일을 옮기거나 경로에 오타가 생겨도 실행하기 전에는 찾지 못할 수 있다. 실제 파일 구조로 만든 타입을 모든 타입 검사 전에 준비하면 개발자의 로컬 Metro 실행 여부와 관계없이 깨진 경로를 같은 명령에서 막을 수 있다. 생성 파일은 Expo와 경로 구조에서 파생되므로 Git에 함께 보관하지 않아도 된다.

## 재검토 조건

- Expo가 typed routes를 없애거나 다른 안정된 경로 검사 방식으로 바꿀 때
- Expo CLI가 개발 서버 없이 경로 타입을 만드는 공식 명령을 바꿀 때
- 서버에서 받은 값처럼 컴파일 시점에 알 수 없는 내부 경로 이동이 제품 요구로 반복될 때

## 계속 제외하는 대안

- 일반 문자열 경로만 사용: 경로 파일 변경과 오타를 타입 검사에서 찾지 못한다.
- 개발 서버를 실행할 때만 경로 타입 생성: 깨끗한 checkout과 자동 검사에서는 typed routes가 빠질 수 있다.
- 생성된 경로 타입을 Git에 올리기: 경로 파일과 생성 파일이 어긋날 수 있고 불필요한 변경이 쌓인다.
