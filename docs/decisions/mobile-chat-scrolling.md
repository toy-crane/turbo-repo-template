# 모바일 채팅 스크롤

## 결정

- 메시지는 `KeyboardAwareLegendList`에 시간 순서대로 넣고 목록을 뒤집지 않는다. 짧은 대화도 첫 메시지를 화면 위쪽에 둔다.
- 질문을 보내면 입력창을 비우고 키보드를 닫는다. 첫 질문은 목록 위쪽 12px에서 시작한다. 두 번째 질문부터 방금 보낸 질문을 화면 위쪽 12px에 놓고 답변과 뒤쪽 빈 영역이 그 아래로 이어지게 한다.
- 사용자가 최신 메시지를 보고 있으면 스트리밍 답변을 계속 따라간다. 사용자가 이전 메시지를 읽으려고 위로 스크롤하면 자동 추적을 끄고 읽던 위치를 유지한다.
- 질문을 새로 보내거나 최신 메시지 이동 버튼을 누르거나 사용자가 목록 끝에 도달하면 자동 추적을 다시 켠다. 끝 도달은 직접 계산한 거리 대신 목록의 `onEndVisible` 신호로 판단한다.
- 최신 메시지가 보이지 않으면 입력창 위 가로 중앙에 아래쪽 화살표 버튼을 표시한다. 접근성 이름은 `최신 메시지로 이동`이다.
- 음수 스크롤 위치, 키보드와 입력창의 움직임, 메시지 크기 변화와 코드가 시작한 스크롤은 사용자가 자동 추적을 끈 것으로 보지 않는다.
- 메시지 크기가 바뀔 때는 읽던 위치를 보정한다. 새 메시지가 추가됐다는 이유만으로 위치를 바꾸지 않는다.
- 여러 줄 입력창의 높이 변화는 키보드 인셋 흐름에서 한 번만 목록 공간에 반영한다. 키보드가 열릴 때는 사용자가 목록 끝에 있을 때만 최신 메시지 영역을 함께 올린다.

## 경계

- 대화는 화면이 살아 있는 동안만 유지한다. 화면에 들어올 때 지난 대화나 읽던 위치를 복원하지 않는다.
- 메시지 본문 형식, 서버 경로, 인증, 모델 라우팅과 스트리밍 프로토콜은 이 결정에서 정하지 않는다.
- 대화 저장, 지난 대화 조회와 이전 메시지 추가 불러오기는 현재 범위에 포함하지 않는다.

## 이유

자동 추적을 단순한 화면 위치가 아니라 사용자가 최신 답변을 보겠다는 상태로 관리하면 스트리밍으로 내용이 커져도 사용자가 이전 메시지를 읽는 일을 방해하지 않는다. 새 질문을 위쪽에 두면 질문과 자라는 답변을 같은 흐름에서 읽을 수 있다. 입력창과 키보드의 높이를 목록에 한 번만 반영하면 빈 공간과 겹침을 막을 수 있다.

## 재검토 조건

- 지난 대화를 복원하거나 이전 메시지를 추가로 불러오게 될 때
- `KeyboardAwareLegendList`의 끝 도달이나 위치 보정 신호가 현재 동작을 안정적으로 표현하지 못할 때
- 질문 전송 뒤에도 키보드를 유지해야 할 때
- 매우 긴 단일 메시지의 렌더링 비용이 실제 문제로 확인될 때

## 계속 제외하는 대안

- 무조건 `scrollToEnd()` 호출: 사용자가 이전 메시지를 읽는 중에도 위치를 바꾼다.
- 새 데이터 추가에 대한 `maintainVisibleContentPosition`: 새 질문을 위쪽에 놓는 흐름과 스트리밍 자동 추적이 서로 위치를 바꾸게 된다.
- 뒤집은 목록이나 짧은 대화의 아래쪽 정렬: 첫 질문을 화면 위쪽에서 읽는 현재 흐름과 맞지 않는다.
- 별도로 계산한 `blankSpace`: 질문 배치와 답변 뒤 공간을 두 경로에서 계산하게 된다.

## 보존할 근거

- iOS에서는 `anchoredEndSpace`로 만든 빈 영역이 React Native의 content inset hit-test 밖에 놓일 수 있다. 이 영역에서도 스크롤을 시작할 수 있게 우회가 필요하다.
