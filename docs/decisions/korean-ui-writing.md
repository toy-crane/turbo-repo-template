# 화면 문구 한국어 말투

## 결정

- 화면 문구는 당근 SEED의 [Writing](https://seed-design.io/foundations/writing)과
  [Voice and Tone](https://seed-design.io/foundations/voice-and-tone)을 판정 기준으로 삼는다.
  원문 사본은 `.agents/context/seed/`에 둔다.
- 기본 종결은 해요체다. 자동으로 발송되는 메시지와 사용자가 조심해야 하는 상황만
  합쇼체를 써서 무게를 싣는다.
- 자주 갈리는 네 가지는 아래대로 판정한다.
  - **버튼과 메뉴**: 기능의 이름이 아니라 목적을 쓴다. "확인", "다음", "계속" 대신
    누르면 무엇이 일어나는지 쓴다. 예외는 온보딩 닉네임 화면의 `다음` 하나다. 규칙만
    보면 목적을 쓴 `아이디 정하기`가 맞지만, 두 화면짜리 흐름에서는 `다음`이 더 자연스럽다.
    이 한 자리에만 두고 다른 화면으로 넓히지 않는다.
  - **오류**: 사과보다 지금 할 수 있는 해결 방법을 먼저 쓴다. 부정문 대신 긍정문을 쓴다.
  - **마침표**: 메인 타이틀, 20pt 이상 큰 글씨, 버튼, 메뉴, 라벨에는 붙이지 않는다.
    나머지 평서문과 명령문에는 붙인다.
  - **존칭어**: 최소로 쓴다. "하실 수 있어요"가 아니라 "할 수 있어요"로 쓴다.
- 이 계약은 템플릿의 기본 말투다. 템플릿에서 만든 프로젝트는 그대로 물려받는다.
- 채팅 답변, 문서, 결정 계약, 작업 기록의 말투는 `AGENTS.md`가 정한다. 이 계약은
  앱 화면에 보이는 문구만 다룬다.

## 경계

- SEED에서 가져오는 것은 글쓰기와 보이스앤톤 판정 규칙뿐이다.
- SEED의 색상, 타이포그래피, 간격, 아이콘, 컴포넌트 시각 자산은 가져오지 않는다.
  이 프로젝트의 시각 결정은 [모바일 색상 시맨틱](mobile-color-semantics.md),
  [모바일 타이포그래피](mobile-typography.md), [모바일 UI 렌더러 경계](mobile-ui-renderer-boundaries.md)가 소유한다.
- 당근의 지역 커뮤니티 세계관은 가져오지 않는다. `이웃` 같은 당근 고유 용어를 쓰지 않는다.
- 제공자가 문구를 정해 둔 자리에는 이 계약보다 제공자 규칙이 앞선다.
  Google과 Apple 로그인 버튼이 여기에 해당한다.
- 공개 규칙에서 답을 찾지 못하는 법률 문구와 알림은 문맥과 위험도에 맞춰 따로 판단한다.

## 이유

출시된 문구만 보고 말투를 되짚으면 의도와 우연을 구분할 수 없고 세션마다 말투가
달라진다. SEED는 버튼, 오류, 마침표처럼 반복해서 갈리는 지점을 공개된 판정 규칙으로
제공한다. 규칙을 외부 문서로 두면 애매한 상황에서 찾아볼 원본이 생기고, 자주 쓰는 네
가지를 계약에 적어 두면 일상적인 판단에는 문서를 열지 않아도 된다.

이 저장소는 템플릿이라 여기서 정한 말투가 파생 프로젝트의 시작점이 된다. 그래서 고유
브랜드 보이스가 생기면 교체할 수 있게 재검토 조건을 함께 둔다.

## 재검토 조건

- 프로젝트의 고유 브랜드 보이스가 정의될 때
- SEED의 공개 규칙이 이 제품에 맞지 않게 바뀔 때
- 한국어가 아닌 언어를 제품 범위에 추가할 때

## 계속 제외하는 대안

- 판정 기준 없이 자체 라이팅 가이드를 새로 쓰기: 같은 논의를 처음부터 다시 하고,
  애매한 상황에서 찾아볼 원본이 없다.
- 출시된 문구만 보고 말투를 귀납하기: 의도와 우연을 구분하지 못한다.
- SEED의 시각 자산과 컴포넌트까지 가져오기: 이미 정한 색상, 타이포그래피,
  렌더러 경계 결정과 충돌한다.
