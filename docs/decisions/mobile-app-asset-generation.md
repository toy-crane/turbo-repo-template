# 모바일 앱 에셋 생성

## 결정

- 앱 아이콘 생성은 `bun run setup`으로 앱 표시 이름과 식별자를 정한 뒤 별도 승인 단계로 실행한다. `initialize-app`은 기본 초기화를 끝낸 뒤 같은 대화에서 이 단계를 이어서 할지 물을 수 있다. 사용자가 이어서 하기를 선택한 것이 `create-app-assets`를 시작하는 명시적 요청이다. 앱의 한 줄 설명이 없으면 컨셉 생성을 시작하지 않는다.
- 외부 `app-icon` 스킬에서는 앱 목적, 상징, 색상, 분위기, 피할 요소와 작은 크기 검토 방식만 참고한다. SnapAI와 별도 이미지 제공자 API 키를 기본 도구에 추가하지 않는다.
- 실제 시안 생성과 수정은 Codex에 설치된 `imagegen`을 사용한다.
- 이 흐름은 `.agents/skills/create-app-assets/SKILL.md`를 원본으로 두는 프로젝트 공용 Skill로 제공한다. Claude는 `.claude/skills/create-app-assets` 심볼릭 링크로 같은 Skill을 읽는다.
- 먼저 서로 다른 컨셉 세 개를 미리 보여 주고 사용자가 하나를 고른 뒤에만 최종 에셋과 Expo 설정을 바꾼다. 승인 전에는 현재 에셋을 덮어쓰지 않는다.
- Apple 아이콘은 Icon Composer의 `.icon` 형식을 사용한다. 기본 구성은 Icon Composer가 만드는 배경과 투명한 전경 상징으로 나눈 두 레이어이며, 컨셉에 꼭 필요할 때만 세 번째 레이어를 추가한다.
- Android adaptive icon은 전경, 배경과 단색 이미지를 서로 다른 역할의 에셋으로 만든다. Apple 아이콘이나 완성된 평면 이미지를 세 역할에 그대로 반복해서 쓰지 않는다.
- 생성 프롬프트와 최종 아이콘을 이루는 원본 레이어를 프로젝트에 함께 보관한다.

## 경계

- 이 결정은 앱 아이콘, Android adaptive icon과 스플래시 이미지에 적용한다. App Store·Google Play 스크린샷과 feature graphic은 실제 화면이 완성된 뒤 별도 작업으로 만든다.
- 화면 안의 탭, 툴바와 메뉴 아이콘은 [모바일 아이콘 렌더링](mobile-icon-rendering.md)의 시스템 심벌 결정을 그대로 따른다.
- 레이어를 안정적으로 분리할 수 없는 사진이나 복잡한 질감의 컨셉은 평면 Apple 아이콘으로 바꿀 수 있다. 이 경우 Liquid Glass 표현이 줄어드는 점을 최종 승인 전에 알린다.
- 단순한 기하학 상징은 생성된 비트맵을 그대로 최종 원본으로 삼지 않아도 된다. 작은 크기에서 선과 가장자리를 지키기 위해 SVG로 다시 그릴 수 있다.
- 기존 에셋을 실제로 교체하는 작업은 최종 시안 승인에 포함된다. 승인은 다른 제품 코드 변경을 허가하지 않는다.

## 이유

컨셉을 고르기 전에 플랫폼 파일을 만들면 사용하지 않을 에셋과 설정 변경이 쌓인다. 컨셉 선택과 최종 파일 생성을 나누면 시각 판단은 되돌리기 쉽고, 승인한 결과만 제품에 남는다. `imagegen`은 현재 Codex에서 별도 API 키 없이 사용할 수 있으므로 같은 이미지 생성을 위해 SnapAI와 비밀 값 관리 경로를 하나 더 둘 이유가 없다.

Apple의 `.icon`은 배경과 전경을 나눌 때 기본, 다크, tinted 표현과 Liquid Glass 효과를 실제로 조정할 수 있다. Android도 전경, 배경과 단색 이미지의 역할이 다르다. 하나의 완성 이미지를 모든 자리에 반복하는 방식보다 공통 상징을 공유하고 플랫폼별 레이어를 따로 만드는 방식이 각 플랫폼 규격과 제품의 시각 일관성을 함께 지킨다.

## 재검토 조건

- Codex의 기본 이미지 생성 기능이 프로젝트 에셋 생성이나 수정에 필요한 품질을 안정적으로 내지 못할 때
- 반복 가능한 CI 이미지 생성, 여러 이미지 제공자 선택 또는 대량 생성이 제품 요구가 될 때
- Apple이나 Expo가 `.icon` 지원 방식 또는 권장 에셋 구성을 바꿀 때
- 제품이 시스템 심벌 대신 하나의 브랜드 아이콘 체계를 화면 전체에 사용하기로 할 때

## 계속 제외하는 대안

- SnapAI를 기본 생성기로 사용: OpenAI 또는 Google API 키와 별도 CLI를 추가하고 `imagegen`과 역할이 겹친다. 제공자 선택이나 CI 자동 생성이 필요해질 때 재검토한다.
- 완성된 평면 이미지 한 장만 `.icon`에 넣기: 빌드는 가능하지만 Icon Composer의 레이어, 다크와 tinted 표현을 활용하기 어렵다. 레이어 분리가 품질을 해칠 때만 대체 경로로 사용한다.
- Android 전경, 배경과 단색 이미지에 같은 파일 사용: 플랫폼별 역할과 마스크에서 예상하지 못한 결과가 생긴다. 각 역할을 따로 검증할 수 없을 때도 허용하지 않는다.
- 초기 설정에서 자동 생성: 프로젝트 정보가 정해지는 즉시 시각 결정을 강제하고 사용자의 승인 없이 기존 에셋을 바꿀 수 있다. 무인 템플릿 생성이 별도 제품 요구가 될 때 재검토한다.

## 보존할 근거

- Expo SDK 57의 iOS 아이콘 플러그인은 `ios.icon`의 `.icon` 폴더를 iOS 프로젝트에 복사하고 `ASSETCATALOG_COMPILER_APPICON_NAME`을 설정한다.
- Xcode 26.6과 iOS 26.5 Simulator가 설치된 로컬 환경에서 임시 `.icon`을 사용한 Expo prebuild와 `actool` 컴파일이 통과했고, iPhone·iPad 아이콘과 `Assets.car`가 생성됐다.
- Expo는 SDK 54부터 `ios.icon`의 Icon Composer 폴더를 지원한다.
