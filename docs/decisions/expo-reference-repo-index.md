# Expo 참조 저장소 색인

## 결정

- 공개 Expo 앱 저장소를 참고 대상으로 삼을 때는
  [Expo 참조 저장소 색인](../references/expo-reference-repos.md)에 기록한다.
- 색인은 골라 볼 수 있는 예시의 지도이며 규범이 아니다. 항목이 결정 계약과
  충돌하면 결정 계약이 이긴다.
- 항목은 네 줄 형식을 쓴다: 무엇, 고정 사본, 이럴 때 본다, 들여오지 않는다.
  고정 사본은 검토 시점의 커밋을 가리킨다.
- 확정 결정과 충돌하는 저장소도 색인에 남기고, 들여오지 않는 부분과 근거 계약
  링크를 항목에 적는다.

## 경계

- 색인은 저장소의 코드 패턴을 옮겨 적지 않는다. 어디를 볼지와 무엇을 들여오지
  않을지만 적는다.
- 결정 계약이 이미 인용하는 저장소는 계약의 인용이 원본이고, 색인 항목은 그
  자리를 가리킨다.
- 일반 Expo API 사용법은 색인이 아니라 설치된 공식 스킬이 다룬다.

## 이유

공식 Expo 스킬은 일반 API 사용법을, 결정 계약은 프로젝트의 확정 선택을 다룬다.
그런데 결정 계약이 아직 없는 새 작업을 시작할 때 완성된 실제 구현을 어디서 볼지
알려주는 자리가 없었다. 색인을 규범이 아닌 지도로 고정하면 참조 저장소의 선택이
확정 결정을 다시 여는 근거로 쓰이지 않는다. 충돌하는 저장소를 지우지 않고
남기는 이유는, 같은 저장소를 다시 만났을 때 왜 들여오지 않기로 했는지 그
자리에서 확인해 같은 검토를 반복하지 않기 위해서다.

## 재검토 조건

- 색인 항목이 많아져 영역별 분리나 다른 구조가 필요할 때
- 항목 대부분의 고정 커밋이 현재 Expo SDK와 두 major 이상 벌어질 때

## 계속 제외하는 대안

- 저장소의 코드 패턴을 서술형 best practice 문서로 추출: SDK가 오르면 금방
  낡고, 공식 스킬과 겹치고, 충돌 패턴이 규범처럼 읽힌다. 스킬과 색인으로 답하지
  못하는 질문이 반복될 때만 재검토한다.
- 결정 계약 안 인용만 유지: 관리 부담은 없지만 계약이 없는 새 작업에서 참조
  저장소가 발견되지 않는다. 색인이 갱신되지 않고 낡기만 하면 재검토한다.
