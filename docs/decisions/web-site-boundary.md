# 웹 사이트 경계

## 결정

- 랜딩, 이용약관, 개인정보처리방침과 계정 삭제 요청 안내는 `apps/web`이 소유한다.
  `apps/mobile`과 `apps/api`는 이 페이지들을 갖지 않는다.
- `apps/web`은 Astro로 만들고 정적 출력만 낸다. 서버 런타임, API 경로,
  데이터베이스 접근을 두지 않는다.
- `apps/web`은 모바일 앱, `apps/api`와 다른 Vercel 프로젝트에 배포한다.
- 계정 삭제 요청은 정적 페이지가 지원 메일 주소를 노출하는 방식으로 받는다. 폼,
  외부 폼 서비스와 웹 로그인을 쓰지 않는다.
- 사람이 보는 모든 페이지에 스토어 등록 정보와 같은 앱 이름 또는 개발자 이름을
  적는다.

## 경계

- Expo Web은 여전히 개발하지 않는다. `apps/web`은 모바일 앱의 웹 빌드가 아니라
  별도 정적 사이트다. [모바일 개발 런타임](mobile-development-runtime.md)은 그대로
  유효하다.
- 이 결정은 페이지의 문구, 디자인, 도메인과 배포 자동화를 정하지 않는다.
- 이 결정은 접수한 삭제 요청을 확인하고 실행하는 절차를 정하지 않는다. 스토어
  제출 전에 따로 정한다.
- `apps/web`에 서버가 필요해지면 이 계약을 먼저 다시 연다.

## 이유

만들 네 페이지가 전부 정적 문서다. Google Play 정책이 계정 삭제 요청 경로로 지원
메일을 명시적으로 허용하므로 이 창구에 서버가 필요 없다. 서버를 두지 않으면
공격면, 비밀 값, 배포 상태 확인이 함께 사라진다.

Astro는 정적 사이트가 기본값이고 Vercel 배포에 어댑터가 필요 없다. 약관과 방침은 앱
이름, 운영자 이름, 개인정보 보호책임자, 모델 제공자를 본문 안에서 불러 쓰므로 순수
Markdown이 아니라 `.astro` 페이지로 둔다. 이 값들을 한곳에서 읽어야 아직 채우지 않은
값을 모든 페이지가 같은 방식으로 경고할 수 있다.

별도 Vercel 프로젝트로 두면 랜딩 문구 수정이 AI API 배포를 건드리지 않는다.
[AI 서버 경계](ai-server-boundary.md)가 `apps/api`를 모바일과 분리한 이유를 그대로
잇는다.

지원 메일을 고른 이유는 주소의 수명이다. 외부 폼 서비스와 문서 호스팅은 제공자
사정으로 사라질 수 있고, 그러면 Play Console Data safety 양식에 등록한 주소가
죽는다. 죽은 링크는 스토어 반려 사유이며 본인이 먼저 알아채기 어렵다. 지원 메일
주소는 본인이 소유한다.

## 재검토 조건

- 웹에 로그인이나 폼 제출처럼 서버가 필요한 기능이 제품 범위에 들어올 때
- 삭제 요청량이 사람이 감당할 수준을 넘어 웹에서 스스로 삭제하게 만들어야 할 때
- Biome의 `.astro` 지원이 실험 단계를 벗어나거나, 반대로 실험 단계 검사가 실제
  작업을 막을 때
- Expo Web이 제품 범위에 추가되어 웹 소유권을 다시 나눠야 할 때
- Google Play가 지원 메일을 계정 삭제 요청 경로로 더는 인정하지 않을 때

## 계속 제외하는 대안

- `apps/api`가 HTML도 내기: 정적 문서를 서버 함수로 내보내고, 랜딩 문구 한 줄
  수정이 AI API 재배포를 부른다. `apps/api`가 사람이 보는 화면을 이미 소유하게 될
  때만 재검토한다.
- Expo Web으로 모바일 앱이 웹 페이지도 내기: 정적 문서 네 장 때문에 지원 플랫폼
  계약을 열게 된다. 웹이 제품 기능으로 들어올 때 재검토한다.
- 저장소 밖 문서 호스팅과 약관 생성기가 호스팅하는 링크: 주소가 제품 도메인과
  달라지고 제공자 사정으로 사라질 수 있다. 스토어에 등록하지 않는 문서에만
  사용한다.
- Google Form으로 삭제 요청 받기: Google의 Abuse Program Policies 대상이라 내려갈
  수 있고, 그러면 등록한 주소가 죽는다.
- 웹 로그인 뒤 스스로 삭제: 본인 확인이 가장 정확하지만 정적 사이트에 인증 화면과
  세션 처리가 붙는다. 위 재검토 조건에 해당할 때 다시 본다.

## 보존할 근거

- Google Play 정책은 계정 삭제 요청 경로로 "an additional link that initiates
  account deletion, a customer service email or a form they can submit a request
  through"을 허용한다. 링크는 오류 없이 열려야 하고, 삭제 요청 경로가 그 페이지에서
  눈에 띄어야 하며, 스토어 등록 정보의 앱 또는 개발자 이름을 담아야 한다.
- Google의 Abuse Program Policies는 Forms에도 적용되며 피싱과 개인 정보 수집을
  금지하고, 위반 시 콘텐츠를 내리고 이의 신청 전까지 제한을 유지한다.
- Biome 2.5.6의 `.astro` 지원은 실험 단계다. 공식 언어 지원 표가 Astro의 파싱,
  포매팅, 린트를 모두 실험으로 표시하고 포매터는 명시적으로 켜야 한다고 밝힌다.
- Astro는 2026년 8월 기준 v7이고 Node v22.12 이상을 요구한다. 저장소 루트의
  `engines.node`가 `>=22.12`라 그대로 맞는다.
- Astro 공식 에이전트 컨텍스트는 llms.txt가 아니라 Docs MCP 서버
  `https://mcp.docs.astro.build/mcp`다. `.mcp.json`이 `Astro docs`로 연결한다.
