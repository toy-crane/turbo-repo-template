# 앱 초기화 작업 흐름

## 결정

- 템플릿에서 새 앱을 시작하는 기본 진입점은 `initialize-app` Skill이다.
- `initialize-app`은 앱이 하는 일을 설명하는 한두 문장과 원하는 시각적 특징을 받는다. 참고 이미지나 URL, 피하고 싶은 표현은 있을 때만 받는다.
- 앱 설명과 시각적 특징이 불분명해 테마를 정할 수 없을 때만 후속 질문을 하나씩 한다. 고정된 제품 인터뷰를 진행하지 않는다.
- 입력이 충분하면 `create-design-system`의 미리보기와 승인 규칙으로 테마를 정하고 적용한다. 그런 뒤 앱 표시 이름, 프로젝트 슬러그와 모바일 앱 식별자를 받아 `bun run setup`을 실행한다.
- 승인한 테마를 적용한 뒤 `docs/app-brief.md`에 앱의 한 줄 설명과 시각적 방향을 저장한다. 사용자가 피할 표현을 정했을 때만 해당 내용을 함께 저장한다.
- 승인한 테마가 적용되고 `bun run setup`이 성공하면 기본 초기화는 완료된다.
- 기본 초기화가 끝나면 같은 대화에서 앱 아이콘과 스플래시 생성을 이어서 할지 한 번 묻는다. 사용자가 선택하면 앞서 정한 앱 설명과 테마 맥락으로 `create-app-assets`를 이어서 실행한다. 건너뛰어도 기본 초기화는 완료 상태를 유지한다.
- 재실행할 때는 현재 테마, `docs/app-brief.md`와 식별자를 읽어 끝나지 않은 단계부터 이어간다. 저장소 상태만으로 이전 승인을 추정하거나 `bun run setup --force`를 임의로 사용하지 않는다.
- 첫 버전은 독립 실행형 CLI, 별도 모델 연결, 인증과 대화형 터미널 UI를 만들지 않는다.

## 경계

- 첫 버전 범위, 핵심 사용자 흐름, 데이터 소유권, 로그인, AI, 결제, 알림과 외부 서비스는 기본 인터뷰에서 확인하지 않는다. 사용자가 별도로 제품 구체화를 요청할 때만 다른 작업으로 다룬다.
- `initialize-app`은 `create-design-system`, `create-app-assets`와 `bun run setup`의 입력 검증, 승인, 파일 변경과 검증 규칙을 가져가지 않는다. 각 작업을 적절한 시점에 실행하고 결과를 이어준다.
- 기존 `docs/app-brief.md`와 새 입력이 다르면 덮어쓰기 전에 차이를 보여 주고 사용자의 의도를 확인한다.
- 앱 에셋 생성은 사용자가 명시적으로 이어서 하기를 선택한 뒤에만 시작한다. 이 선택은 시안을 고르거나 활성 에셋을 바꾸는 승인이 아니다.
- 실제 제품 기능과 화면은 이 초기화의 범위가 아니다.

## 이유

테마를 정하기 위해 앱 전체의 기능, 데이터와 보안 정책을 먼저 확정할 필요는 없다. 앱이 하는 일과 원하는 시각적 특징을 알면 테마를 제안할 수 있고, 이름과 식별자를 알면 기본 설정을 안전하게 적용할 수 있다.

앱 에셋은 테마와 앱 설명을 재사용하면 자연스럽게 이어지지만 이미지 생성과 시안 승인이 오래 걸릴 수 있다. 따라서 같은 대화에서 선택적으로 이어주되, 이를 건너뛰어도 기본 초기화가 완료되도록 완료 지점을 나눈다.

짧은 앱 요약을 저장하면 중간에 작업이 멈춰도 확정한 설명과 시각적 방향을 대화 기록에 의존하지 않고 다시 읽을 수 있다. 현재 파일은 완료한 단계를 찾는 근거로 사용하되, 파일만으로 확인할 수 없는 사용자의 승인은 다시 확인해야 한다.

대화가 필요한 작업은 Skill이 이끌고, 똑같은 설정 필드를 바꾸는 일은 기존 스크립트를 유지한다. 이렇게 하면 별도 CLI가 필요로 하는 모델 연결, 인증, 상태 관리와 터미널 UI를 만들지 않아도 된다.

## 재검토 조건

- 앱 설명과 시각적 특징만으로는 실제 테마 선택이 반복해서 실패할 때
- Codex나 Claude 밖에서도 앱 초기화를 독립적으로 실행해야 할 때
- CI에서 사람의 대화 없이 앱 초기화를 반복해야 할 때
- 실제 사용에서 에이전트별 행동 차이가 크고 Skill 규칙만으로 안정적인 결과를 내지 못할 때

## 계속 제외하는 대안

- 광범위한 제품 인터뷰: 테마와 식별자 설정에 필요하지 않은 첫 버전 범위, 데이터, 인증과 외부 서비스까지 먼저 정하게 한다. 사용자가 제품 구체화를 요청할 때만 별도로 다시 검토한다.
- 앱 에셋을 기본 완료 조건으로 두기: 시안 생성과 승인을 완료해야만 초기화를 끝낼 수 있다. 무인 템플릿 생성이 별도 요구가 될 때만 다시 검토한다.
- 독립 실행형 CLI를 첫 버전으로 제공: 아직 확정하지 않은 대화 흐름까지 상태 기계와 전용 UI로 고정하고, 이미 있는 코딩 에이전트의 대화와 도구를 중복한다. 에이전트 밖에서 독립 실행해야 하는 요구가 생기면 다시 검토한다.
