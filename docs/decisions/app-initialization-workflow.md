# 앱 초기화 작업 흐름

## 결정

- 템플릿에서 새 앱을 시작하는 기본 진입점은 `initialize-app` Skill이다.
- `initialize-app`은 사용자와 대화하며 앱 방향을 구체화하고, 이미 있는 전용 Skill과 스크립트를 필요한 순서로 연결한다.
- 답변에 따라 다음 질문이 달라지는 제품 인터뷰는 Skill이 맡는다. 식별자 적용처럼 변경 대상과 검증 규칙이 정해진 작업은 스크립트가 맡는다.
- 첫 버전은 독립 실행형 CLI, 별도 모델 연결, 인증과 대화형 터미널 UI를 만들지 않는다.

## 경계

- `initialize-app`은 `bun run setup`의 식별자 검증과 파일 변경 책임을 가져가지 않는다. 결정한 입력값을 스크립트에 넘긴다.
- 아이디어 방향이 없는 경우의 탐색, 정한 방향의 구체화, 디자인 시스템과 앱 에셋 생성은 기존 전용 Skill의 결정과 승인 규칙을 재사용한다. `initialize-app`에 같은 규칙을 복사하지 않는다.
- 이 결정은 제품 기능 구현의 범위를 확정하지 않는다.

## 이유

앱 방향을 정하는 일은 사용자의 답변을 바탕으로 후속 질문을 바꾸어야 한다. 코딩 에이전트의 기존 대화와 도구 실행을 재사용하면 별도 CLI가 필요로 하는 모델 연결, 인증, 상태 관리와 터미널 UI를 만들지 않아도 된다. 반면 똑같은 설정 필드를 바꾸는 일은 기존 스크립트를 유지해야 변경 범위와 재실행 결과를 일관되게 보장할 수 있다.

## 재검토 조건

- Codex나 Claude 밖에서도 앱 초기화를 독립적으로 실행해야 할 때
- CI에서 사람의 대화 없이 앱 초기화를 반복해야 할 때
- 실제 사용에서 에이전트별 행동 차이가 크고 Skill 규칙만으로 안정적인 결과를 내지 못할 때

## 계속 제외하는 대안

- 독립 실행형 CLI를 첫 버전으로 제공: 아직 확정하지 않은 인터뷰 흐름까지 상태 기계와 전용 UI로 고정하고, 이미 있는 코딩 에이전트의 대화와 도구를 중복한다. 에이전트 밖에서 독립 실행해야 하는 요구가 생기면 다시 검토한다.
